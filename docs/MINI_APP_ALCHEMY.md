# Механики «Алхимии»: очки, достижения, лидерборд, сохранения

Игра «Alchemia — мастерская открытий» остаётся автономной страницей. PostgreSQL
хранит её прогресс, но локальный/offline-save сам по себе не подтверждает награды.
Награждаются только новые рецепты, проверенные серверной командой; ранее набранные
очки сохраняются без пересчёта и списаний.

## Что решено (зафиксировано 2026-10-05)

| Правило | Значение |
|---|---|
| Очки за новый элемент | 2 |
| Очки за закрытую главу | 3 |
| Очки за достижение игры | 5 |
| За что вообще | только за новое открытие из server-verified recipe; import/sync не награждает |
| Потолок | 30 очков в сутки по Москве; излишек не переносится и не сгорает задним числом |
| Куда идут | `users.global_score` (тот же счёт, что у квиза) + отдельный учёт в `alchemy_progress` |
| Метка источника | очки Алхимии лежат в `alchemy_progress.points_total`, поэтому вклад видно без переписывания истории |
| Достижения игры | строка в `achievement_grants` с `chat_id=0` и кодом `alchemy_<id>` — рядом с квизовыми, но не в их каталоге |
| Лидерборд | отдельная сортировка по числу server-verified элементов; локальные claims не дают рейтинг |
| Сохранения | server progress + отдельное verified-состояние; localStorage и legacy saves остаются импортируемой коллекцией |

## Как это работает

1. Периодическая `/sync` принимает локальную сводку для восстановления коллекции.
   Даже все ID из каталога не меняют подтверждённое состояние, рейтинг, очки или
   achievement grants.
2. При успешном смешивании игра отправляет ингредиенты и idempotency key в
   `/craft`. Сервер сверяет пару с каноническим `data.json` и допускает рейтинговый
   результат, только если оба ингредиента уже подтверждены (четыре базовых
   элемента или предыдущие подтверждённые рецепты).
3. Проверенные открытия, главы и достижения обновляются транзакционно. Повтор
   команды и повтор того же рецепта не начисляют награду повторно; действует
   московский дневной потолок.
4. Import и verified-прогресс хранятся отдельно: старые открытия видны и не
   теряются, но для нового рейтинга их нужно получить через серверные рецепты.

## Чего сознательно нет

- **Соревнования по очкам Алхимии между игроками**: лидерборд считает открытые
  элементы, а не очки, чтобы фарм Алхимии не влиял на общий рейтинг.
- **Уведомлений в чат**: только личный дайджест (по решению из `DESIGN_LEVEL2.md`),
  и он не чаще одного раза в сутки.
- **Отдельной валюты/магазина**: награда — очки общего профиля и достижения.

## Проверки

- `tests/test_alchemy_verification.py` — импорт без наград, проверенный craft,
  идемпотентность, защита исторических очков, непроверенные ингредиенты и рейтинг.
- Приёмка вручную: синхронизация с реальным сохранением, появление очков в профиле,
  место в лидерборде и подстановка прогресса на «чистом» устройстве.

## Маршруты API

| Маршрут | Что делает | Ограничения |
|---|---|---|
| `POST /api/mini/alchemy/sync` | объединяет локальную коллекцию без подтверждения наград | JSON, тело ≤ 128 КиБ, ≤ 4000 элементов и ≤ 8000 рецептов, попытки 0…100000; обычное ведро 120 запросов в минуту |
| `POST /api/mini/alchemy/craft` | проверяет одну пару и однократно записывает server-verified результат | JSON: `command_id`, `ingredient_a`, `ingredient_b`; обычная auth/rate-limit защита |
| `GET /api/mini/alchemy` | открытия, главы, достижения, очки из Алхимии, место | обычное ведро |
| `GET /api/mini/alchemy/leaderboard` | рейтинг по числу открытий (`limit` ≤ 100) | обычное ведро, чужие id не раскрываются |

Все маршруты требуют сессию мини-аппа. Тело сводки ограничено и фильтруется по
каталогу; корректно сформированная сводка не является доказательством. Для craft
неизвестный/несуществующий рецепт или неверная форма команды отклоняются.

## Проверки

- `tests/test_alchemy_verification.py` — PostgreSQL-приёмка в изолированной схеме; в
  отсутствие тестовой БД все такие сценарии должны оставаться `NOT VERIFIED`.
- `tests/test_alchemy_mechanics.py` — pure catalog checks и общие PG fixtures.
- `tests/js/alchemy_sync.test.cjs` — тесты моста: сводка, craft-команда и подстановка
  серверного прогресса, работа без токена, чтение самого первого формата сохранения,
  обрыв сети и защита от повторной перезагрузки страницы.

## Цель дня и суточный лимит

Игрок должен понимать, за что он получает очки и почему они перестают капать.
`GET /api/mini/alchemy` отдаёт вместе со сводкой:

| Поле | Смысл |
|---|---|
| `points_today` | сколько очков набрано сегодня (считается по московским суткам) |
| `daily_limit` | суточный потолок — 30 очков |
| `remaining_today` | сколько ещё можно набрать сегодня |
| `daily_goal` | цель дня: `{target: 10, progress, done}` — 10 очков достаточно, чтобы день считался закрытым |

Очки прошлых суток в цель дня не идут (проверено тестом на московскую полночь), но
`points_total` и место в рейтинге сохраняются. Цель дня не даёт дополнительных очков —
её отсекает тот же суточный потолок; она нужна как понятная ежедневная планка и
основа для серии дней. На экране достижений мини-аппа видны и цель, и остаток лимита.

### Серия дней

Когда суммарные очки за сутки доходят до цели дня (10), день считается закрытым и
серия увеличивается: `daily_goal.streak`. Повторная синхронизация в тот же день
серию не накручивает, пропущенный день начинает её заново (проверено тестом на
московских сутках). Серия видна игроку на экране достижений: «Серия: N дней подряд
с закрытой целью».
