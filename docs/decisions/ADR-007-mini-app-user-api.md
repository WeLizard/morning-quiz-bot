# ADR-007: Отдельный пользовательский контур Mini App

Статус: `accepted`. Дата: 2026-08-30. Область: backend-часть MQB-001, локальная разработка.

## Контекст

Админка предназначена для локального контура и имеет полномочия изменения
данных. Публиковать её вместе с пользовательской страницей нельзя. Сохранённые
игровые checkpoints содержат ответы, а записи участия не отражают выход из группы.

## Решение

1. Отдельное FastAPI-приложение без imports/mounts админки, со своими origin,
   signing credentials и строкой подключения к той же PostgreSQL.
2. Telegram HMAC и короткий срок входа; одноразовый обмен на непрозрачный bearer.
   Сессия 15 минут хранится в PG только как digest, переживает рестарт, отзывается
   при выходе и несовпадении moderation revision. Сессия админки не подходит.
3. Пользовательские данные выдаются по явному списку полей. Нет endpoint для
   произвольного профиля, глобальной выгрузки, игрового ответа или административной записи.
4. Своя история доступна после входа; групповые данные дополнительно требуют
   свежего Telegram-членства. Ошибка внешней проверки закрывает доступ.
   Сетевой запрос выполняется вне транзакции, затем доступ перепроверяется.
5. Счёт/ID передаются строками. Read-only транзакции дают согласованный snapshot;
   сервер остаётся источником истины, браузер не считает очки и не получает спойлеры.
6. Новая таблица login-сессий не меняет прежние таблицы/значения. Локальный
   offline-запуск не содержит обхода подписи и не вызывает реальный Telegram.

## Альтернативы и последствия

- Отвергнуто расширение публичными маршрутами существующей админки: выше риск
  ошибочно опубликовать привилегированные endpoints и её статику.
- JWT не нужен: серверная сессия упрощает отзыв и проверку бана. Цена — запрос к
  БД; при её недоступности нет fallback на JSON или доверие клиенту.
- Нельзя использовать старую запись участия как доступ ко всему групповому
  рейтингу. Цена свежей проверки — два вызова getChatMember и необходимость
  админских прав бота. При offline/ошибке рейтинг группы временно недоступен.
- Потерянный ответ login требует нового Telegram-входа: plaintext bearer не
  хранится для повторной выдачи. После восстановления backup сессии отзываются.
- Этот ADR не выбирает frontend stack, игровой экран или production domain.
  Публичное развёртывание, least-privilege роль и live-клиенты требуют отдельной приёмки.

## Проверка

318 тестов, включая 65 Mini App проверок, миграцию заполненной схемы и dump/restore.
Реальный loopback HTTP-цикл входа/выхода выполнен на синтетическом ключе.
См. [контракт, запуск и ограничения](../MINI_APP_API.md).
