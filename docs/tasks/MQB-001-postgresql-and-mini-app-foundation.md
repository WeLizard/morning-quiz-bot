# MQB-001 — PostgreSQL-хранилище и фундамент Telegram Mini App

- **Статус:** `in_progress`
- **Приоритет:** high
- **Создана:** 2026-08-28
- **Обновлена:** 2026-08-30
- **Ответственный:** не назначен
- **Связанные ADR:** [ADR-001 — PostgreSQL как основное хранилище](../decisions/ADR-001-postgresql-primary-store.md)
- **Baseline функций:** [проверенная по коду карта](../CODE_VERIFIED_FEATURE_MAP.md)

## Цель

Заменить файловое хранение изменяемых данных на транзакционное PostgreSQL-хранилище
и подготовить безопасный backend-контур для Telegram Mini App, сохранив текущее
функциональное покрытие викторины и возможность контролируемого отката.
Улучшить пользовательское поведение классического бота и применять актуальные,
проверенные возможности Telegram API, в том числе для согласованных новых
форматов квизов. Сохранение функций не означает сохранение ошибок и неудобств.

Пользовательский результат: статистика, настройки и прогресс не теряются при
конкурентных действиях бота и веб-приложения, а Mini App может безопасно работать
с теми же данными через авторизованный API.

### Конечный результат текущего релиза

Довести Morning Quiz Bot до проверенного релиза с PostgreSQL, сохранением
накопленных данных и всех существующих функций чата, улучшенным классическим
квизом, локальной админкой на той же БД и работающим Telegram Mini App на
реальных данных. Разработка и тесты
выполняются на локальном компьютере; финальный перенос на сервер — отдельно
согласованный шаг после приёмки и свежей резервной копии.

Завершение отдельных адаптеров или HTML-прототипа не означает завершение
релиза. Готовность подтверждается следующими результатами:

| Результат | Доказательство перед завершением релиза |
| --- | --- |
| Накопленные данные сохранены | Свежий snapshot при остановленных writers, копия на другом устройстве, отчёт сверки перенесённых данных по идентификаторам и значениям очков, серий, достижений, настроек и расписаний; нет необъяснённых расхождений. |
| Бот сохраняет прежние возможности | Проверены обычная и фото-викторина в чате, команды, рейтинги, расписания, мудрости, восстановление после рестарта и очередь удаления; пройдены регрессионные сценарии из карты функций. |
| Классический бот стал удобнее | Читаемые вопросы, понятное управление и компактная обратная связь; исправлены подтверждённые дефекты ответов, повторных нажатий и ошибок доставки. Согласованные новые форматы проверены на целевом API и клиентах, старые результаты и правила очков сохранены. |
| PostgreSQL — общее рабочее хранилище | Бот и локальная админка читают и изменяют одни и те же операционные данные; конкурентные ответы и административные изменения не теряют записи и не удваивают начисления. |
| Telegram Mini App действительно работает | Запуск из Telegram по HTTPS, проверка подписи и срока initData, разрешённые профиль, рейтинг и состояние викторины из API; нет подмены серверных данных демонстрационными значениями. |
| Границы доступа сохранены | Админка остаётся в локальном контуре; публичные маршруты и пользовательская сессия Mini App не дают доступа к административным операциям. |
| Релиз развёрнут и проверен | После отдельного подтверждения переноса выполнены миграция свежих серверных данных, переключение backend и smoke-проверка на сервере; записаны результаты, инструкция резервирования и проверенный сценарий восстановления. |

Для Mini App сохраняется одобренное визуальное направление прототипа.
Выбор между экраном профиля/рейтинга и самостоятельным прохождением квиза,
frontend stack и production domain остаётся явным продуктовым решением ниже;
оно не считается автоматически согласованным этой формулировкой цели.
Классическая викторина в Telegram-чате не заменяется Mini App.

Полная игровая реализация «Ночного города»/мафии не входит в этот релиз.
Её дизайн и персонаж могут развиваться как прототип, но готовность этой игры
не добавляется скрыто к критериям MQB-001.

До отдельного разрешения на перенос рабочий сервер не переключается.
Локальные тестовые данные не копируются поверх накопленных серверных.
Откат после начала записи в PostgreSQL должен учитывать новые записи:
возврат старого JSON snapshot без их сохранения не считается безопасным откатом.
Подробный порядок — в [руководстве локальной разработки](../LOCAL_DEVELOPMENT.md).

## Контекст на момент создания

- Проект использует `python-telegram-bot`, FastAPI, JSON и PTB
  `PicklePersistence`; SQLAlchemy и Alembic пока не подключены.
- В `data/` найдено 126 JSON-файлов общим объёмом около 3,08 МБ. Из них 63 файла
  относятся к банку вопросов и не обязаны переноситься на первом этапе.
- В рабочем Python-коде найдено 464 ссылки на JSON в 23 файлах.
- `DataManager` загружает пользовательские данные в общую память и сохраняет
  целые файлы по чатам.
- FastAPI-админка содержит собственные прямые чтения и записи JSON, поэтому
  замены только `DataManager` недостаточно.
- Бот обрабатывает updates конкурентно, а бот и веб-панель могут быть отдельными
  процессами.
- В `requirements.txt` уже разрешена версия `python-telegram-bot >=22.4`, но
  версия не закреплена. Код викторины использует `correct_option_id` при отправке
  Telegram quiz poll.
- Текущая FastAPI-админка имеет изменяющие endpoints, но эксплуатируется только
  в локальном контуре. Она не публикуется вместе с Mini App: внешний
  пользовательский API создаётся отдельно с Telegram-аутентификацией.
- Фактический runtime включает обычную и фото-викторину, рейтинги, серии,
  достижения, категорийную статистику, ежедневные расписания, мудрости,
  восстановление активных игр, очередь очистки и эксплуатационные состояния.
- На момент проверки в банке 63 категории и 6706 валидных обычных вопросов;
  метаданные фото-викторины содержат 198 записей.

## Архитектурное направление

- Использовать SQLAlchemy 2, `asyncpg` и Alembic.
- Скрыть БД за repository/service-интерфейсами, чтобы доменная логика и Telegram
  handlers не выполняли SQL напрямую.
- Настроить ограниченный пул соединений, короткие транзакции, foreign keys,
  unique constraints и явные transaction boundaries.
- Оставить статические вопросы, тексты и конфигурацию в JSON на первой итерации.
- Использовать сервер как единственный источник истины для Mini App.
- Проверять Telegram `initData` на backend; не доверять `initDataUnsafe`.
- Отделить пользовательский API Mini App от административных endpoints.

## Входит в задачу

### 1. Основа хранения

- Конфигурация подключения, пула соединений и жизненного цикла БД.
- PostgreSQL service в Docker Compose с healthcheck и постоянным volume.
- SQLAlchemy models, async sessions и Alembic migrations.
- Таблицы для чатов, пользователей, участия пользователя в чате, очков,
  ответов, серий, достижений, настроек, расписаний, статистики, активных
  викторин и очереди удаления сообщений.
- Сущности фото-викторины, подсказок и связей с медиа; сами бинарные изображения
  могут остаться файловыми на первом этапе.
- Явные уникальные ограничения и foreign keys для защиты от дублей.
- Repository/service API для бота и FastAPI.

### 2. Миграция данных

- Идемпотентный импорт существующих операционных JSON и состояния активных
  викторин.
- Нормализация идентификаторов Telegram и коллекций, которые сейчас хранятся как
  списки или множества.
- Отчёт импорта: количество сущностей, пропущенные записи и ошибки.
- Проверка контрольных количеств до переключения backend.
- Резервная копия файлов перед переключением.

### 3. Перевод текущих приложений

- Перевод чтений и записей бота на repository/service слой.
- Перевод изменяющих и аналитических endpoints веб-панели на тот же слой.
- Восстановление активных викторин и расписаний после перезапуска.
- Удаление прямых операционных JSON-записей после успешного cutover.
- Сохранение статических JSON-файлов банка вопросов и конфигурации.

### 4. Telegram API и Mini App

- Улучшение классического чатового UX, надёжности отправки и обработки ответов;
  проверка новых игровых возможностей по [дорожной карте](../TELEGRAM_QUIZ_ROADMAP.md).
- Согласование и внедрение выбранных новых форматов без автоматического
  изменения исторических результатов и рейтингов. Список новинок — кандидаты,
  а не обещание включить все возможности API в один релиз.
- Закрепление проверенной версии `python-telegram-bot` и проверка изменений между
  используемой и целевой версиями.
- Адаптация отправки quiz poll к актуальному API с регрессионным тестом.
- HTTPS frontend shell с Telegram Web App SDK, темой, viewport и базовой
  навигацией.
- Кнопка запуска через `WebAppInfo` и/или menu button.
- Endpoint проверки подписи `initData` и срока `auth_date`.
- Короткоживущая серверная сессия либо эквивалентная схема аутентификации.
- Минимальные пользовательские endpoints: профиль, рейтинг и текущее состояние
  викторины.
- Отдельный web-сервис и маршрутизация HTTPS в Docker Compose/nginx.

## Не входит в задачу

- Полный перенос банка вопросов и статической конфигурации из JSON.
- Реализация игрового домена «Ночной город».
- Полный UI «Ночного города».
- Публичный matchmaking, платежи и монетизация.
- Redis и горизонтальное масштабирование.
- Удаление исходных JSON до успешной проверки миграции и периода стабилизации.

## План реализации

### Этап 0 — решение и baseline

1. Применить принятое решение из ADR-001 о PostgreSQL как основном хранилище.
2. Снять инвентаризацию форматов и контрольные количества данных.
3. Зафиксировать текущий набор smoke-тестов и ручных сценариев.

### Этап 1 — БД без переключения production path

1. Добавить зависимости и конфигурацию.
2. Создать models, repositories и первую миграцию.
3. Реализовать импорт JSON в новую БД.
4. Добавить проверки целостности и идемпотентности импорта.

### Этап 2 — переключение бота

1. Перевести пользователей, настройки, очки, достижения и статистику.
2. Перевести подписки, активные викторины и восстановление после рестарта.
3. Прогнать регрессионные сценарии Telegram-команд и опросов.
4. Сохранить управляемый fallback на файловый snapshot до завершения приёмки.

### Этап 3 — переключение веб-панели

1. Убрать прямое изменение операционных JSON из FastAPI.
2. Перевести аналитику и CRUD на repositories/services.
3. Добавить отдельные границы авторизации административного API.

### Этап 4 — Telegram Mini App foundation

1. Обновить и закрепить Telegram-зависимость после проверки совместимости.
2. Исправить UX и обработку событий классического квиза; проверить совместимость
   вопросного банка, выдачи объяснений и восстановления после ошибок.
3. Согласовать игровые новинки, реализовать выбранные и проверить новые правила.
4. Реализовать frontend shell и Telegram launch button.
5. Реализовать проверку `initData`, пользовательскую сессию и API.
6. Добавить web-сервис, HTTPS-маршрутизацию и production-конфигурацию.

### Этап 5 — cutover и стабилизация

1. Выполнить резервную копию и финальный импорт.
2. Сверить контрольные количества и ключевую статистику.
3. Переключить основной storage backend.
4. Проверить рестарт, параллельные ответы, админку и Mini App.
5. Обновить документацию данных, deployment и changelog.

## Риски и откат

- **Скрытое расхождение форматов.** Сначала импортировать в отдельную БД и
  формировать отчёт, не изменяя исходные файлы.
- **Исчерпание пула соединений.** Ограничить pool size, измерять время ожидания и
  не удерживать транзакции во время запросов к Telegram или внешним API.
- **Недоступность отдельного сервиса БД.** Добавить healthcheck, корректный
  startup retry и проверяемую процедуру резервного копирования/восстановления.
- **Дублирование статистики.** Зафиксировать idempotency keys/unique constraints
  для ответов и начислений.
- **Потеря активного состояния.** Отдельно проверить восстановление викторин и
  scheduler jobs до cutover.
- **Случайная публикация локальной админки.** Разнести сервисы или сетевые
  маршруты так, чтобы внешний HTTPS Mini App не проксировал административные
  endpoints; для пользовательского API применить отдельную auth policy.
- **Откат.** Остановить writers, сохранить проблемную БД, вернуть предыдущую
  конфигурацию storage backend и исходный read-only snapshot JSON.

## Открытые решения до статуса `ready`

- [ ] Выбрать минимальный функциональный экран Mini App: профиль/рейтинг или
  полноценное прохождение викторины.
- [ ] Выбрать frontend stack и способ сборки.
- [ ] Определить production domain и способ выпуска TLS-сертификата.
- [ ] Определить период хранения JSON snapshot после cutover.
- [ ] Выбрать новые игровые форматы и правила их участия в рейтинге по
  [проверке Telegram API](../TELEGRAM_QUIZ_ROADMAP.md).

## Оценка

При выполнении Codex с последовательной проверкой:

- БД, импорт и перевод основного бота: примерно 1–2 плотных рабочих дня;
- перевод веб-панели и стабилизация: примерно 1 рабочий день;
- базовый Mini App с авторизацией и API: примерно 1 рабочий день.

Оценка уточняется после решений из предыдущего раздела и не включает реализацию
самой игры «Ночной город». Добавленный объём улучшений классического бота и
новых игровых форматов требует переоценки после выбора механик; прежняя оценка
не является сроком расширенного релиза.
