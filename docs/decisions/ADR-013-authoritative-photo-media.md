# ADR-013: PostgreSQL-каталог и content-addressed photo media

Статус: `accepted` для dev. Дата: 2026-09-04. Задача: MQB-006.

## Контекст

Метаданные photo-вопросов уже хранились в PostgreSQL, но runtime сначала
сканировал `*.webp` и мог автоматически создать запись по имени файла.
Так каталог не был source of truth, а незавершённая/посторонняя загрузка
могла попасть в игру.

## Решение

- В PG-режиме игра рассматривает только enabled, не archived записи
  `photo_quiz_items`; файл никогда не создаёт runtime-метаданные.
- Логический `media_key` сохраняет идемпотентность upload-формы.
- Новые пиксели публикуются один раз как `sha256-<digest>.webp`;
  `storage_name` и `image_sha256` хранятся в PG-каталоге.
- Админка и игра проверяют, что файл не symlink, остаётся в
  media root и, если digest известен, совпадает с SHA-256.
- Оставшийся после uncertain commit файл без PG-записи не играется.

## Совместимость и следующий gate

Старые каталоги пока читают именованные legacy-файлы, но лишь при
наличии своей PG-записи. Перед production cutover нужен отдельный
идемпотентный backfill/rehearsal: скопировать каждый legacy asset
под content hash, записать manifest в PG и сверить количество/дайджесты.
До этого пунк content-addressed migration в MQB-006 не считается закрытым.
