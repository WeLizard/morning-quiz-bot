# ADR-011: Общее хранилище долгоживущих игр

Статус: `accepted` для dev. Дата: 2026-09-04. Задача: MQB-006.

## Контекст

`quiz_sessions` хранит переходное состояние классического квиза, а Mafia ранее
жила одним приватным payload в `system_states`. Такая запись не даёт общей
истории партий, идемпотентных команд двух клиентов, безопасного исполнения
дедлайнов и расширения платформы следующими режимами.

## Решение

Добавить общий substrate, не зависящий от Telegram и конкретных правил Mafia:

- `games` — авторитетный versioned state, phase/status и признак текущей партии;
- `game_players` — состав, места и раздельные public/private projections;
- `game_commands` — единый idempotency receipt для Bot и Mini App;
- `game_events` — append-only история переходов;
- `game_deadlines` — серверные дедлайны фаз;
- `notification_outbox` — транзакционная очередь доставки событий адаптерам.

На один `chat_id + mode` допускается только одна current-партия, но завершённые
партии сохраняются. Команда сериализуется advisory lock логического игрового
ключа и row lock текущей игры. Одинаковый command ID с теми же параметрами
возвращает сохранённый результат; повторное использование ID с другими
параметрами отклоняется.

Mafia первой переведена на этот слой без изменения её public application API.
Миграция 0008 атомарно преобразует `mafia_lobby:*` из `system_states`, создаёт
players/events/deadline и удаляет прежнюю запись только после успешной вставки.
Реванш создаёт новую запись игры, поэтому история закрытого дела не затирается.

Переход Mafia по deadline и постановка `mafia.phase` выполняются в одной
транзакции. Worker забирает подходящие ему типы через `FOR UPDATE SKIP LOCKED`,
а `dedupe_key` не позволяет двум конкурентным переходам создать два intent.
Явный Telegram `RetryAfter` возвращает intent в `pending`; неизвестный исход
`sendMessage` отмечается `uncertain` и не пересылается вслепую, согласно ADR-006.
Зависшая запись `sending` также не подбирается автоматически: это сознательная
at-most-once граница внешнего API без idempotency key, а не обещание exactly-once.

## Границы этапа

Outbox подключён к серверным переходам Mafia. Classic и Photo пока используют
свои переходные session-модели, а их события ещё не публикуются через общий
outbox. Их перенос выполняется следующими вертикальными этапами, без добавления
логики в MiniBridge.

## Проверка

- две конкурентные попытки обработать один истёкший deadline меняют фазу один раз;
- один переход создаёт ровно один публичный outbox intent без ролей и user ID;
- два worker не забирают один intent, а worker одного режима не забирает чужой;
- `RetryAfter` планирует следующую попытку, неизвестный исход становится `uncertain`;
- повтор одного command ID не создаёт второй event;
- чужая роль отсутствует в public projection;
- пользователь без актуального `chat_members` не может выполнить команду;
- Alembic upgrade переводит legacy Mafia state и не оставляет второй source.
