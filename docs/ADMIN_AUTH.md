# Локальная админка: вход и проверка PostgreSQL-интерфейса

Реализовано в локальной копии 2026-08-30. **Production не трогать**:
не запускать там команды, не копировать новые файлы и не менять окружение.
Это не публичный Mini App API и не завершённая миграция всей админки.

## Вход

`web/main.py` защищает административные маршруты и документацию API в обоих
backend-режимах. Без сессии `/` перенаправляет на `/login`, API отвечает 401.
Нужен отдельный `ADMIN_ACCESS_TOKEN` длиной 32–512 символов. Пустое или слишком
короткое значение даёт 503: небезопасного режима без входа нет. Не используйте
токен Telegram, не сохраняйте ключ в Git и не передавайте его в URL.

После входа выдаётся случайный cookie с HttpOnly и SameSite=Strict, Secure на
HTTPS. Сервер хранит только хэш ID сессии, а CSRF-токен передаётся интерфейсу
и хранится в памяти страницы. Выход отзывает сессию. Таймаут бездействия —
30 минут, абсолютный — 8 часов; перезапуск панели отзывает все сессии.
Лимиты: 5 попыток входа за минуту с адреса, 40 на процесс и до 256 сессий.

Для изменяющих запросов нужны cookie и `X-CSRF-Token` из `GET /auth/session`.
Чужой Origin, cross-site запрос или неподходящий Host отклоняются. По умолчанию
разрешены localhost, 127.0.0.1 и ::1; HTTP разрешён только для loopback-клиента
на loopback-хосте. `ADMIN_ALLOWED_HOSTS` расширяется только явными именами,
без wildcard; удалённый доступ требует HTTPS. Не доверять произвольным
X-Forwarded-* заголовкам и не публиковать панель в интернет.

Выбор cookie-флагов, сроков и серверного отзыва опирается на
[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
Проверка Origin дополняет CSRF-токен, а не заменяет его:
[OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

## Готовые экраны PostgreSQL

### Оформление

По согласованию с пользователем внешний вид старой панели не копируется 1:1:
она служит перечнем функций. Утверждённая демка задаёт тёмную палитру и лаймовые
акценты. Общие цвета и знак с глазами находятся в `web/static/css/quiz-brand.css`;
они используются на входе и во всех шести готовых PG-разделах.
Главное действие выделено лаймом, удаление — отдельной контурной кнопкой.
Счётчики обзора читают API, не содержат демонстрационных значений в разметке.

PG-тема устанавливается сервером до загрузки JS и не зависит от старого
переключателя light/dark. Оформление legacy JSON-панели не заменяется.
Локальные SVG/CSS не требуют внешних шрифтов или изображений. Учтены
`prefers-reduced-motion`, видимый клавиатурный фокус, labels и названия диалогов.
На мобильном экране закрытое меню недоступно для Tab, открытое удерживает
фокус; Escape возвращает его кнопке меню, выбор раздела — заголовку страницы.
Длинные формы прокручиваются внутри диалога без прокрутки подложки.

### Функции

- Обзор: чаты, пользователи, свежесть подтверждения расписаний ботом.
- Чаты: параметры обычного/ежедневного квиза, расписание, часовой пояс,
  автоудаление. Сохранение использует `expected_revision`; при конфликте форма
  остаётся открытой и не повторяет запись автоматически.
- Пользователи: актуальный общий/чатовый счёт и изменение баллов с `expected_score`.
  Поиск по имени/ID и подробный профиль: серии, достижения по чатам, журнал
  новых ответов и экспорт страницы. У чатов также есть профиль и versioned
  переименование только в локальных данных. [Контракты и лимиты](ADMIN_PROFILES.md).
- Фото-квиз: ответ, JSON-подсказки, включение/отключение без удаления медиа.
  Добавлена загрузка JPEG/PNG/WebP с ответом, поиск, фильтры и пагинация;
  [лимиты и сохранность медиа](PHOTO_CATALOG.md).
  Версия metadata проверяется под блокировкой строки; старый запрос даёт 409.
  При правке ответа синхронизируется display_answer, используемый игрой.
- Банк вопросов: категории, поиск, CRUD, импорт/экспорт, версия и история файла.
- Аналитика: итоги PostgreSQL, рейтинг, использование категорий и новый журнал по дням.

В этих экранах значения из БД добавляются через textContent, а не HTML.
Навигация доступна с клавиатуры, формы имеют labels и сообщения об ошибках.
PG-страница не загружает сторонние JS/шрифты, не использует inline handlers;
CSP разрешает скрипты только с собственного origin. Для legacy JSON-интерфейса
этот строгий script-src пока не включён: старые виджеты ещё используют inline/CDN.

Непереведённые разделы скрыты в PG-навигации, но не считаются завершёнными:
расширенная аналитика, удаление операционных данных,
обслуживание, логи и управление процессом бота требуют дальнейшей работы.
Банк вопросов доступен через versioned `/api/bank`, с поиском, CRUD,
импортом/экспортом и историей файлов. Старые файловые write-routes в PG закрыты.
Основная аналитика читает PostgreSQL; история по дням включает только новый
журнал ответов и не выдумывает даты старых агрегатов.
Статический question-bank API остаётся файловым и требует той же авторизации;
непереведённые операционные маршруты по-прежнему дают 501 без JSON fallback.
UI пока не редактирует все поля, доступные через versioned settings API.
В профилях теперь доступны [блокировки, безопасный сброс и квитанции](ADMIN_MODERATION.md).
Физическое удаление/замена фото-файлов пока не реализованы; отключение сохраняет
изображение. Preview пишет новые фото только в `.local/preview/images`.

## Проверка на этом компьютере (PowerShell)

Предпочтительный запуск теперь одной командой:
`pwsh -NoProfile -File .\scripts\Start-LocalDevelopment.ps1` из локальной копии.
Повторяемая приёмка: `pwsh -NoProfile -File .\scripts\Test-LocalMilestone.ps1`.
Подробности и границы — [первый локальный комплект](LOCAL_MILESTONE.md).
Preview редактирует банк в `morning_quiz_dev`. Исходный `data/questions` служит
только одноразовым seed для пустой БД и после запуска не является runtime source.

Preview использует `morning_quiz_dev`, а pytest — отдельную логическую базу
`morning_quiz_test` в том же локальном PostgreSQL-контейнере.

```powershell
Set-Location -LiteralPath 'C:\Users\Lizard\Projects\morning-quiz-bot'
.\scripts\Start-LocalDevelopment.ps1
```

Открыть `http://127.0.0.1:4184/` и вставить ключ. Preview проверяет точный адрес
тестовой БД, очищает Telegram/OpenRouter credentials в своём процессе,
добавляет только тестовые чат/пользователя/фото-метаданные. Банк изменяется в
dev-БД; upload ограничен `.local/preview/images`. Реального бота не запускает.

После проверки:

```powershell
.\scripts\Stop-LocalDevelopment.ps1
```

Процессы UI остановятся; PostgreSQL и dev-данные сохранятся. Сервер и резервные
архивы не затрагиваются.

## Проверено и что не обещается

`tests/test_admin_auth.py` и `tests/test_postgres_admin_ui.py` проверяют вход,
CSRF/Origin/Host, cookie, отзыв/таймауты, лимиты, не настроенный вход, пути медиа,
конфликты фото-метаданных, отсутствие JSON fallback и настоящий web.main.app.
Браузерная проверка: вход, две конфликтующие вкладки, сохранение баллов,
редактирование/отключение фото-вопроса, повторный вход после рестарта и выход.
Все записи — в синтетические данные временной БД. Текущий полный контейнерный
набор: 433 passed; включает PostgreSQL-банк, миграционный rehearsal Mafia,
dump/restore и сквозную приёмку.

Это один доверенный локальный администратор и один процесс web-приложения.
Не реализованы персональные аккаунты/роли, MFA, общий session store для нескольких
workers, полноценный аудит действий и завершённая проверка всех legacy handlers.
Защита входа не означает, что весь старый веб-код прошёл security audit.
Не использовать `--workers` больше 1; ротация ключа требует перезапуска процесса.
Telegram initData не даёт административную сессию.
