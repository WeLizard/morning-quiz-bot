# ADR-008: Постоянный dev-контур и границы эксплуатационных операций

Статус: `accepted`. Дата: 2026-08-31. Область: MQB-002, только локальная разработка.

## Контекст

Демонстрационные данные нельзя терять при pytest/recreate одноразового PostgreSQL.
Полный перенос возможностей включает эксплуатационные кнопки; их старые реализации
вызывают JSON, shell и Telegram с глобальным токеном. Простое включение старых
маршрутов нарушает границы dev и сохранность данных.

## Решение

- Preview получает persistent PG volume/порт 55433; тесты используют отдельную
  логическую `morning_quiz_test` в том же контейнере. Это заменяет прежний
  disposable preview и отдельный тестовый Compose из инструкции ADR-003/007,
  но не меняет их разделение административной и пользовательской авторизации.
- Автономный PTB worker внутри панели использует настоящие handlers и планировщики,
  но исключительно synthetic BaseRequest; процесс production не запускается.
- Рассылки пока только offline, с сохранённым предпросмотром и квитанцией.
  Наличие токена не является автоматическим разрешением на отправки.
- Миграция 0007 добавляет архивные флаги. Удаление профиля — архив после блокировки,
  не удаление anti-replay ledger/очков. Восстановление не снимает бан.
- Dev backup: фиксированные Docker/БД, согласованный PG snapshot, SHA-256 файлов,
  реальное восстановление в UUID-временную БД. Полный откат dev — только offline
  PowerShell с lease и страховочной копией; не HTTP-эндпоинт.
- AI-секреты остаются на сервере. Все три провайдера подключаются серверным API,
  без исполнения стороннего JS в административной сессии; real I/O выключен
  до отдельной настройки и подтверждения оператора.

## Последствия

Dev имеет работающие пользовательские сценарии, но не доказывает доставку в
Telegram или готовность production. UI-dialogue автономного worker и AI-история
в памяти могут исчезнуть при перезапуске; прогресс и настройки остаются в PG.
Публикация, настоящие секреты, HTTPS/ingress и свежая production-миграция остаются
отдельными действиями с отдельной приёмкой. Запуск multi-worker панели не поддержан.
