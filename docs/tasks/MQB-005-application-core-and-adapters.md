# MQB-005 — Общее ядро Morning Quiz и равноправные интерфейсы

- **Статус:** `in_progress`
- **Приоритет:** high
- **Создана:** 2026-09-01
- **Связанное решение:** [ADR-010](../decisions/ADR-010-application-core-and-adapters.md)
- **Среда:** локальная dev-копия; production не изменяется

## Цель и пользовательский результат

Morning Quiz работает как единое приложение. Пользователь может выполнить
доступный сценарий через Telegram или Mini App и получить те же правила,
состояние и результат. Telegram-бот остаётся удобным интерфейсом и транспортом,
но не владеет бизнес-логикой.

## Входит в задачу

- Application commands и projections без типов Telegram/FastAPI.
- Единое состояние классики, фото-квиза и «Ночного города».
- Telegram-adapter: команды, callback-кнопки, polls, групповые права, уведомления.
- Mini App-adapter: игровые экраны, ответы, профиль и настройки.
- Общая идемпотентность, ledger и восстановление после рестарта.
- Матрица паритета функций двух пользовательских интерфейсов.

## Не входит

- Production cutover и изменение production-процессов.
- Публикация локальной админки.
- Одновременная полная перепись всех legacy handlers.

## План

1. Зафиксировать команды/проекции и delivery events общего слоя.
2. Перенести мафию как первый новый вертикальный сценарий сразу с двумя adapters.
3. Перенести классический вопрос/ответ/результат из PTB handlers в game service.
4. Перенести фото-вопрос/подсказку/ответ/результат.
5. Перенести пользовательские настройки и меню.
6. Удалять переходные bridges только после теста паритета и восстановления.

## Критерии готовности

- [x] `/mafia` и Mini App используют одно состояние всей партии и адресные роли.
- [x] Классический вопрос создаётся ядром и одинаково доступен в обоих интерфейсах.
- [x] Фото-вопрос читается из общей сессии, изображение доступно защищённым API.
- [x] Личные настройки, темы и расписание меняются через общий `SettingsService`.
- [x] Повтор команды/ответа из другого интерфейса не создаёт дубль и не начисляет
  баллы повторно.
- [x] Восстановление общего состояния не зависит от Telegram message history.
- [x] Для пользовательских функций отмечены Telegram, Mini App и общий test.
- [ ] Старт/переходы фото-серии и подготовка классического раунда ещё используют
  переходный PTB runtime bridge; вынести delivery events в общий outbox.

## Проверка

- Транспортно-независимые unit tests application services.
- Contract tests Telegram- и Mini App-adapters на одинаковых fixtures.
- PostgreSQL integration tests идемпотентности и восстановления.
- Только после этого — живая проверка в отдельном тестовом Telegram-чате.

## Риски

- Переходный код может временно поддерживать два пути; каждый migrated use case
  должен иметь одного владельца состояния.
- Telegram poll нельзя считать базой данных голосов: принятый ответ фиксирует ядро.
- Скрытые роли и правильные ответы выдаются только адресному projection.
