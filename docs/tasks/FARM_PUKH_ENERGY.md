## 2. Экономика: что нашлось в каталоге

### 2.1. Закон цены рецепта (проверен по данным)

`цена выхода ≈ стоимость входов + минуты * (2.5 + 0.1 * уровень_рецепта)` (в `tests/test_farm_crops_r9.py:119-124` для R9, и тем же законом посчитаны R16: `currant_morse` 361 + 10*4.6 = 407, факт 408; `cherry_syrup` 490 + 15*5.9 = 578, факт 578). Следствие: прибыль в час = `60 * (2.5 + 0.1 * L)` независимо от состава. Для нашей цепочки: уровень 11 даёт 216/ч, 12 — 228/ч, 13 — 240/ч. Это ровно класс соседей.

Правило ингредиентов (`test_farm_crops_r9.py:93-108`): быстрая культура (<1800 с) не более 3x урожая, средняя (<14400 с) не более 2x, долгая не более 1/2 урожая. Малина (7200 с, урожай 4) — не более 8, берём 4. Мята (900 с, урожай 1) — не более 3, берём 1.

### 2.3. Содержание и фонд

* Содержание здания в сутки: `ceil(cost * level / 100)` (`economy.py:68-82`, `catalog.py:620`), начинается с 10 уровня игрока. Здание за 1800 = 18 монет/сутки на ур.1; для сравнения INCOME_REF на ур.10-14 = 13000/сутки (`catalog.py:603`). Вклад ничтожный.
* Улучшения зданий выводятся автоматически (`catalog.py:398-416`): для здания за 1800 ур.2 = 900 монет, ур.3 = 1800; код трогать не надо.
* Фонд деревни принимает ЛЮБОЙ товар из склада по цене `price * 1.25` (`economy.py:151-152`), т.е. выгоднее продажи. Пороги личной шкалы на ур.10-14: 6500/19500/39000/65000/104000. Один «Ягодный энергетос» (85) = 106 в фонд. Новые товары попадают в фонд автоматически, без правок.
* Продажа: `price * (100 + бонус склада 0/5/10%) / 100` (`domain.py:362-365`).
* Заказ: монеты `ceil(цена * 1.45) + 6`, особый заказ x1.2, XP `max(5, цена // 5)`, плюс +5% за уровень репутации (`domain.py:160-175`, `market.py:60`). Пример: заказ на 2 «Ягодных» = 170 -> 253 монеты, 34 XP; особый 304.

### 4.6. «Пух заказывает постоянно» — нужен хук в `make_order`

Проблема: сейчас потребности заказа выбираются случайно и от жителя не зависят (`domain.py:152-160`), любимые товары работают только в особых заказах с уровня «Приятель» и только в 25% случаев. Без хука Пух просил бы случайные товары и энергетиков почти не заказывал бы.

Минимальное решение (в каталоге константа, в `make_order` небольшой блок). Эскиз (НЕ внедрено):

```
# catalog.py
NPC_SIGNATURE = {'Медведь Пух': ('berry_charge', 'honey_charge', 'forest_charge')}
SIGNATURE_PCT = 70        # шанс заказа «в его теме», если есть достижимое

# domain.make_order, после выбора npc и только при seq > 2
sig = [i for i in NPC_SIGNATURE.get(npc, ()) if i in products]
if sig and (rng // 41) % 100 < SIGNATURE_PCT:
    needs = {sig[(rng // 43) % len(sig)]: 1 + (rng // 47) % 3}
    # price считать после этого блока
```

Свойства: обучающие заказы (seq 0-2) не меняются; детерминированно; без здания энергетиков хук молчит и заказ остаётся обычным; особые заказы работают как раньше.

Побочный эффект, который надо принять заранее: `rng % len(NPCS)` теперь делит на 9, поэтому НОВЫЕ заказы и обозы у всех жителей раскладываются по-другому (уже выданные заказы в сохранениях не меняются). Тестов с зашитым «кто именно заказал» нет (проверено), симулятор в пределах шума.

Опционально (вопрос 3): вес Пуха x2 через дополнительный слот в розыгрыше (`rng % (len(NPCS)+1)`, лишний слот отдаёт Пуха); по симулятору на экономику не влияет.

Приглашения друзей (`invite`, `INVITE` в `catalog.py:611`) с жителями не связаны; точек встраивания Пуха там нет, но в `app.js` рядом сейчас идут чужие правки (раздел 7).

## 8. Риски

1. Слово «Пух» само по себе совпадает с частью имени известного персонажа. Образ (бурый медведь с бирюзовым платком и молнией), хижина и реплики оригинальные, но имя решает Илья (вопрос 1).
2. Откат кода после выхода: у игроков с репутацией Пуха старый код упадёт в `validate_market` (`market.py:307`, ошибка 500). Откат делать только вместе с чисткой `rep`.
3. Сдвиг `rng % len(NPCS)` меняет раскладку жителей по НОВЫМ заказам и обозам. Тестов, фиксирующих это, нет.
4. Сломанные до нас тесты (19 красных) нельзя путать с последствиями Пуха.
5. Единственный обязательный сломанный тест от Пуха: `farm_village.test.cjs:125` (восемь позиций).
6. Параллельные правки в `app.js` (раздел 7): конфликт слияния, а не логики.
7. Цена и баланс: цены посчитаны по закону каталога; симулятор показывает шум 1-2%, но реальный прогон на готовом коде обязателен.
8. Мёд как узкое место: «Медовый» берёт 2 мёда за 600-900 с; при желании уменьшить до 1 мёд + 2 травы (пересчитать цену по закону).
9. Сообщения «энергетик» для детей: в тексте подчёркнуть «без кофеина, ягоды и мёд».
