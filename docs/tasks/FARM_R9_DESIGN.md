# Проект r9: 90 дней до финала (этап 11)

Статус: проект wl-architect (Opus), 2026-10-10. Числа — оценки по таблицам «Баланс r9» из
`FARM_GROWTH_PLAN.md` и коду; проверяются на этапе 17 (критерии в разделе 6).

Основа (из кода и плана). Уровень вычисляется из `xp` (`catalog.level`), не хранится. Активный
игрок сейчас достигает L30 за 18,6 дня, на L25–30 набирает ≈10,2 тыс. XP/сутки. Начисления XP —
в 14 местах: `domain.py` (harvest/collect_all, collect, collect_animal +5, build, expand, order,
quest), `expansion.py` (harvest, take_animal, take_job, collect_trip, night_delivery),
`market.py` (обоз, контракты).

## 1. Кривая уровней и миграция

**Максимум L50. Пороги L1–30 не меняются, L31–50 дописываются сверху.** Уровень по-прежнему
вычисляется из xp, поэтому при xp < 146 000 он не меняется — понижение исключено по построению.
Хранимый уровень или пересчёт xp рискованнее (два источника правды, лишняя миграция).

Хвост: Δ(30+k) = 17 000·1,15^k для k = 1…5, далее Δ ×1,04 за уровень. Без перелома: Δ30 = 17 000,
Δ31 = 19 600.

Оценка: при росте базового XP/сутки с 10,2 тыс. (L30) до 13 тыс. (L50) и бонусе М1 (+15%) L50
наступает на ~75–85-й день, последний уровень ≈4 суток. Для 85–95 дней: XP/ч нового контента —
не выше +2% за уровень к L30; основной рост — монеты и разнообразие.

**Хвост L31+ не выкладывается в прод до прогона этапа 17 с контентом этапа 16.** После выкладки
пороги заморожены; дальше подстраиваются только М1–М3 (их можно двигать в обе стороны).

Динамика — одна воронка `progression.grant_xp(farm, amount, source, at, owner)`. Сутки — по
`market.moscow_day` (не `domain.daily`, тот в UTC). Таблица `PACE[lv]` — эталонный XP/сутки:
L1–4 400, L5–9 2 300, L10–14 3 900, L15–19 7 000, L20–30 10 000, далее 10 000 + 150·(lv−30).

| механизм | формула | кому помогает |
|---|---|---|
| М1 «Утренняя роса» | за сутки удваиваются первые 0,15·PACE(lv) XP от команд владельца | всем ежедневным; казуалу относительно больше (+25% против +15%) |
| М2 «Бодрость» | каждые полные московские сутки без команд владельца добавляют 0,5·PACE в пул, потолок 1,5·PACE; пока пул не пуст, XP удваивается | вернувшимся; активный не получает, кривая от неё не зависит |
| М3 «Усталость» | XP с культур короче 600 с и рецептов короче 120 с сверх 0,1·PACE/сутки ×0,25; М1/М2 на него не действуют | гасит эксплойт grind |

Бонусы — только при `owner=True`. Смены помощников в `settle` идут по историческому времени:
бонусы на них не действуют, пул не тратят, «последнюю активность» не сдвигают.

**Нужны данные с прода:** число ферм с `xp ≥ 146000` и распределение по уровням (таблица ферм в
`qw_farm/persistence.py`) — эти игроки сразу поднимутся на L31+.

## 3. Стоки монет

**Содержание фермы** (с L10, путь rescue не задет). Счёт раз в «активные» московские сутки (была
команда владельца):
U = грядки·PLOT_UPKEEP[size] + Σ построек (не декор) ⌈1%·cost·level⌉ + 1 500·га полей,
PLOT_UPKEEP = {≤10: 0, 12: 2, 14: 5, 16: 10, 18: 18, 20: 30}.

Списывается `min(U, coins − starter_credit)` — инвариант `validate_state` сохраняется. Остаток —
`debt` (не копится, закрывается следующим счётом). Пока долг есть, новые таймеры ×1,2 через
`duration()` при старте; идущие не меняются. `pay_upkeep` гасит долг. Предметы не пропадают.
Оценка на L25: ≈5 тыс./сутки, ~12% дохода.

**Фонд деревни** — личная сезонная шкала, сезон 28 московских суток, с L8. Вклад — монеты 1:1 или
товары по цене ×1,25. Пороги (0,5 / 1,5 / 3 / 5 / 8)·INCOME_REF(lv) (монеты/сутки эталона из
симулятора). Награды: сезонный декор, «Праздник» +10% XP на 3 дня, −25% к содержанию до конца
сезона, анимированный декор, трофей с титулом.

**Платный декор** — только косметика, без содержания. Тиры: I L8 1–3 тыс., II L15 8–20 тыс.,
III L25 40–90 тыс., IV L35 150–300 тыс., V L45 400–800 тыс. (трофеи).

Цель — стоки съедают 30–60% чистого дохода с L10. Фонд и декор добровольные, поэтому цель — ёмкость
стоков в полосе; в симуляторе — явная политика трат (раздел 6).

## 4. XP за животных

`xp = max(2, (V_out − V_in) // 4)` за базовую партию × `mult` улучшения домика (V — цены `ITEMS`,
добавленная стоимость: корм уже дал XP культурам). Примеры: курочки 3 (сейчас 5), коровы 6, овцы 9,
пчёлы 16, павлины 28. XP пишется в `animal_job['xp']` при кормлении, сбор берёт
`job.get('xp', 5)` — идущие партии сохраняют старую награду. Доля животных в XP: ~3% → 4–6%.

## 5. Поля и техника

**Данные.** Поля — отдельно в `farm['fields']`, не в `objects` (`validate_state` ограничивает
клетки объектов `size`, `rect()` — LAND_MAX, есть `object_limit`). Запись:
`{id, step, ha, w, h, state: wild|ready|growing|ripe, crop, run, revision}`.

**Цены.** `FIELD_STEPS`: L22 1 га 60 тыс., L27 1 га 120 тыс., L32 2 га 250 тыс., L38 2 га 450 тыс.,
L44 3 га 800 тыс. (самый дорогой шаг земли — 25 тыс.).

**Экономика.** 1 га = 64 клетки ≈ 16 грядок по выходу. Урожай = `yield_qty·16·q_sow·q_harvest`,
семена = `cost·16`, рост = `max(seconds, 14400)`, XP = `crop.xp·8·q` (на единицу вдвое меньше
грядки). Топливо 200 монет/га за операцию. Сажать — только культуры с флагом `field`.

**Техника.** `tractor` и `harvester`; домашний `machine_run` и квест q13 остаются. Трактор —
«расчистка» и «посев», комбайн — «уборка». Тиры ширины 1→2→3: т2 30 тыс., т3 120 тыс. (сток).

**Мини-игра** — сетка 8×(8·га). «Автопилот» доступен всем: q = 0,95, готово через
90 с·га/ширину по серверному таймеру. Вручную q = 0,85 + 0,2·score,
score = clamp((cov − 0,6)/0,38, 0, 1) − 0,3·max(0, overlap − 0,25); итог 0,85–1,05, по двум
операциям ≤ 1,10.

**Протокол.**
- `buy_field {step}`.
- `field_start {field, op, crop, revision}` — сервер списывает топливо и семена, создаёт
  `run {id, op, started_at, expires_at = +900 с, width, seed}`; препятствия детерминированы (sha256).
- `field_finish {field, run, path|null}` — `path` из UDLR длиной ≤ min(3·tiles/width, 2000).

**Античит.** Сервер сам проигрывает путь (соседство ходов, границы, препятствия), сам считает
покрытие; цифра клиента игнорируется. Время: `now − started_at ≥ 0,12 с·len`; `finish` — один раз;
просроченный `run` закрывается в `settle` как автопилот. Выгода бота ≤ +10% к автопилоту. Лимит
размера тела запроса сверить в `api.py`/`rate_limits.py`.

## 6. Симулятор

- `--days 90`; `BANDS` и `MILESTONES` до L50 с шагом 5.
- Профили: active, casual, grind, `returning` (active с перерывом на дни 30–40), `skilled`
  (поля «змейкой», q 1,05).
- Политики: `pay_upkeep` при долге; покупка поля при цене + резерв; операции на полях каждый визит;
  излишек сверх 2·INCOME_REF — 50% в фонд до 5-го тира, затем декор (≤ 30% излишка).
- Отчёт: XP по источникам (с М1, М2 и потерями от М3); доля стоков по полосам; максимум суток на
  уровень; монеты на руках.

**Критерии приёмки:**
- active — L50 за 85–95 дней, casual — за 120–150;
- grind быстрее active не больше чем на 10%;
- любой уровень active — не дольше 4,5 суток;
- стоки 30–60% с L10;
- запас монет к концу полосы ≤ 10 суток дохода;
- животные дают 4–8% XP.

## Очередь правок по отзывам игроков (2026-10-10, после этапа 15A)

1. **Рожь** (отзыв: «пшеница быстро, рожь 2 часа»): рожь ни в одном рецепте не используется и даёт
   ~28 монет/ч против ~480 у пшеницы. Сделать: рост 1 ч, доходность не ниже культур своего уровня;
   мельница — ржаная мука; пекарня — ржаной (бородинский) хлеб, батон, бублики/сушки (новые товары
   и рецепты, отрисовка иконок). В карточке семян — время роста, доход/ч и подсказка «Долгая
   культура: посади перед уходом».
2. **Отмена посадки** (решение владельца: с небольшим штрафом): в первые 60 с после посадки —
   полный возврат стоимости семян (защита от промаха); позже — возврат 50% стоимости, без XP.
   Грядка сразу свободна. Кнопка «Выкопать» в окне грядки с подтверждением и суммой возврата.
3. **Досрочный возврат из леса** (с небольшим штрафом): в первые 60 с — отмена с полным возвратом
   взятого (хлеба и т. п.); позже — «Вернуться раньше»: добыча = floor(выход × доля прошедшего
   времени × 0,5), XP не начисляется, взятое не возвращается. Помощник-проводник — та же логика.
4. **Разнобой времени роста** (отзыв: тыква 3 ч, рожь 2 ч, пшеница 30 с). Сейчас время не следует
   правилу: на L1 овёс 30 мин рядом с пшеницей 30 с, на L3 рожь 2 ч рядом с горохом 25 мин, на L6
   тыква 3 ч, хотя тыквенный пирог требует 3 тыквы. Сделать единое правило:
   - сетка времён: 30 с, 2, 5, 15, 30 мин, 1, 2, 4, 8, 12, 24 ч; у каждой культуры класс
     «быстрая» (≤ 15 мин), «средняя» (30 мин – 2 ч), «долгая» (≥ 4 ч, «посади перед уходом»);
   - на каждой полосе уровней есть культуры каждого класса; доход за урожай растёт со временем,
     доход в час у долгих ниже (плата за то, что не надо заходить), но в одном коридоре;
   - культуры-ингредиенты рецептов (тыква для пирога и т. п.) — не дольше «средней», либо рецепт
     требует меньше штук;
   - список семян сортируется по времени, в карточке — класс, время, доход/ч, подсказка.
   Пересчитать симулятор (этап 17 учитывает новую сетку). Растущие посадки не меняются.
### Очередь 2 (владелец, 2026-10-11) — после завершения 15A, перебалансировки культур и п.1–4

Порядок владельца: сначала доделать предыдущее (15A, проект перебалансировки, п.1–4), потом это.

5. **Новые производства:** молокозавод (молоко → йогурт, кефир, сыворотка/сывороточные напитки,

10. **Наведение:** подсвечивать сам объект (животное, здание), а не клетку.
11. **Строительство:** после установки грядки режим не закрывается — можно ставить несколько подряд;
    выход — кнопкой/Esc.
12. **Нижняя лента семян:** прокрутка колесом мыши на ПК при наведении.
13. **Подсказки назначения** зданий (зачем кормоцех и т. п.): что производит, из чего, кому нужно.
14. **Тосты** («Базилик посажено» и т. п.) не перекрывают ленту семян: перенести наверх, сделать
    ненавязчивыми (короткие, полупрозрачные, без перекрытия управления).

Сервер проверяет всё сам (ревизия объекта, идемпотентность команды), начисления — через существующие
механизмы (XP только progression.grant_xp).

## Решения владельца (2026-10-10)

1. **Фонд деревни — две части:** личная сезонная шкала (как в разделе 3) **и** общий счётчик всей
   деревни. Каждый вклад идёт в обе. Общая цель сезона масштабируется от числа активных ферм; при
   её достижении награду получают все внёсшие хотя бы минимальный вклад (сезонный декор + общий
   «Праздник»). Реализация: отдельная таблица сезона деревни (alembic, только добавление), атомарный
   `UPDATE ... SET total = total + :v`, без блокировок фермы. «Праздник» +10% XP оставляем.
2. **Мини-игры — вид сверху, своя на каждую спецтехнику** (уточнение владельца): цикл поля из трёх
   операций, у каждой своя машина и своя механика. Все — сетка сверху, ввод = путь UDLR плюс
   события, сервер проигрывает всё сам (античит раздела 5).
   - **Культиватор — «культивация»** (расчистка/подготовка `wild`/после уборки → `ready`): объехать
     поле, срезая сорняки и объезжая камни; оценка — покрытие и перекрытие (формула score из
     раздела 5). Влияет на **время роста**: вручную до −15% к автопилоту (без роста дохода с клетки).
   - **Сеялка — «посев»** (`ready` → `growing`): вести ровные ряды; оценка — доля клеток, засеянных
     по разметке рядов, штраф за двойной посев и пропуски. Влияет на **урожай** (q_sow).
   - **Комбайн — «уборка»** (`ripe` → `wild`): собирать полосы, следить за бункером и вовремя
     выгружать в грузовик у края поля (событие `U` в пути); переполнение = потери. Влияет на
     **урожай** (q_harvest).
