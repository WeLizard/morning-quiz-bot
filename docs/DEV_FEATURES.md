## Открыть и попробовать

Из рабочей копии одной командой:

```powershell
.\scripts\Start-LocalDevelopment.ps1
# Вместе с живым тестовым Telegram-адаптером:
.\scripts\Start-LocalDevelopment.ps1 -WithTelegram
```

- Панель: <http://127.0.0.1:4184>. Синтетический ключ:
  `local-tests-only-admin-key-0000012345` — только для loopback dev.
- Mini App: <http://127.0.0.1:4185/app>. Кнопка входа явно обозначена как dev;
  по умолчанию используется игрок `900000000091` и его synthetic private игра.
  Для существующего профиля в dev-БД:
  `Start-LocalDevelopment.ps1 -PlayerId <ID>`.
  Для реального ID это только просмотр, не управление Telegram. По умолчанию
  полный игровой сценарий работает с OfflineRequest; публиковать порт 4185 нельзя.
- В панели откройте **Тестовый бот → Запустить → /quiz → Начать**. Кнопки
  опроса создают настоящие входящие Update в PTB; обработчики начисляют очки в PG.
  `/photo_quiz` запускает фото-серию с текстовыми ответами. Нужен включённый
  вопрос с файлом: его можно загрузить в разделе «Фото-квиз».
- Главная Mini App теперь игровая: классический/фото-квиз, настройка параметров,
  вопросы и ответы прямо в приложении. Верхнее «Обновить» убрано; профиль и
  рейтинги второстепенны. [Покрытие и ограничения](MINI_APP_GAMEPLAY.md).

Автономный бот работает внутри одного процесса панели, не запускает `bot.py`,
не ищет/не завершает чужие процессы и не выполняет shell-команды. Его транспорт
не имеет сетевого клиента, поддерживает только синтетический чат. Журнал и
последние сообщения — память процесса; игровые checkpoints и прогресс — PG.
Закрытие панели останавливает worker. Планировщик подхватывает настройки каждые
15 секунд; реальные Telegram-запросы отсутствуют.

## Какие возможности доступны

| Область | Результат |
| --- | --- |
| Настройки | Число вопросов, таймер, интервал, анонс/задержка, режим и пул категорий, количество тем; ежедневные времена/timezone, мудрость, сброс с версией и подтверждением |
| Банк | PostgreSQL CRUD, поиск, атомарный экспорт/импорт категорий, исправление вопросов, optimistic version и журнал прежних ревизий |
| Фото | PG-каталог, content-addressed upload, ответ/подсказки, отключение, immutable-замена, корзина и восстановление; незарегистрированные файлы не играются |
| Профили | Баллы, история, достижения, ban/unban, безопасный reset, архив/восстановление с квитанциями |
| Аналитика | Область чата/все, период новых ответов, полный рейтинг с пагинацией, категории/веса, распределение и график активности, JSON/CSV |
| Обслуживание | PG-флаг, прерывание игр, блокировка запусков/очков/расписаний; уведомления не чаще раза в минуту на чат; последующая очистка |
| Рассылки | Явные адресаты, сохранённый предпросмотр, подтверждение количества, идемпотентный автономный отчёт и история. Сообщений в Telegram: 0 |
| AI | Диалог и выбор Anthropic/OpenRouter/Puter, отдельные серверные ключи, обычный текст без исполнения HTML; демонстрационный ответ явно не выдан за модель |

Архивирование пользователя/чата требует предварительной блокировки. Сохраняются
баллы, достижения, история и антидубль ответов; восстановление **не** снимает бан.
Сброс категорий затрагивает вклад только выбранного чата, а не соседние чаты.
График показывает новые ledger-события: старые JSON-итоги не превращаются в
выдуманные исторические точки. Массовый импорт банка проверяет весь пакет перед
записью и применяет категории одной PostgreSQL-транзакцией; предыдущие версии
сохраняются в журнале ревизий.

## Данные dev и тестов разделены

| Назначение | Docker / порт / БД | Хранение |
| --- | --- | --- |
| Панель, Mini App, автономный/Telegram-бот | контейнеры `mqb-local-dev`, БД `morning_quiz_dev` | Постоянный volume `mqb-local-dev_dev-postgres` |
| pytest | тот же `mqb-local-dev`, 55433, `morning_quiz_test` | Отдельная логическая БД; отдельные схемы для сценариев |

PostgreSQL-контейнер ровно один; приложения, миграции и тесты используют один
общий dev image. Приёмка пересоздаёт только
`morning_quiz_test`, не `morning_quiz_dev` и не volume. Регрессия не получает
dev URL через `TEST_DATABASE_URL`. Банк находится в `morning_quiz_dev`; каталог
`.local/preview/images` содержит только media-файлы. Исходный JSON-банк может
один раз заполнить пустую dev/test-БД, но после seed не читается runtime.
Не используйте `down -v` для dev: это удалит постоянный volume. Обычный
`docker compose -p mqb-local-dev -f compose.dev.yml stop` сохраняет данные.

## Резервные копии

Раздел **Управление**: создать → скачать → проверить восстановление. Архивы в
`.local/dev-backups` на этом ПК, не на production-сервере. Формат 2 содержит
custom `pg_dump`, media-файлы и SHA-256 каждого файла; банк вопросов уже находится
в дампе и отдельно не дублируется. Секреты `.env`, ключи и исходный код в архив
не входят. Формат 1 по-прежнему читается для восстановления старых dev-архивов.

Проверка создаёт временную `mqb_restore_<uuid>` в том же локальном PostgreSQL,
восстанавливает дамп, сравнивает число/содержимое строк всех таблиц
и удаляет **только эту** проверочную БД. Dev не перезаписывается.
Актуальная контейнерная проверка прошла для 21 таблицы и 200 файлов
без изменения dev-БД; snapshot `176a633c61264070a6792379acc452bf` восстановлен
во временную БД и побайтово сверен.

Для намеренного полного отката dev остановите оба приложения, затем:

```powershell
.\scripts\Restore-LocalDevBackup.ps1 -BackupId <ID_из_списка> -ConfirmOverwrite morning_quiz_dev
```

Проверяются локальный workspace, Docker, БД/роль/порт, остановленные службы и
эксклюзивная файловая блокировка. Создаётся свежая страховочная копия; предыдущие
каталоги сохраняются отдельно. Восстановленные сессии Mini App отзываются,
активные игры прерываются. Эта перезапись текущей dev-БД при разработке не запускалась.
«Удалить архив» перемещает конкретный zip в `trash`, а не стирает его безвозвратно.

В PG `/backup`, `/backups`, `/backupstats`, `/restore`, `/deletebackup` не вызывают
старый JSON-архиватор. Команды доступны только владельцу бота; сам архив не
отправляется в чат. `/restore ID` — проверка отдельной БД, не онлайн-откат сервера.
Реальные Telegram-команды пока не проверялись; в симуляторе файловые операции
выполняются через панель, а не через поле ввода чата.

## Обновлённые меню и Mini App

Новая главная бота: классический/фото-квиз, прогресс, рейтинги, категории,
помощь и доступные по правам настройки. Настройки показывают текущие значения,
содержат возврат на главную; старые карточки не могут менять активный диалог.
Кнопки используют [поддерживаемые Telegram цветовые стили](https://core.telegram.org/bots/api#inlinekeyboardbutton).
При timeout редактирования сообщение не дублируется слепой повторной отправкой.

Mini App сохраняет утверждённый стиль с совой и лаймовым акцентом. Главная
компактнее; в профиле есть системная/светлая/тёмная тема, виброотклик и явный
fullscreen при поддержке клиентом. Подключены BackButton, SettingsButton,
изменения темы/viewport/safe areas и обновление после возврата в приложение.
[Контракт Telegram SDK](https://core.telegram.org/bots/webapps#initializing-mini-apps).
Настройки вида хранятся локально, но токены/очки — нет.

При заданном сервером username бота и личном контексте приложение открывает
игру или настройки deep link-ом. Без username, в локальном просмотре и для
групп команда копируется явно — приложение само не отправляет сообщения от игрока.
Классический и фото-квиз продолжают играться в чате.

Подготовлен `Start-LocalTelegramMiniApp.ps1`: отдельный loopback upstream 4187,
test token, Telegram HMAC и allowlist одного пользователя. Он не публикует tunnel.
Нельзя направлять ingress на админку 4184, dev-login 4185, health 4186 или PG.
После явного разрешения 2026-08-31 подключён временный Quick Tunnel и Mini App URL
только для тестовой лички. [Текущая ссылка, запуск и остановка](TELEGRAM_MINI_APP_TEST.md).

Проверка 2026-08-31: **392 passed, 30 warnings**, JUnit
`.local/acceptance/telegram-menu-mini-app.xml`; HTTP-проверка выбранного реального
dev-профиля и logout. Telegram подтвердил доставку новой главной. Визуальная
приёмка и настоящий Mini App-вход в Telegram ещё не выполнены.
[Задача и незакрытые критерии MQB-003](tasks/MQB-003-telegram-experience.md).

## Другие внешние подключения

Тестовый Telegram-ключ хранить только локально в игнорируемом `.env.telegram-test`:
`TELEGRAM_TEST_BOT_TOKEN=…`. Само наличие файла не запускает бот. Нужны явные
тестовый чат/пользователи и разрешение на тестовые сообщения. Production token
не требуется. Публичный Mini App потребует HTTPS и проверки в Telegram-клиентах.
`MINI_APP_URL` по умолчанию пуст: никакого изменения меню рабочего бота нет.
После отдельной настройки валидного HTTPS URL код добавляет кнопку в личный
`/start` и menu button; группы продолжают использовать обычные команды.

AI: `MQB_ADMIN_AI_ENABLED=1`, отдельные `MQB_ADMIN_AI_<PROVIDER>_KEY` и
`MQB_ADMIN_AI_<PROVIDER>_MODEL` для `ANTHROPIC`, `OPENROUTER`, `PUTER`.
Ключи не вводятся в браузере и не попадают в PG/экспорт. Каждый реальный запрос
требует подтверждения передачи текста; автоматического чтения данных бота нет.
Puter подключается серверным токеном, а не сторонним JS внутри административной
сессии. Контракты: [Anthropic](https://platform.claude.com/docs/en/api/messages/create),
[OpenRouter](https://openrouter.ai/docs/api_reference/overview),
[Puter](https://developer.puter.com/tutorials/puter-auth-token/).
Реальные ключи/платные запросы не использовались; проверены подменённые ответы,
ошибки авторизации/лимитов/формата, без слепого повтора.

## Повторяемая проверка

start → /start → stop автономного бота. Не вмешивается в уже запущенный пользователем

основной приёмки не требуется.

новых экранов и доставка на настоящие Telegram-устройства в этот прогон не входили.
