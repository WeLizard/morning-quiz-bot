# Профили участников и чатов в локальной админке

Реализовано локально 2026-08-30 в рамках MQB-001. Production не читался и не менялся.

## Возможности

В разделах «Участники» и «Чаты и расписания» доступны поиск по имени/названию
или ID и страницы по 24 карточки. Кнопки «Профиль участника» и «Профиль чата»
открывают подробности: актуальные баллы, количество классических ответов,
верные ответы с учётом фото-квиза, серии и коды достижений по чатам,
первая/последняя известная активность. Профиль чата также показывает активные
игры без раскрытия будущих вопросов и ответов.

Счётчик классических ответов и число верных ответов с фото имеют разные
основания подсчёта. Делить второе на первое для вычисления процента точности
нельзя: верных ответов с фото может быть больше. UI не рисует такой процент.
Даты, отсутствующие в импортированных данных, показываются как «Нет данных».

## Согласованность и история

`AdminProfiles.read()` выполняет запросы в одной транзакции PostgreSQL
`REPEATABLE READ READ ONLY`. Показатели, строки участников и события одного
ответа API относятся к одному срезу. Чтение не обновляет кэш бота и не пишет JSON.
Баллы и начисления передаются в API строками Decimal; Telegram IDs — строками.

Журнал содержит только фактически записанные `poll_answers`. Старые агрегаты
не превращаются в выдуманные события. Ручные изменения баллов не попадают в
журнал игровых ответов, поэтому сумма журнала не обязана совпадать с рейтингом.
Имена в журнале берутся из текущего профиля, а не считаются историческими именами.
Время в интерфейсе показано в UTC.

Страница содержит не более 50 участий и 50 событий. Участия листаются по offset,
история — по курсору `(answered_at, poll_id, user_id)` с детерминированной сортировкой.
Каждая новая страница — новый согласованный срез, не закреплённая на сервере
долгая транзакция. При изменении рейтинга между страницами offset-выдача может
сдвигаться; для актуального просмотра следует обновить профиль.

## API и экспорт

`GET /api/users/{id}/profile` и `GET /api/chats/{id}/profile` принимают
`members_offset` (0–1 000 000), необязательный `history_before` и `download=true`.
Курсор проверяется по формату/типам, но не заменяет авторизацию: область выборки
всегда ограничивается участником или чатом из URL. Всё API требует сессии админа.
Отрицательный offset, переполненный int64 ID и неправильный курсор дают 422,
отсутствующая сущность — 404. Ответ имеет `Cache-Control: no-store`.

«Экспорт страницы · JSON» загружает новый срез с теми же параметрами страницы,
включая лимиты, total, has_more, next_cursor и время среза. Это **не полный архив**
и не резервная копия БД. Между просмотром и скачиванием данные могут обновиться.
Не экспортируются raw settings, служебные токены и состояние будущих вопросов.
JSON выбран без табличного вычисления пользовательских строк как формул.

## Название чата

`PUT /api/chats/{id}/title?expected_revision=...` принимает `{"title":"..."}`.
Название обрезается по краям, должно содержать 1–255 символов.
В одной транзакции под row lock обновляются `chats.title`, `settings.title`
и общая `settings_revision`. Без версии — 428; чужая правка настроек/названия
даёт 409 и не перезаписывается. Повтор уже актуального названия не меняет версию.
Отсутствующий чат не создаётся. Настройки и строки расписаний сохраняются.

Это название в данных проекта, **не вызов Telegram setChatTitle**. Перезапуск,
отправка сообщения или обращение к Telegram для переименования не нужны.

## Миграция и проверки

Alembic `20260830_0003` добавляет индекс `poll_answers(user_id, answered_at, poll_id)`
для пользовательского журнала. Данные и столбцы не изменяются. Используется
обычный CREATE INDEX: будущий production upgrade требует согласованного окна,
поскольку операция может блокировать writers; здесь применялась только локально.

Проверены API, авторизация/CSRF, экспорт, Unicode-курсор, границы страниц,
одновременное чтение и правка счёта, конкурентное переименование/настройки,
сохранение расписаний, отсутствие JSON fallback для ban/reset/delete.
Браузером проверены 1440/390/320 px, поиск/пустая выдача, оба профиля,
вложенная форма переименования, сохранение и возврат названия тестового чата.
Широкие таблицы имеют собственную прокрутку и клавиатурный фокус.

Общая регрессия: **182 passed, 0 failed, 0 skipped**, 21 прежнее предупреждение:
174 теста в отдельной временной БД и 8 сквозных тестов в приватных схемах
локальной test DB, включая `pg_dump/restore`. Отчёты:
`.local/acceptance/profiles-regression.xml`, `profiles-acceptance.xml`.
`alembic check` чистый; JS проверен `node --check`.

## Что обнаружено в старых ban/reset

Поиск `blacklist` в Python-коде нашёл чтение/запись только в `web/main.py`.
Подключённые handlers/managers не проверяют этот список: наличие кнопки
ban/unban не доказывает фактическую блокировку команды, ответа или расписания.
Нужны явный контракт блокировки и применение в runtime, а не только перенос JSON.

Legacy reset пользователя стирает answered_polls и часть профиля, chat reset
очищает users.json и статистику категорий. Перенос этих действий без учёта
ledger, активных игр, глобальных агрегатов и восстановления опасен.
Исправление реализовано следующим локальным блоком: [действующие блокировки,
предпросмотр сброса и журнал операций](ADMIN_MODERATION.md). Старые опасные
маршруты остаются 501, новые формы используют отдельные PostgreSQL-контракты.
История/дедупликация сохраняются; автоматический undo не заявлен. Общий релиз
MQB-001 остаётся незавершённым.
