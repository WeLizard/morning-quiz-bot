# Интеграция «Alchemia» с Morning Quiz

## Что это

«Alchemia — атлас маленьких чудес» — одиночная браузерная игра: 190 элементов из
четырёх стихий, 347 однозначных рецептов, 190 векторных иллюстраций, 10 категорий,
8 необязательных глав, 12 достижений. Игра не ходит в сеть, не знает про Telegram
и хранит прогресс в `localStorage` (ключ `alchemia.atlas.v1`), плюс есть экспорт и
импорт JSON-сохранения.

## Как встроена (уровень 0)

- `build.py` собирает один автономный HTML (`shell.html` + `style.css` + `art.svg`
  + `data.json` + `game.js`), внутри него лежат все стили, скрипты и графика.
- Собранная страница закоммичена как `web/mini_client/alchemy.html` (316 259 байт,
  sha256 `84c416ab3a4337ae9713cd35d114936cd75a58e258e2cbc332e941455c68ec51`)
  и отдаётся мини-аппом по маршруту `GET /app/alchemy` (`web/mini_app.py`,
  объявлен раньше обработчика `/app/{asset}`).
- Плитка «Атлас маленьких чудес» на главной мини-аппа
  (`web/mini_client/app.js`).
- Тест `test_alchemia_atlas_is_served_as_self_contained_mini_app_page`
  (`tests/test_mini_app.py`) проверяет: страница отдаётся, автономна, **её CSP
  разрешает инлайн-стили и скрипты**, у API-маршрутов политика остаётся строгой,
  а `/app/alchemy.html` по-прежнему 404.

## Важно: CSP мини-аппа

Мини-апп ставит `Content-Security-Policy` на каждый ответ. Для страниц-одиночных
игр политика должна разрешать инлайн, иначе браузер выкидывает стили и скрипты и
вместо игры видно голый текст. В `web/mini_app.py` для этого есть
`static_game_page`:

```
default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self' data:; connect-src 'none';
base-uri 'none'; form-action 'none'; frame-ancestors https://web.telegram.org https://*.telegram.org
```

Сеть (`connect-src 'none'`), формы и подмена base-uri запрещены — игры автономны,
им это не нужно. Новую одиночную игру нужно добавить и в `static_game_page`, и в
`public_page` (второй набор нужен, чтобы Telegram-фрейм не отбивался проверкой
`Sec-Fetch-Site`).

## Пересборка

```sh
cd minigames/alchemia-1.0
python build.py                                    # проверяет граф и собирает index.html
cp index.html ../../web/mini_client/alchemy.html
```

Две ловушки при сборке на Windows:

1. `build.py` запускает `build_data.py` и `build_art.py`, а те читают файлы
   `read_text()` без явной кодировки — на русской Windows это cp1251 и падение с
   `UnicodeDecodeError`. Лечится запуском с `PYTHONUTF8=1`.
2. `write_text()` на Windows превращает `\n` в `\r\n`, поэтому собранный файл
   отличается от версии, собранной на Linux, ровно на число строк (675 байт).
   Для сравнения с закоммиченным артефактом нормализуйте переводы строк.

После нормализации сборка совпадает с закоммиченной страницей байт в байт.

## Границы уровня 0

- Прогресс хранится в браузере устройства, между устройствами переносится только
  вручную через экспорт/импорт JSON.
- Очки, достижения и рейтинги платформы не начисляются: игра не пишет в PostgreSQL
  и не участвует в game substrate.
- Из бота игра не запускается и не анонсируется.
- У страницы игры нет своей кнопки возврата: назад — системной кнопкой или
  историей браузера.

## Что нужно для уровня 2 (полноценная четвёртая игра)

1. Хуки в `game.js`: событие об открытии элемента и чтение/запись прогресса.
2. Модель в game substrate: `Game(kind='alchemy')`, `game_events`, при
   необходимости `game_deadlines` и `notification_outbox`, миграция `0012`.
3. `application/alchemy.py` + доменные правила (какие открытия дают очки).
4. Адаптеры: маршруты мини-аппа, команды и уведомления из бота, лидерборд.
5. PG-тесты, ADR и обновление описаний в `docs/`.
