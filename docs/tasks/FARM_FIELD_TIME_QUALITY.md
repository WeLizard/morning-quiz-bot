# Техника на полях: время, качество и автопилот (вариант формулы)

Статус: **решено владельцем 2026-10-14: вариант B, 2,5× / 6× / срок захода 1800 с. Реализовано** (сервер, клиент, тесты;
не закоммичено). Клиент (темп 450/320/180 мс на шаг, обратный отсчёт, итоговый экран) сделан раньше.

Реализация: `catalog.py` (`FIELD_RUN_TTL`, `FIELD_FULL_K`, `FIELD_ZERO_K`, ключи `run_full_k`/`run_zero_k` в публичном
каталоге), `fields.py` (`timed_quality`, метка `qrule = 2` в заходе, `last_q` в поле — точное качество последнего захода для
экрана результата), `static/tractor_game.js` (`timedQuality`, `timeKeep`, `timeLimits`; строка «полный бонус ещё M:SS /
бонус тает»), `style.css` (`.fg-pace`). Тесты: `tests/test_farm_fields_r9.py` (формула, ключевые точки, старый заход без
`qrule`, срок), `tests/fixtures/farm_fields_timed/timed.json` + `tests/js/farm_tractor.test.cjs` (паритет JS↔Python).

Запрос владельца: «время на работу с техникой слишком маленькое — никто не успеет; нужно побольше; результат должен быть
пропорционально зависим от времени, качества и автопилота: сделал сам — молодец, полный бонус».

## 1. Что есть сейчас (`qw_farm/fields.py`, `catalog.py`)

- Качество вручную: `q = 850 + 250·score/1000` (0,85…1,10); автопилот `Q_AUTO = 950`, готов через `90 с · га / ширину`.
  Решение владельца (`FARM_R9_DESIGN.md`, п. 3): вручную до +15 % за операцию к автопилоту, цикл вручную ≈ +34 % урожая.
- Срок захода `FIELD_RUN_TTL = 900 с`; просроченный заход закрывает `settle` как автопилот (q = 950, без бонусов владельца).
- Время сервер знает только как нижнюю границу (`0,12 с · длина пути`, защита от ботов). На качество оно **не влияет**:
  можно ехать 14 минут и получить то же, что за 40 секунд.
- Эталонный маршрут (честный игрок, `reference_path`) — 24–222 шага; при темпе клиента 450 мс чистое движение
  занимает от 11 с (1 га, ширина 3) до 100 с (3 га, ширина 1).

Вывод: 900 с хватает на сам маршрут с запасом, но **ничто не связывает время с наградой**, а запас на «подумать, отвлечься,
играть с телефона» невелик (15 минут и поле закрывается автопилотом).

## 2. Предлагаемая модель времени

Единица времени — `A = auto_seconds(га, ширина)` (то, сколько ждал бы автопилот; считается без множителя скорости мира:
пороги в реальных секундах). Время захода `t = finish_at − started_at` (целые секунды серверных часов, как и сейчас).

```
q_score = 850 + 250·score/1000                       # как сейчас, 850…1100
bonus   = q_score − 950                              # над автопилотом (может быть < 0)
T_full  = A · K_FULL / 100       T_zero = A · K_ZERO / 100
f(t)    = 1000                      при t ≤ T_full   # «успел» — полный бонус
        = 1000·(T_zero − t)/(T_zero − T_full)        # линейно вниз
        = 0                         при t ≥ T_zero   # медленно = автопилот
q       = 950 + bonus·f/1000        если bonus > 0
        = q_score                   если bonus ≤ 0   # (вариант C: = 950)
```

Автопилот — база: медленный игрок никогда не получает меньше автопилота за счёт одного только времени; быстрый и чистый — полный
бонус (до +15 %); между ними пропорционально. Все числа целые, без плавающей точки (как весь `fields.py`).

Пороги при `K_FULL = 250 %`, `K_ZERO = 600 %`:

| га / ширина | A, с | полный бонус до | бонус 0 с |
|---|---|---|---|
| 1 / 3 | 30 | 75 с | 3 мин |
| 1 / 1 | 90 | 3 мин 45 с | 9 мин |
| 2 / 2 | 90 | 3 мин 45 с | 9 мин |
| 3 / 1 | 270 | 11 мин 15 с | 27 мин |

Сравнение: эталонный маршрут 1 га/ширина 1 — 64 шага; при темпе 450 мс это 29 с чистого хода, т. е. «полный бонус» даётся с
запасом ×7 на раздумья. Для самого большого заезда (3 га, ширина 1, 222 шага, 100 с хода) — окно 11 минут.

Срок захода должен быть не меньше `T_zero` самого большого заезда (`270 · 6 = 1620 с`), поэтому
**`FIELD_RUN_TTL = 1800 с`** (30 минут) вместо 900. Остаётся константой каталога и уходит клиенту как `run_ttl`
(«через конфиг» = через `catalog.py`; отдельного файла настроек у `qw_farm` нет).

### Примеры (1 га, ширина 1: A = 90, T_full = 225 с, T_zero = 540 с)

| score | q_score | за 60 с | за 225 с | за 380 с | за 540 с и дольше |
|---|---|---|---|---|---|
| 1000 | 1100 | 1100 | 1100 | 1026 | 950 |
| 800 | 1050 | 1050 | 1050 | 1000 | 950 |
| 400 | 950 | 950 | 950 | 950 | 950 |
| 0 | 850 | 850 | 850 | 850 | 850 (B) / 950 (C) |

Полный цикл (культивация + посев + уборка) вручную в срок и идеально: ≈ ×1,34 урожая к автопилоту и −15 % времени роста
(как и решено ранее). Медленный цикл → ровно автопилот.

## 3. Варианты

- **A. Только срок.** `FIELD_RUN_TTL` 900 → 1800, формула качества та же. Просто и безопасно, но не выполняет «зависимость
  от времени»: ехать можно сколько угодно.
- **B. Срок + время в бонусе (рекомендую).** Формула из раздела 2: бонус над автопилотом умножается на `f(t)`, плохая езда
  по-прежнему даёт меньше автопилота (штраф за небрежность остаётся).
- **C. B без риска.** То же, но качество вручную не ниже автопилота (`q = 950 + max(0, bonus)·f/1000`). Ручная игра становится
  чистым плюсом: «сам справился — не хуже автопилота». Цена: исчезает штраф за небрежную езду (при score 0 цикл вручную был бы ×0,80 от автопилота, станет ×1,00),
  решение п. 3 меняется — нужен ваш явный ответ.

Параметры в B/C (для подстройки при прогоне этапа 17): `run_full_k` (250), `run_zero_k` (600), `run_ttl` (1800).

## 4. Совместимость со старыми заходами

- Заход получает метку `qrule = 2` **при создании** (`field_start`). Заходы без метки (открытые до выкладки, `expires_at`
  = старт + 900) завершаются по старой формуле без времени — их награда не меняется. Состояние фермы не мигрируем,
  `schema_version` не трогаем (метка добавляется в `run`, `validate` её не требует).
- Срок старых заходов остаётся 900 (`expires_at` уже записан); новые получают `FIELD_RUN_TTL`.
- Автопилот (путь `null`) и закрытие по сроку считаются как раньше (q = 950).
