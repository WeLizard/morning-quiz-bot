# Telegram API: предложения для игр

Дата исследования: **2026-11-16**. Статус: **предложения для выбора владельцем**.
Исследование и сохранение разрешены; внедрение не согласовано. Приоритеты ниже —
рекомендация, не очередь реализации. Код, зависимости, настройки бота и контуры
развёртывания этим документом не меняются.

## Основания и границы

Официальная документация на дату проверки описывает Bot API **10.4 от 2026-11-09**.
Ephemeral появились в 10.2, персональная замена карточки — в 10.3; 10.4 расширяет
ответы на callback без явного получателя. Это возможности платформы Telegram,
не подтверждение поддержки нашим приложением. [История API](https://core.telegram.org/bots/api-changelog).

Срез dev: `main`, HEAD `bde8342`, с многочисленными чужими изменениями и
неотслеживаемыми файлами. Источники ниже прочитаны из рабочего дерева; это не
состав принятого релиза. [STATUS](../../STATUS.md) и старые отчёты местами отстают:
например, `application/night_case.py` уже существует, хотя обзор говорит об отсутствии кода.
Статусы задач этим исследованием не меняются.

В [каталоге](../../../application/game_catalog.py) есть Classic, Photo, Night,
Atlas и Farm. Клиент использует название Алхимия, `/app/alchemy` и
`/api/mini/alchemy`; ресурс `alchemy.webp` связан с `host-atlas.webp` в
[web/mini_app.py](../../../web/mini_app.py). Здесь Atlas/Алхимия рассматриваются
вместе; согласование окончательного названия — отдельное продуктовое решение.
Mafia и `night_case` имеют разные сервисы и не считаются одним идентификатором игры.

## Проверенные возможности Telegram

| Возможность | Где применима и что ограничивает |
| --- | --- |
| Ephemeral и приватные команды | Личные взаимодействия на общей ленте. Доставка не гарантирована, сообщение может исчезнуть. Ответ по действию — за 15 секунд; инициативная отправка участнику группы требует прав администратора. [Условия](https://core.telegram.org/bots/api#ephemeral-messages-and-commands) |
| Персональная замена исходной карточки | `replace_callback_query_message` меняет представление только нажавшему. Для callback из уже ephemeral-карточки нужны методы `editEphemeralMessage…`; `answerCallbackQuery` всё равно обязателен. [Параметры](https://core.telegram.org/bots/api#ephemeralmessageparameters) |
| Новые опросы | Перемешивание, скрытые до закрытия итоги, несколько правильных ответов, медиа. Это не меняет автоматически наши правила очков. [sendPoll](https://core.telegram.org/bots/api#sendpoll) |
| Rich Messages | Структурированные карточки с таблицами, раскрывающимися разделами, медиа и кнопками. [Формат](https://core.telegram.org/bots/features#rich-messages) |
| HTML widgets | В обычном Telegram пока **только личка с ботом**; группы, inline и пересылки — **только test server Telegram**. Наша rehearsal-песочница сама по себе не является этим test server. [Доступность](https://core.telegram.org/bots/widgets#availability) |
| Mini App | Fullscreen/safe areas, haptics, ориентация и датчики; DeviceStorage/SecureStorage, sharing, ярлык на домашнем экране. Проверять поддержку каждого метода. [API Mini Apps](https://core.telegram.org/bots/webapps) |

Виджет ограничен: HTML 32 КБ / 4 КБ после сжатия, без сети и клавиатурного ввода;
запрос 64 байта, ответ 1024 байта, срок ответа 15 секунд. `chat_data` в группе
общие; у shared widget `public_data` общие для его показов, а пересылка static
widget получает снимок состояния. `viewer.id` не защищает общий
payload. Персональный ответ получает запросивший экземпляр, но он не обновляет
состояние сообщения. Роли и закрытые улики предлагаем выдавать через ephemeral
или авторизованный кабинет. [Устройство и лимиты](https://core.telegram.org/bots/widgets).

Guest Mode позволяет вызвать бота без добавления в чат, но даёт только контекст
вызова и один ответ, без истории и состава чата. Это кандидат для приглашения
или справки, не самостоятельный ведущий длительной партии.
[Guest Mode](https://core.telegram.org/bots/features#guest-bots).

## Предложения по режимам

P1 — наибольшая ожидаемая польза; P2 — следующий эксперимент; P3 — необязательная
идея. Все пункты ниже **не утверждены**. Для каждого сначала выбираются правила,
потом проектируется и проверяется отдельный законченный сценарий.

### Classic

| ID | Предложение и польза | Что решить / проверить до внедрения |
| --- | --- | --- |
| C1 · P1 | По общей кнопке «Мой ответ» открывать личную квитанцию: принят ли ответ, какой выбран вариант. Меньше вопросов к ведущему. | До закрытия не раскрывать правильность; параллельный ответ и дедлайн, повтор запроса, общий счёт браузера и Telegram. |
| C2 · P1 | Отдельный вариант игры со скрытыми промежуточными результатами. | Когда показывать итоги; не обещать запрет обмена ответами между игроками. |
| C3 · P2 | Медиа-раунды и вопросы с несколькими правильными ответами. | Новый контент, полное/частичное начисление, отдельная версия правил; исторический рейтинг не пересчитывать автоматически. |
| C4 · P2 | Серверное перемешивание вариантов вместо дополнительного локального. | Сейчас уже есть локальное перемешивание; исключить двойную обработку, сопоставлять устойчивые ID вариантов, не только позиции. |
| C5 · P2 | «Вопрос дня» с вечерним итогом и личным разбором. | Часовой пояс, поздние ответы и восстановление; не раскрывать решение раньше дедлайна. |

Основание: [существующий roadmap](../../TELEGRAM_QUIZ_ROADMAP.md),
[Classic service](../../../application/classic.py).

## Общие предложения для платформы

- **G1 · P1:** единый способ открыть персональную карточку из разных игр; одинаковые
  состояния «принято», «уже выполнено», «фаза завершилась» и повторный просмотр.
- **G2 · P2:** добровольная отправка итогов/достижений через `shareMessage`;
  `requestChat` — только если потребуется выбор связанного чата, не как выдача прав на комнату.
- **G3 · P2:** ярлык приложения и восстановление последнего разрешённого экрана;
  ссылка несёт идентификатор, а не право доступа или секретную роль.
- **G4 · P3:** Guest Mode для краткого знакомства с игрой и приглашения в комнату.
  Не подменять им уведомления и полный lifecycle партии.
- **G5 · P3:** темы в личке по активным партиям, чтобы не смешивать напоминания,
  результаты и поддержку. Нужна проверка настройки тем в BotFather.

Fullscreen/storage/sharing/датчики существуют в разных версиях API, часть — с
2024–2025 годов; они включены за полезность, а не названы новинками ноября.
Локальный cache не доказывает результат и не является backup. Возможности Mini App
проверяются по поддержке; сервер доверяет только проверенному `initData`.
[Документация Mini Apps](https://core.telegram.org/bots/webapps).

## Виджеты в чате: план по играм (2026-11-19)

Владелец хочет подключить HTML-виджеты к большинству игр. Ограничение production
на 2026-11-19: виджет отправляется **только в личку с ботом** и не пересылается.
Группы, inline и пересылки работают только на test server Telegram. Поэтому
сначала идут личные карточки игрока. Общие доски в группе (живой счёт Classic,
стол Мафии) готовятся на test server и включаются, когда Telegram откроет группы.

Что умеет виджет: HTML до 32 КБ (4 КБ после zlib), без сети и клавиатуры;
кнопки, canvas, анимации, haptics. Состояние до 1024 байт пишет только бот.
Запрос к боту — до 64 байт, ответ — до 1024 байт за 15 секунд. В личке виджет
сам обновляется, когда появляется на экране (не чаще раза в 5 секунд). Большие
экраны остаются в Mini App: кнопка виджета открывает нужный экран по `startapp`.

| ID | Игра | Карточка в личке | Действия из виджета | Риск / что решить |
| --- | --- | --- | --- | --- |
| W1 · P1 | Ферма | Готовые грядки, таймер до урожая, заказ трактира | «Собрать всё», «Сдать заказ», «Открыть ферму» | Повтор не даёт второй урожай; сервис фермы сейчас активно правится |
| W2 · P1 | Classic | «Вопрос дня» целиком в виджете: варианты кнопками | Ответ запросом, итог и разбор после дедлайна | Отдельный учёт очков от группового квиза; часовой пояс |
| W3 · P1 | Мафия | «Моя роль»: роль, фаза, разрешённые цели | Ночное действие кнопкой, квитанция | Чат-состояние видно только в личке; старые кнопки после смены фазы |
| W4 · P2 | Алхимия | Экспедиция: состояние, таймер, находка | «Забрать», «Открыть Алхимию» | Не выносить таблицу рецептов; один save с Mini App |
| W5 · P2 | Ночной город | Досье: хронология и свои улики | Подгрузка записей ответом бота, «Продолжить» | 1024 байт на ответ — досье листается частями |
| W6 · P2 | Мини-игры фермы | Дом Филиныча: вопрос и варианты; Пирог/Баллиста — тренировка | Ответ; тренировка без награды | Награда только через проверяемый replay в Mini App |
| W7 · P3 | Фото-загадки | Мои попытки и подсказки по раунду | Взять подсказку | Списание подсказки при недоставке |

Общая основа для всех карточек (делается один раз вместе с пилотом):
выдача карточки по согласию (кнопка в Mini App или команда в личке), хранение
`(игрок, игра) → message_id, ревизия` в PostgreSQL для обновлений, объединение
частых правок (`editMessageWidgetData` расходует лимит отправки сообщений),
единые ответы `ok` / `already` / `phase_over` / `unavailable`.

Предлагаемый пилот — **W1 Ферма**: самая частая игра с возвратом, все данные
личные. Альтернатива с меньшим риском пересечения правок — **W2 Вопрос дня**.

## Состояние адаптера (2026-11-19)

PTB 22.8 остаётся последней версией на PyPI и нативно знает Bot API 10.0.
Возможности 10.1–10.4 подключены без форка через `api_kwargs` и
`Bot.do_api_request`: [modules/telegram_api_ext.py](../../../modules/telegram_api_ext.py)
(ephemeral, отключённые кнопки, приватные команды, `allowed_updates`) и
[modules/telegram_widgets.py](../../../modules/telegram_widgets.py) (лимиты, отправка,
состояние, ответы, `WidgetQueryHandler`). Polling принимает `widget_query` и
`shared_widget_query`; модерация проверяет и их. Игры эти слои пока не используют:
поведение бота не изменилось. Rich Messages, Guest Mode и кошелёк в адаптер не
вошли, пока для них нет выбранного сценария.

## До выбора реализации

В [requirements](../../../requirements.txt) закреплён PTB 22.8. Его
[stable-документация](https://docs.python-telegram-bot.org/en/stable/#telegram-api-support)
обещает нативный Bot API 10.0, не весь 10.4. Новые методы идут через адаптер выше;
обновление номера зависимости не равно поддержке возможностей.

Для будущей оценки адаптера: учитывать сериализацию новых полей и фильтр
`allowed_updates`, не только исходящие методы. Эфемерные идентификаторы не должны
становиться ID игровых команд. Браузерный ответ не имитируется как голос
пользователя в Telegram poll; оба интерфейса используют общий серверный учёт,
а отличие отображения явно объясняется игроку.

Предлагаемые критерии для каждого выбранного пункта:

1. Владелец выбирает сценарий, правила очков, круг видимости и приоритет.
2. Проверяются текущий общий сервис, серверные права и минимально нужные права бота.
3. Два игрока с разными ролями видят только свои данные; старый callback, повтор,
   гонка с дедлайном и второй клиент не дублируют действие/награду.
4. Возврат после перезапуска и недоставки восстанавливает состояние из PostgreSQL.
5. Проверяется эквивалентный браузерный путь, без обязательного Telegram-чата.
6. Отдельный тестовый бот и реальные Desktop/Android/iOS: версии и наблюдения;
   неподдержанный клиент получает понятный запасной путь.

Проверки настоящих Telegram-клиентов и live API-вызовы в этом исследовании не
проводились. Обновления production, запуск бота, изменение настроек BotFather и
выкладка в rehearsal не выполнялись. Документ не является разрешением на них.

Feedback песочницы в этой сессии прочитать не удалось: `serverold` не разрешился
в использованном SSH-маршруте; прямое подключение по LAN IP прошло, но выбранный
путь `sudo -n -u postgres` вернул `unknown user postgres`. SELECT не выполнился;
очередь не объявляется пустой. Это ограничение проверки доступа, не заключение
об отсутствии PostgreSQL или feedback на сервере.
