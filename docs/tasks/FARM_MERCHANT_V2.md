# Сорока-коробейница v2: 30 товаров, свой набор у каждой фермы, редкость, подвоз

Статус: **серверная механика разделов 2–4 реализована и локально проверена (2026-10-29), на существующих товарах.** Новые товары раздела 1,
клиентские пометки и таймер, визуальная приёмка и выкладка остаются отдельными шагами. Запрос: игрок за один заход скупил всё
у Сороки; решение владельца — расширить ассортимент до 30 позиций, у каждой фермы свой набор, редкость товаров,
подвоз в середине визита. Позже (отдельная задача) — обмен и продажа коллекционных вещей между игроками.

Исходная механика в `qw_farm/merchant.py`: визиты 2 раза в неделю по 24 ч + ярмарки, 6 мест, общий для всех сток
из дня визита и лимиты товаров по видам. Данные берутся из `qw_farm/catalog.py` (`EXOTIC_CROPS`, `DYE_ROWS`, `SCROLL_RECIPES`, `CURIO_SERIES`,
`ORCHARD_ROWS`, `MERCHANT`), принципы `FARM_ECONOMY_AUDIT.md` §1 пп. 4–5 и навык `mqb-feature` («новый видимый
объект — сразу с рисунком»).

## 1. Ассортимент: 30 позиций

| Вид | Сейчас | v2 | Новое |
|---|---|---|---|
| Заморские семена | 6 | 6 | — |
| Красители | 3 | 6 | ореховый (коричневый), сиреневый, изумрудный — с рецептами крашения полотна |
| Свитки рецептов | 3 | 6 | три новых рецепта (заморская выпечка/напитки из уже существующих продуктов) |
| Садовое (прививки, талон) | 3 | 5 | прививки «Слива-венгерка», «Вишня-шпанка» (новый вид дерева, как у яблони и груши) |
| Диковинки сезона | 4 из серии | 4 | — |
| Диковинка из прошлого сезона | — | 1 | «лот дня»: случайная диковинка прошлых серий, которой у фермы ещё нет |
| Странные штуки | — | 2 | коллекционный декор без пользы (две серии по одной в сезон), только у Сороки |

Итого 30. Каждый новый видимый предмет — вместе с рисунком (сцена, миниатюра, значок) по навыку `mqb-feature`.

## 2. Редкость

| Редкость | Что | Шанс места |
|---|---|---|
| Обычная | семена, красители | высокий |
| Необычная | свитки, садовое | средний |
| Редкая | диковинки сезона, странные штуки | низкий |
| Лот дня | диковинка прошлого сезона | ~1 визит из 4 |

Цены — прежняя формула `ceil(k · income_ref(уровень) / 100)`, лимиты по видам прежние.

## 3. Свой набор у каждой фермы

- Набор визита — `HMAC(секрет_сервера, ферма : визит : половина)` → выбор позиций по весам редкости; предсказать
  или перебрать заранее нельзя (секрет как у редкого урожая, `FARM_RARE_HARVEST.md` §2.4).
- 6 мест: место 0 — дешёвый пакет новичка (как сейчас), 5 мест по весам; одинаковые позиции в одном наборе не
  повторяются; «ничего из прошлого визита» — сохраняется, пока пул позволяет.
- Сток вычисляется на лету; цены и полные карточки товаров не сохраняются. `farm['merchant']['bought']` по номерам
  мест сохраняется для совместимости. Для v2 нужны служебные данные визита: исходная коллекция, покупки по id товара,
  выкупленные места первой половины и история предложенных id. Без них покупка «лота дня» меняла бы пул, а подвоз —
  смысл прежнего счётчика места. Проекция остаётся чистой; служебные данные сохраняются вместе с командой.

## 4. Подвоз в середине визита

- Через 12 часов от открытия визита 3 места из 5 (не купленные целиком) заменяются новыми по тому же правилу
  с половиной `2`. Кто заглянет к Сороке дважды за визит, увидит больше — по принципу «ручная игра выгоднее».
- Купленное не пропадает; лимиты по видам — на весь визит.

## 5. Позже: обмен и продажа коллекционных вещей

Отдельная задача (решение владельца — «потом»): диковинки и странные штуки — коллекционные, сейчас `bound`. Позже —
обмен и продажа между игроками (как у коллекционеров), через существующие механизмы соседей/лавки или отдельную
биржу коллекций; со своей защитой от абузов (вторые аккаунты). Сюда же — витрина коллекции и достижения.

## 6. Порядок

1. Механика: свой набор (HMAC), редкость, подвоз, лот дня; тесты детерминизма и честности (Sonnet).
2. Новые товары: 3 красителя с рецептами, 3 свитка, 2 прививки, 2 странные штуки — рисунки Opus, механика Sonnet.
3. Превью владельцу, гейт, предпроверка ферм, песочница.

## Серверный контракт механики v2 (2026-10-29)

- `MERCHANT.rarity_weights`: обычная / необычная / редкая — **60 / 30 / 10**. Сначала выбирается доступная категория,
  затем товар внутри неё. После исключения повторов веса доступных категорий нормируются заново; это не квоты в каждом наборе.
  `rarity_by_kind` задаёт категорию вида товара; строки существующих каталогов автоматически попадают в пул.
  Новых id товаров в этом этапе нет. Дешёвые семена зарезервированы для места 0.
- «Лот дня» — один бросок с шансом **25% на визит**, одно из мест 1–5, только отсутствующая в коллекции диковинка
  другой сезонной серии. «Прошлые» здесь — остальные четыре серии циклического каталога; текущая исключена. Если их коллекция полна,
  специального лота нет. Подвоз не делает второй бросок.
- Через 12 часов меняются до трёх не выкупленных мест 1–5; если таких мест меньше, меняются только они.
  Купленные товары, коллекция и открытые рецепты сохраняются. `MERCHANT.limits` по-прежнему задаёт лимит каждого
  товара данного вида, а не общий бюджет всей категории; покупки по id учитываются за обе половины визита.
- Поле `stock_v2` хранит `owned`, `previous`, `purchased`, `first_full`. Снимок исходной коллекции не меняется после
  покупки «лота дня»; покупки после подвоза не переставляют места. Чтение проекции не сохраняет и не меняет ферму.
- Сохранённый текущий `merchant.visit_id` **без `stock_v2`** — старый визит: прежний набор, прежние номера `bought`,
  без подвоза до его конца. Следующий визит — v2. Старая ферма без покупок/продаж в текущем визите сразу получает v2:
  у неё нет счётчиков мест, которые нужно переносить. `validate_state` принимает старую и новую формы без смены версии схемы.
- Скупка, расписание и отдельные ярмарочные товары сохранены. Склад, монеты и игровые данные не мигрируются.

### Настройка сервера при будущей выкладке

Добавить **`QW_FARM_MERCHANT_SECRET`**: одно постоянное случайное значение длиной не менее 32 символов
(например, 64 шестнадцатеричных символа из генератора секретов), одинаковое у всех процессов API. Хранить вне Git.
Если переменная не задана, ключ выводится через HMAC с отдельной меткой назначения из постоянного
`QW_FARM_INVITE_SECRET`, затем из `BOT_TOKEN` (также минимум 32 символа). Секрет процесса из `sharing.py` здесь
не используется. Если постоянного секрета нет или выбранный секрет слишком короткий, расчёт v2 выдаёт явную
ошибку настройки: публичного или случайного временного ключа нет. Не менять ключ и источник ключа посреди визита;
перезапуск с прежними настройками сохраняет ассортимент. Значение ключа и HMAC не попадают в проекцию.

### Контракт для параллельной клиентской работы

`qw_farm/static/merchant.js` в этом этапе не меняется.

- В `merchant_view.next_restock_at` приходит Unix timestamp следующего подвоза; после подвоза, вне визита и для
  старого визита — `null`. Показывать оставшееся время по серверным часам рядом со сроком ухода Сороки.
- У места `rarity`: `common`, `uncommon`, `rare`, `lot_day`. Отображать «Обычная», «Необычная», «Редкая», «Лот дня».
- `visit_id` остаётся непрозрачным токеном команды: `v<день>:h1` и `v<день>:h2` для половин v2;
  `base_visit_id` и внутреннее сохранение по-прежнему используют `v<день>`. Прежний токен покупки после подвоза
  или с открытого до выкладки экрана получает `stale_visit` без списания денег, чтобы клик на прежнюю карточку
  не купил её замену. Сохранённый старый визит продолжает принимать `v<день>`. Скупка принимает и базовый токен визита.
  Текущий клиент уже передаёт токен без разбора, опрашивает сервер каждые 15 секунд и обновляется после ошибки.
- В `app.js:syncMerchantFlag` ключ уведомления о приезде следует брать из `base_visit_id`, сохранив `visit_id`
  для команд: иначе смена половины вызовет повторное «Сорока приехала на рынок!».
- Для нового таймера и пометок остаются клиентская реализация и отдельная визуальная проверка по `UI_RULES`.
- Анонс следующего визита нейтральный: текущие покупки ещё могут изменить следующий набор, поэтому конкретный
  товар заранее не обещается. Общая проекция расписания не выдаёт персональные места.
