# Классический бот: улучшение поведения и новые возможности Telegram

Проверено 2026-08-30. Часть [MQB-001](tasks/MQB-001-postgresql-and-mini-app-foundation.md).
Базовая модернизация классического квиза реализована и проверена локально.
Новые игровые форматы ниже — предложения, они ещё не включены.

## Цель

Сохранить существующие возможности чата и накопленные результаты, улучшив
читаемость вопросов, управление игрой, темп, обратную связь и устойчивость.
Новые API применять там, где есть понятная польза игрокам. Новые игровые режимы
включать после выбора правил и проверки совместимости, без скрытого изменения
исторических очков и правил классического режима.

## Проверенные версии

- Официальная документация Telegram на дату проверки описывает Bot API 10.3
  от 2026-08-24. Это версия API, а не установленной Python-библиотеки.
  [Telegram changelog](https://core.telegram.org/bots/api-changelog#august-24-2026).
- Stable-документация `python-telegram-bot` показывает 22.8; её changelog
  подтверждает поддержку Bot API 9.6 и 10.0. Новые поля ответов требуют
  обновления тестовых fixtures, а старый аргумент `correct_option_id` оставлен
  для совместимости и объявлен устаревающим.
  [PTB changelog](https://docs.python-telegram-bot.org/en/stable/changelog.html).
- В отдельной `.venv-local` установлен и проверен PTB **22.8** (релиз
  подтверждён [PyPI](https://pypi.org/project/python-telegram-bot/)).
  Версия закреплена в manifests и полном локальном lockfile.
  Глобальный Python с PTB 21.7 не изменён; серверная версия не проверялась.
- PowerShell-скрипты по умолчанию используют `.venv-local`, не глобальный Python.
  [Подготовка и запуск](LOCAL_MILESTONE.md). Lockfile проверен на Windows/Python
  3.13; другой Python/ОС требует собственной проверки совместимости.

## Что реализовано локально

- `quiz_payload.py`: plain text без Markdown-экранирования. Условие до 300
  символов сохраняется целиком; сначала убирается категория, затем заголовок.
  Варианты до 100 символов не обрезаются. Невалидный вопрос не отправляется,
  исходный банк не исправляется автоматически. Прежние конфигурационные лимиты
  280/90 не используются для разрушительной обрезки.
- Локальное перемешивание пар «исходный индекс + ответ» сохраняет верный вариант.
  Контракт классики остаётся 2–10 вариантов и ровно один правильный:
  `correct_option_ids=[index]`, без повторного/множественного голосования
  и без дополнительного серверного перемешивания.
- Реальный PTB `ExtBot` с глобальным MarkdownV2-default проверен через
  перехват сериализованного запроса. У question/options parse mode явно выключен.
- `option_persistent_ids` и число вариантов сохраняются в PG checkpoint.
  Ответы с несовпадающей идентичностью/индексом игнорируются, а не считаются
  неправильными. Старые checkpoints без ID сохраняют индексный режим.
  Голос без пользователя, отзыв голоса и повтор не портят счёт;
  кеш ответа заполняется только после успешной работы хранилища.
- `solution`, а при его отсутствии `explanation` из редактора, публикуются
  после завершения вопроса. Пустое сообщение «💡» больше не создаётся.
  Старый placeholder можно отредактировать: отдельная отправка разрешена
  только после явного «message to edit not found»; «not modified» — успех.
- До публикации пояснения PG сохраняет `solution_delivery=sending`.
  После timeout/рестарта неподтверждённая отправка не повторяется.
  Успех сохраняет message ID и попадает в прежнюю очередь удаления.
  Пояснения длиннее одного сообщения явно помечаются как сокращённые,
  источник остаётся целым.
- Общий `telegram_transport.py`: повтор после явного 429 — максимум два раза,
  суммарное ожидание RetryAfter до 30 секунд, с поддержкой числа/timedelta.
  `BadRequest` не перепутан с сетевой ошибкой. Неопределённый результат
  `sendPoll/sendMessage` не вызывает слепой повтор даже в JSON-режиме.
  После ожидания доступность текущей игры перепроверяется перед опросом/разбором.
  Отдельный rate limiter опросов сохраняется.
- Длинный plain text делится без потери символов, каждая часть повторяется
  отдельно только после явного отказа. Rich text свыше 4096 символов отклоняется
  до отправки (произвольная нарезка ломает entities). Итоги используют прежний
  компактный plain-text fallback только при подтверждённой ошибке содержания,
  а не при timeout. Из личного поздравления убраны лишние getMe/getChat.

Гарантия доставки — **не exactly-once**: Telegram не даёт здесь idempotency key.
После неопределённой отправки возможен пропуск сообщения или потеря его ID для
очистки, но автоматическое создание дубликата запрещено.
`PartialDeliveryError.messages` содержит подтверждённые части длинного текста;
старый интерфейс успешной отправки возвращает только первое сообщение.
Полный учёт/удаление всех частей во всех legacy-caller'ах остаётся отдельной работой.
Длительность игры, правила очков и существующий рейтинг не менялись.

## Подтверждённые возможности и идеи

API 9.6 добавил несколько верных ответов, перемешивание, скрытие результатов
до закрытия, повторное голосование и более длительные опросы; также изменил
контракт правильных вариантов на `correct_option_ids`.
[Изменения опросов](https://core.telegram.org/bots/api-changelog#april-3-2026).

| Возможность | Предлагаемое применение | Ограничение проекта |
| --- | --- | --- |
| Медиа в вопросе, вариантах и объяснении | «Угадай фильм по кадру», музыкальный раунд, выбор картинки. [Poll media](https://core.telegram.org/bots/api#inputpollmedia) | Типы медиа различаются по месту вложения; существующий фото-квиз не заменяем автоматически. |
| Несколько правильных вариантов | «Выбери все верные утверждения». | Сначала согласовать полное/частичное начисление и подготовить контент. |
| Скрытые результаты, перемешивание | Турнир с объявлением результатов в конце. | Не обещать защиту от пересылки ответов; проверить соответствие вариантов пришедшим голосам. |
| Длительный опрос | «Вопрос дня» с вечерним итогом. | Согласовать дедлайн, поздние ответы и восстановление после рестарта. |
| Персональные сообщения внутри группы | Подсказка ведущего или личный результат без засорения общего чата. [Ephemeral messages](https://core.telegram.org/bots/api#ephemeral-messages-and-commands) | Обычный бот отвечает на допустимое действие за 15 секунд; свободная отправка требует прав администратора. Доставка не гарантирована. |

Идеи в правой части таблицы — проектные предложения, а не готовые игровые
механики Telegram. Для ephemeral и других возможностей новее покрытия SDK
проверить адаптер/поддержку отдельно; не считать обновление PTB достаточным.
Подсказка не должна исчезать из учёта расходов только из-за недоставки сообщения.
Нужен повторный просмотр личного результата через обычное меню или Mini App.

Предлагаемый порядок игровых экспериментов: медиа-раунд и компактный разбор,
затем режим скрытых результатов; несколько верных ответов и персональные
подсказки — после утверждения правил и проверки клиента/SDK.
Не включать все режимы сразу и не менять обычный рейтинг без отдельного решения.

## Обязательные улучшения текущего поведения

1. Читаемые вопросы и ответы без артефактов экранирования; длинный вопрос не
   теряет существенную часть условия. Различимые варианты после форматирования.
2. Ясные состояния запуска, ожидания, остановки и завершения. Повторное нажатие
   не запускает вторую сессию; устаревшие кнопки дают понятный ответ.
3. Быстрое подтверждение callback и последовательное изменение состояния одной
   игры при конкурентных updates, без блокирования других чатов.
4. Компактный разбор и финальный результат, меньше дублирующих сообщений.
   Важные достижения остаются доступны; тихая подача не скрывает ошибки.
5. Единая политика ошибок: 429, запрет отправки, удалённое сообщение,
   недоступные ЛС и сетевой сбой не ломают игру или начисление.
6. После таймаута отправки результат может быть неизвестен. Повторный
   `send_poll` нельзя считать безопасным только потому, что проверяется уже
   полученный poll id: новый poll может иметь другой id. Требуются явное
   состояние неопределённой отправки и проверяемая политика восстановления.
7. Новые режимы хранят тип вопроса, выбранные варианты и версию правил отдельно;
   старые одиночные вопросы и исторические результаты остаются совместимыми.
