# MQB-003 — Mini App, меню и настройки Telegram

- **Статус:** `in_progress`
- **Приоритет:** high
- **Создана:** 2026-08-31
- **Обновлена:** 2026-08-31
- **Ответственный:** разработка dev-копии
- **Связанные ADR:** [ADR-007](../decisions/ADR-007-mini-app-user-api.md)

## Цель

Дать игроку выбор: играть и пользоваться функциями бота через Telegram или
полноценный Mini App. Это два интерфейса одного продукта, с общими правилами,
прогрессом и доступными по роли настройками; не только кабинет профиля.

## Контекст

Пользователь запросил именно Telegram App и улучшение существующих меню,
настроек и интеграции с Telegram API. Восстановление старого функционала в PG
само по себе не закрывает эту задачу. Разработка и запуск разрешены только
на локальной dev-копии и отдельном тестовом боте, в разрешённой личке.

## Входит в задачу

- Общая навигация для обработчиков бота, симулятора и private test runner.
- Компактные настройки с текущими значениями, возвратом на главную и защитой
  от устаревших кнопок. Существующие опции и права доступа сохраняются.
- Mini App: профиль, режимы, Telegram-тема, safe areas, BackButton,
  SettingsButton, настройка виброотклика и явный полноэкранный режим.
- Переходы к игре/настройкам через deep links при известном username бота;
  копирование команды в локальном просмотре и для группового контекста.
- Изолированный HTTPS test backend с проверкой Telegram initData и доступом
  только одному разрешённому пользователю. Не включает админку или dev-login.
- Проверка пользовательского сценария в настоящем Telegram после публикации.

## Не входит в задачу

- Production, его данные, процессы, настройки BotFather и публикация админки.
- Новые правила начисления и мафия. Исключение игры внутри Mini App из прежней
  редакции отменено прямым уточнением пользователя 2026-08-31.
- Массовые рассылки и групповые live-тесты без отдельного разрешения.
- Утверждение, что весь Telegram API проекта уже модернизирован.

## План реализации

1. Общие карточки меню и штатные ConversationHandler entry points.
2. Подключённый Mini App и Telegram SDK, без сохранения авторизации в localStorage.
3. Изолированный test backend и явное согласование HTTPS-публикации.
4. Автотесты, обновление живого dev, затем проверка Desktop/Android/iOS.

## Риски и откат

- Публичный endpoint требует отдельного разрешения. Подготовленный launcher
  сам не публикует tunnel и слушает только loopback 4187.
- Local preview 4185 имеет явный dev-login: публиковать его нельзя.
- HTTPS-тест разрешает только одного пользователя и его личный чат; групповой
  доступ закрыт. Proxy trust ограничен loopback; ingress проверяется при подключении.
- Остановка test runner и Mini App не удаляет dev-БД. Миграций/сброса данных
  этот этап не добавляет. Чатовые команды остаются доступны без Mini App URL.

## Открытые решения

Разрешение на временный HTTPS ingress получено 2026-08-31; ссылка подключена,
кнопка подтверждена обратным чтением Telegram API и доставлена в личку.
Остаётся настоящий пользовательский вход и проверка Telegram-клиентов;
задачу не считать закрытой по одним автономным тестам.
[Запуск, проверки и остановка](../TELEGRAM_MINI_APP_TEST.md).
