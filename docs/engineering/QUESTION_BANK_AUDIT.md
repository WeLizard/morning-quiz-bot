# Безопасный аудит банка вопросов

Скрипт `scripts/audit_question_bank.py` только читает данные и формирует отчёт.
Он не редактирует seed, не импортирует изменения и не запускает миграции.

Обычный запуск проверяет все JSON-файлы вопросов:

```powershell
python scripts/audit_question_bank.py
```

По умолчанию отчёты сохраняются в `.local/acceptance/question-bank-audit.json`
и `.local/acceptance/question-bank-audit.md`. Скрипт проверяет схему записей,
невалидные/повторяющиеся варианты, управляющие символы и точные дубли вопроса
после нормализации регистра, Unicode и пунктуации. Дубли — предупреждения для
редакторского решения, не автоматическое удаление.

Сверка с авторитетным PostgreSQL включается отдельно и принимает только
`TEST_DATABASE_URL`; `DATABASE_URL` не рассматривается намеренно. Дополнительно
разрешён только локальный endpoint `127.0.0.1:55433` (с хоста) или `postgres:5432`
(из dev-контейнера), база `morning_quiz_test`, пользователь `mqb_dev`:

```powershell
$env:TEST_DATABASE_URL = 'postgresql+asyncpg://.../morning_quiz_test'
python scripts/audit_question_bank.py --postgres
```

В этом режиме сравниваются наборы категорий, содержимое/ревизии PG-категорий,
валидность и дубли в обеих копиях. Сравнение по content hash показывает, где
текущая БД отличается от seed. Код не выбирает автоматически, какую версию
считать правильной. Доступ к PostgreSQL — только `SELECT`; отчёт указывает
`differs`, `missing_from_seed` или `missing_from_postgres`.

Ненулевой код возврата означает невалидные записи либо расхождение JSON/PG.
Дубли сами по себе дают отчёт-предупреждение. Любое содержательное исправление
должно пройти редакторскую проверку и применяться через контролируемый импорт
с проверкой версии/историей, а не прямой записью скрипта.
