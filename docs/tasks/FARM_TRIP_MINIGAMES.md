# Мини-игры для рыбалки и лесных вылазок («сам» или «отправить»)

Статус: **дизайн одобрен владельцем 2026-10-15 (по всем вопросам раздела 8 — рекомендации). Реализовано, не закоммичено.**
**2026-10-22: рыбалка переделана в v2 (поклёвка → подсечка → вываживание, редкая рыба, журнал улова) — см. §10; §4 описывает v1.**
Реализация: `qw_farm/trip_games.py` (правила, `trip_play`), `expansion.py` (`start_trip` создаёт `game` для поездки без проводника,
`collect_trip` выдаёт `final_outputs`, `validate`), `service.py` (блок каталога `trip_games`), `static/trip_game.js` (чистые функции +
игры), `app.js` (выбор «сам с игрой / сам без игры / проводник», кнопка «сыграть» в карточке поездки), `style.css`. Тесты:
`tests/test_farm_trip_games.py` (73), `tests/fixtures/farm_trip_games/games.json` + `tests/js/farm_trip_game.test.cjs` (паритет JS↔Python,
153 случая). Проверено в браузере на локальном стенде в памяти: ПК и 375 px, день и ночь, обе игры, ответ сервера принят.
Запрос владельца: у тракторов и комбайнов есть выбор «сам или автопилот» — пусть рыбалка («порыбачу сам») и лесные
вылазки («пойду сам») тоже станут мини-играми, а не просто таймером.

Опирается на: `FARM_R9_DESIGN.md` (решения 2–3: ручная игра даёт ограниченный бонус над автопилотом, сервер проигрывает
ввод), `FARM_FIELD_TIME_QUALITY.md` (время в награде), `FARM_LAKE_FISHING.md` (рыбалка как поездка), код:
`qw_farm/expansion.py` (`start_trip` / `collect_trip` / `abort_trip`), `undo.py` (досрочный возврат), `fields.py` и
`static/tractor_game.js` (образец: серверное проигрывание, чистые функции без DOM, паритет JS↔Python).

## 1. Что есть сейчас

- Поездка = `trips[]` в состоянии фермы (макс. 2 одновременно: «ты» и/или проводники, лес и рыбалка делят места).
  `start_trip {route, guide}` списывает цену и вещи, кладёт `outputs`, `ready_at`; `collect_trip` после `ready_at`
  выдаёт добычу и XP; `abort_trip` — отмена за 60 с или возврат раньше срока (половина пропорционально, без XP).
- В списке «Кто идёт / Кто рыбачит» уже есть пункт **«Пойду сам» / «Порыбачу сам»** — но это просто «без проводника»:
  поездка по таймеру, играть не во что. Проводник: −20 % времени и +1 предмет основной добычи по специальности.
- Сервер и клиент уже умеют «игру с серверным проигрыванием» (поля): случайность из `sha256(seed)`, клиент шлёт только ввод,
  сервер сам считает результат, цифре клиента не верит, просроченный заход закрывает как автопилот.

## 2. Идея

Выбор при отправке:

| путь | что происходит | награда |
|---|---|---|
| **Сам** (мини-игра) | поездка стартует как обычно, сразу открывается короткая игра (30–60 с); время поездки остаётся | добыча × q, q = 1,00…1,25 |
| **Сам, без игры** (автопилот) | как сейчас, без игры; игру можно не открывать, а закрыть окно | добыча как сейчас (q = 1,00) |
| **Проводник** | как сейчас: −20 % времени, +1 предмет по специальности | как сейчас; игры нет |

Автопилот остаётся полноценным путём: никто не обязан играть, базовая добыча и XP не меняются. Игра — необязательный
бонус «молодец, сделал сам». Игра и проводник не складываются (у проводника играет он, не ты).

Ключевое решение: **игра не меняет время поездки и XP**, а только количество добычи. Так проводник (скорость + специальность)
и ручная игра (количество) — разные плюсы, а XP по-прежнему идёт одной воронкой `progression.grant_xp` без нового
источника накрутки.

## 3. Награда (та же модель, что у техники)

```
score   — 0…1000 (‰), считается сервером по записи игры
q       = 1000 + 250·score/1000          # 1000…1250 ‰, без штрафа ниже автопилота (вопрос 2)
outputs = round_half_up(base_qty · q / 1000)   для каждого предмета, не больше base + ceil(base/4)
```

Примеры при q = 1250: 3 карася → 4; 5 окуней → 6; 4 гриба → 5; 8 лисичек → 10; 2 щуки → 3. Средняя игра (score 500, q = 1125):
3 → 3, 4 → 5, 8 → 9. Итого: идеальная игра ≈ +25 %, но в малых числах это обычно +1 предмет — сопоставимо с бонусом проводника
по специальности, а не «двойной улов».

- Все числа целые, без плавающей запятой (как весь `fields.py`).
- Бонус применяется при `collect_trip`; `abort_trip` и досрочный возврат считают от базовой `outputs`, то есть бросить поездку
  ради бонуса нельзя (бонус только за законченную поездку).
- Награда за секреты (`atlas`, `night`) и XP — как у автопилота.
- Окно игры: от старта поездки до её сбора, но не позже `GAME_TTL` (рекомендую 900 с) после старта. Не сыграл в окне — путь
  закрывается как автопилот (q = 1000), как просроченный заход техники. Играть можно один раз (вопрос 4).

## 4. Мини-игра «Порыбачу сам»: заброс, поклёвка, подсечка

Цель: 3 заброса (тихий пруд), 4 (заводь), 5 (речной поворот). Один заброс ≈ 8–12 с. Вся игра — один большой экран-«озеро»,
ввод только по касанию в любом месте (без точного прицеливания пальцем).

1. **Заброс.** По воде ходит кольцо-мишень туда-обратно (период ≈ 1,6 с, фаза от seed); тап «Забросить» останавливает
   поплавок. Точность = расстояние до центра ближней «рыбной зоны» (камыши / глубина / тень; зоны от seed). Три уровня:
   в зоне, рядом, мимо. От точности зависят длина ожидания и ширина окна подсечки.
2. **Поклёвка.** Поплавок качается; через `wait_ms` (1,5…5 с, из seed) он «ныряет» — виден по цвету/кругам/вибрации
   (`navigator.vibrate`, если есть), не только по звуку.
3. **Подсечка.** Тап в окне `window_ms` (900 мс; 700 мс на речном повороте) после нырка. Раньше — рыба спугнута (0 очков),
   позже — сорвалась (0 очков), внутри окна — тем лучше, чем ближе к середине окна.
4. **Итог.** Очки заброса = 0,4·точность + 0,6·подсечка (‰). `score` = среднее по забросам. Показываем уловленных рыб
   и итог «+1 к улову»/«как у автопилота».

Правила только-вверх: промах = 0 очков, но не штраф (q ≥ 1000).

## 5. Мини-игра «Пойду сам»: короткий сбор в лесу

Вид сверху, сетка 6×6 (клетка ≥ 52 px, помещается в 360 px ширины), лесная поляна. Игрок — корзинка, ходит по клеткам;
запас шагов `B` (12 на тропе/опушке, 14 на поляне/лугу, 16 в роще). Управление пальцем: **тап по соседней клетке** =
шаг; тап по дальней = автопроход кратчайшим путём до неё (каждый шаг — отдельный ход записи); есть кнопки-стрелки
и клавиши ←↑→↓/WASD на ПК.

- На клетках лежит добыча маршрута (грибы, ягоды, дрова, травы, орехи — иконки маршрута), «пустые» клетки и несколько
  **ловушек** (мухомор, крапива, гнилой пень): ловушка отнимает 2 шага запаса, но не отнимает уже собранное. Для «Тропы
  Ночного города» ловушек нет.
- Раскладка детерминирована: `sha256(seed, route, label)`. Сначала генерируется эталонный маршрут длиной `B` (случайное
  блуждание), на нём лежит ~60 % добычи; остальная добыча и ловушки — вне эталона. Эталон даёт «потолок» — сколько
  реально можно собрать за запас шагов.
- `score = min(1000, 1000 · собрано_добычи / добыча_на_эталоне)`; повторно ступать на пройденную клетку можно, штрафа нет,
  но шаги тратятся.
- Игра ≈ 30–45 с, без таймера реакции — это игра на планирование маршрута, не на скорость; удобно с телефона одной рукой.

Почему разные механики: рыбалка — спокойное «ловить момент», лес — «выбери путь»; обе сводятся к простому записанному вводу.

## 6. Серверная часть и защита от накруток

Состояние: у поездки без проводника появляется `game = {kind, seed, state: open|done, expires_at, q}`. Старые поездки
без `game` и поездки с проводником работают как раньше; `schema_version` не повышаем (поле необязательное, как `qrule`),
`validate_state` принимает `game` только при `guide == ''`.

Команды (общий `POST /api/farm/v1/commands`, идемпотентность через receipts, как у остальных):
- `start_trip {route, guide}` — без изменений в схеме. Для `guide == ''` сервер сам создаёт `game` (seed = sha256 от id команды и
  маршрута). Клиент по умолчанию открывает игру, но может закрыть её — тогда поездка идёт как автопилот.
- `trip_play {trip, log}` — закрывает игру. `log`: для рыбалки список `[{aim_ms, strike_ms|null}]`, для леса строка из
  `UDLR` (как путь у техники). Ограничения: длина ≤ верхний предел для маршрута, типы строгие, без NaN/отрицательных/нецелых.

Проверка (сервер ничему не верит на слово):
1. Поездка существует, без проводника, `game.state == 'open'`, окно не истекло, `now ≥ started_at + min_time`.
2. Рыбалка: сервер из seed сам получает `wait_ms` и положение мишени в момент `aim_ms`, сам считает точность и окно подсечки;
   `strike_ms` должен быть ≥ `bite_ms` (нельзя подсечь до поклёвки) и ≥ предыдущий момент; предел: `last_ms ≤ (now − started_at)·1000
   + допуск` (нельзя «прожить» больше времени, чем прошло). Минимум человеческой реакции 150 мс — быстрее считается
   сбоем (0 очков за заброс).
3. Лес: сервер проигрывает путь по эталонной раскладке (соседство шагов, границы, запас шагов, ловушки) — тот же приём,
   что `fields._walk`. Минимум времени `0,2 с · длина` с момента старта.
4. `q` считается только сервером; число от клиента игнорируется; `trip_play` выполняется один раз (повторный вызов с тем же
   id команды возвращает прежний ответ, с другим — `already_played`).
5. Бот, который знает seed (он приходит клиенту, как препятствия у техники), в худшем случае получит ровно то, что получает
   идеально играющий человек: **максимум +25 % добычи**, XP не растёт, расход сырья и цена поездки те же. Лимит частоты команд
   — общий `rate_limits.py`; отдельный лимит на размер `log`.
6. Просроченную/ненужную игру закрывает `settle` как автопилот (q = 1000).

## 8. Вопросы владельцу

1. **Что даёт игра:** больше добычи (до +25 %) — рекомендую; сократить время; или и то и другое?
2. **Штраф за плохую игру:** нет (q не ниже автопилота) — рекомендую; или как у техники (до −15 % при полном провале)?
3. **Автопилот для «сам»:** оставить «Сам, без игры» отдельным пунктом (рекомендую) — или «сам» всегда открывает игру?
4. **Попытки:** одна игра на поездку (рекомендую, чтобы нельзя было переигрывать до идеала) или несколько?
5. **Окно игры:** до 15 минут после старта (рекомендую) или пока поездка не будет собрана?
6. **Сколько забросов/шагов:** рыбалка 3/4/5 заброса, лес 12–16 шагов — подходит? Игра ≈ 30–60 с — не слишком длинно/коротко?
7. **Проводник против «сам»:** проводник даёт −20 % времени и +1 по специальности, «сам» — до +25 % добычи. Должен ли

9. **Редкая добыча:** хочешь ли в рыбалке редкую рыбу/лесную находку за идеальную игру (это новый контент и баланс — отдельная задача)?

## 10. Рыбалка v2: поклёвка → подсечка → вываживание (2026-10-22)

Запрос владельца: «Апгрейдить мини-игру рыбалка, доработать её более грамотно». Раздел заменяет §4 для рыбалки;
лес (§5) не меняется. Статус: **реализовано в dev-копии, не закоммичено, в песочницу не выложено** (см. 10.8).

### 10.1 Что было слабым (проверено рендером v1 на 390×844 и 1280×800, день и ночь)

- **Не рыбалка, а ползунок.** Пустой градиент с пятью линиями; «прицел» — серая полоса внизу, поплавок появляется в другом
  месте экрана; нет берега, удочки, рыбы, камышей. Стиль фермы не узнаётся.
- **Два тапа и пустое ожидание.** Заброс по бегущей метке и одна подсечка; 1,5–5 с ожидания без событий. После подсечки
  ничего не происходит: рыба не видна, не борется, нечего «вытащить».
- **Мало мастерства.** Ровно два тайминга; лучшая подсечка — «в середине окна», что противоречит интуиции («подсекай сразу»).
  Ложных поклёвок нет, читать поплавок не нужно.
- **Однообразие.** Пруд, заводь и река отличаются только числом забросов и шириной окна; рыбы одинаковые.
- **Награда абстрактная.** «Оценка 62 % · ×1,15»; что поймано — не показано; коллекции и редкой рыбы нет; время суток и
  погода не влияют; наживку выбрать нельзя.
- **Читаемость.** Подсказки на холсте 14–16 px поверх воды; ночью шкала и поплавок почти сливаются с фоном.

### 10.2 Цикл одного заброса (8–18 с)

1. **Заброс.** По воде бежит кольцо-прицел (период 1,6 с; в ветер 1,25 с). Рыбное место видно: тень и пузыри.
   Тап «Забросить» — поплавок летит туда (0,6 с). Точность `acc` (‰) — как в v1 (мёртвая зона 60, спад 300).
2. **Ожидание и поклёвка.** Поплавок 0–2 раза **подрагивает** (ложные поклёвки, мелкое кольцо) и затем **уходит под
   воду** (всплеск, «Клюёт!», вибрация). Ожидание `wait·wait_pct/100·bait_pct/100 + 2·(1000−acc)` мс: точный заброс —
   быстрее клёв; промах — до +2 с.
3. **Подсечка.** Нажатие в окне `[bite+150, bite+150+window]` мс (пруд 900, заводь 800, река 700). Раньше — рыба спугнута,
   позже — ушла. `timing = 1000 − 500·(d−150)/window`: чем быстрее, тем лучше (1000…500).
4. **Вываживание.** Подсечка — это нажатие; **держи** кнопку (или холст, или пробел) — катушка тянет рыбу, **отпусти** —
   леска отдаётся. Наверху шкала натяжения: зелёная < 600, жёлтая 600–800, красная ≥ 800, обрыв на 1000.
   Провисшая леска (натяжение < 60 дольше 1,2 с) — рыба сходит; рыба утянула леску до 1000 или бой длится > 20 с — ушла.
5. **Итог заброса.** Пойманная рыба показывается крупно: вид и вес («Окунь · 340 г»); редкая — с золотым кантом.

Счёт (‰): поймана → `(3·acc + 3·timing + 4·fight)/10`, `fight = 1000 − min(300, 300·max(0, тики−par)/par)`;
сорвалась после подсечки → `(3·acc + 3·timing)/20`; нет подсечки → 0. `score` = среднее по забросам. Награда как прежде:
`q = 1000 + 250·score/1000` — **максимум +25 % улова поездки**, XP и время поездки не меняются, хуже автопилота не бывает.

### 10.3 Вываживание: целочисленная модель (тик 50 мс, одинакова в Python и JS)

```
eff      = pull·(500 + S/2)/1000                       # рыба устаёт: S 1000 → 0, сила 100 % → 50 %
держишь:  target = 200 + 15·eff;  D −= max(0, 9 − eff/8);  S −= 4
отпустил: target = 5·eff;         D += eff/4;               S −= 1
T += (target − T)/5, если target > T, иначе /6         # натяжение догоняет цель (вниз медленнее)
T ≥ 1000 → обрыв · T < 60 24 тика подряд → сход · D ≤ 0 → поймана · D ≥ 1000 или 400 тиков → ушла
старт: D = 600, T = 450, S = 1000
```

`pull` — график рывков рыбы из плана (24 отрезка `[тиков, сила]`, по кругу). Поведение по видам:

| вид | где | спокойно (сила × тики) | рывок | par | вес, г | «держать всегда» / «по шкале»* |
|---|---|---|---|---|---|---|
| Карась | пруд, заводь | 8–14 × 14–28 | потяжка 36–44 × 6–12 | 90 | 150–450 | 100 % / 100 %, ~4 с |
| Окунь | заводь, река | 10–16 × 6–14 | частые рывки 58–66 × 4–9 | 150 | 120–400 | 73 % / 99 %, ~9 с |
| Щука | река | 8–14 × 16–30 | дрожь 30–32 × 6 → бросок 60–70 × 14–24 | 200 | 900–3200 | 3 % / 95 %, ~10 с |
| Золотой карась (редкая) | пруд | 12–18 × 12–22 | потяжка 54–62 × 8–14 | 160 | 500–1100 | 77 % / 100 % |
| Линь (редкая) | заводь | 18–24 × 12–20 | потяжка 52–60 × 12–18 | 200 | 600–1800 | 76 % / 100 % |
| Сом (редкая) | река | 14–20 × 16–28 | дрожь 32–34 × 8 → бросок 62–72 × 18–28 | 260 | 4000–12000 | 0 % / 85 %, ~13 с |

\* симуляция 200 рыб: «по шкале» = отпускает, когда видит натяжение ≥ 780 с запаздыванием 0,2 с, и снова тянет при ≤ 450.
Щуку и сома нельзя вытащить, просто держа палец: перед броском леска дрожит — это подсказка отпустить.

### 10.4 Места, погода, время суток, наживка, редкая рыба

| место | забросов | окно, мс | обычная рыба | редкая | база редкой |
|---|---|---|---|---|---|
| Тихий пруд | 4 | 900 | карась | золотой карась | 25 ‰ |
| Озёрная заводь | 4 | 800 | окунь 60 %, карась 40 % | линь | 25 ‰ |
| Речной поворот | 4 | 700 | щука 50 %, окунь 50 % | сом | 25 ‰ |

Длительность (измерено ботом на 600 поездках каждого места: заброс с разбросом точности, подсечка через 0,1–0,45 с, вываживание «по шкале»): пруд 29–47 с (медиана 35), заводь 32–61 с (48), река 44–70 с (56). Было 3/4/5 забросов; пруд поднят до 4 (иначе медиана 26 с), река снижена до 4 из-за вываживания. Живой игрок медленнее бота: верх — около 90 с.

- **Время суток** — по московскому часу старта поездки (сервер): рассвет 4–8 и вечерняя зорька 18–21 — `wait_pct 75`
  (клёв), ночь 22–3 — `wait_pct 90` и +20 ‰ редкой, день — 100.
- **Погода** — одна на московский день для всех: `sha256('weather:'+день)` → ясно / облачно (+15 ‰ редкой) / дождик
  (`wait_pct ×0,8`) / ветер (прицел быстрее: 1,25 с). Время и погода фиксируются в плане при старте поездки.
- **Наживка** (необязательно, выбирается перед игрой, тратится 1 шт. при `trip_play`, сверх прикормки маршрута):
  хлеб — клёв быстрее (`bait_pct 70`); кукуруза (пруд, заводь) — +40 ‰ редкой; живец-карась (река) — +50 ‰ редкой,
  `bait_pct 90`. Без наживки — как раньше. `abort_trip` наживку не возвращает: она потрачена в игре.
- **Редкая рыба** клюёт, только если `acc ≥ 800` и `roll < шанс` (`roll` 0…999 из плана). Пример: пруд, облачно,
  кукуруза, точный заброс — 80 ‰; без наживки днём — 25 ‰. Измерено (тот же бот, время суток и погода вперемешку):
  ~1 редкая на 6–7 поездок без наживки и ~1 на 3 с наживкой. Первая версия (60 ‰, +90/+120) давала 1 на 3,5 и 1 на 1,3 —
  слишком часто для «редкой»; ставки снижены.
- **Экономика.** Редкая рыба — **только запись в журнале**, не предмет склада и не продаётся: монет не добавляет.
  Наживка — сток (хлеб, кукуруза, карась за 18 монет). Множитель добычи прежний (≤ 1,25), XP прежний.

### 10.5 Журнал улова

`farm['fish_journal'] = {вид: {n, g}}` — сколько поймано и лучший вес (г). Пишется один раз при `trip_play` по
вытащенным рыбам; видит только владелец (проекция хозяина). В панели «Озеро» — карточка «Журнал улова»: шесть видов,
непойманные редкие — силуэтом. Первая рыба вида — строка в событиях.

### 10.6 Сервер, запись игры, миграция

- План v2 (`plan.v = 2`): `{casts:[{phase, zone, wait, nibbles:[‰], roll, fish:[обычная, редкая|null]}], window, mark_period,
  wait_pct, rare_chance, sky:{tod, weather}, baits}`, рыба `{id, g, pulls:[[тиков, сила]…]}`. Всё из `sha256(seed)`
  и серверного времени старта; клиент ничего не хэширует.
- Запись: `trip_play {trip, log}`, `log = {v: 2, bait: '' | id, casts: [[aim_ms, strike_ms|null, [переключения_ms…]]…]}`.
  Переключения — моменты отпускания/нажатия после подсечки (подсечка = нажатие). Проверки: строгие целые, шаг ≥ 40 мс
  между переключениями, ≤ 200 на заброс, заброс не раньше конца прошлого (+1 с паузы после боя), конец последнего
  заброса ≤ `(now − started_at)·1000 + 2000`. Переключения после конца боя игнорируются. Наживка должна быть на складе
  и подходить месту. Сервер сам проигрывает бой и выставляет `score`, `q` и улов. Один раз; повтор — через receipts.
- Миграция: открытые рыбалки v1 (`plan` без `v`) при загрузке (`upgrade_state`) получают план v2 из того же `seed` и
  `started_at` — их можно доиграть по новым правилам. Сыгранные v1 сохраняют свой `q`. Запись v1 (список) против плана v2
  → `422 bad_log` («обнови страницу»). Счёт v1 оставлен для плана без `v`.

### 10.7 Клиент

Холст в стиле фермы (те же формы и палитра: деревья как `treeSprite`, лебедь и утка через `smallAnimal`, вода и рябь озера):
дальний берег с деревьями, вода, кувшинки и камыши, берег с удочкой. Одна большая кнопка ≥ 64 px внизу меняет смысл:
«Забросить» → «Подсечь!» → «Тяни — держи». Шкала натяжения и расстояние до рыбы — на холсте сверху, крупно;
ночью подсвечены. На вступлении: время суток и погода, выбор наживки (группа выбора с количеством на складе).
Итог: пойманные рыбы с весом, новые записи журнала, бонус к улову.
