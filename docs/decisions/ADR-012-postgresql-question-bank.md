# ADR-012 — Транзакционный PostgreSQL-банк вопросов

- **Статус:** `accepted`
- **Дата:** 2026-09-04
- **Связанные задачи:** [MQB-006](../tasks/MQB-006-platform-postgresql-cutover.md)
- **Заменяет:** [ADR-004](ADR-004-local-question-bank.md)

## Контекст

Файловый `QuestionBank` позволил безопаснее редактировать JSON в первом
локальном прототипе, но оставлял два источника данных: PostgreSQL для игрового
состояния и каталог файлов для контента. Отдельные процессы bot/admin не могли
получить общую транзакцию, блокировка файла не распространялась на БД, а backup
должен был отдельно согласовывать дамп и копию каталога.

## Решение

Категории и вопросы хранятся в `question_categories`. Каждая категория имеет
монотонную ревизию и content hash для optimistic concurrency. Предыдущая версия
перед изменением сохраняется в `question_category_revisions`; удаление категории
является архивированием, а не физическим уничтожением истории.

Bot и admin API используют один `PostgresQuestionBank`. Массовый импорт
проверяет весь пакет и применяет его в одной транзакции. Bot перечитывает банк
перед новой игрой; уже начатая игра продолжает использовать свой snapshot.

Legacy `data/questions/*.json` и `data/global/categories.json` входят в строгий
одноразовый importer. Чистая dev/test-БД может быть заполнена этими файлами
явной seed-командой только если таблица категорий пуста. После seed/import
runtime не читает файлы и не выполняет dual-write.

## Последствия

- Изменения admin видны следующему запуску квиза в обоих интерфейсах.
- Конкурирующая правка с устаревшим hash получает конфликт, а не затирает данные.
- PostgreSQL dump содержит актуальный банк; новый формат dev backup не дублирует
  его JSON-копией, но восстановление старого формата остаётся совместимым.
- Исходный каталог вопросов остаётся в репозитории как миграционный seed до
  production cutover, но больше не является runtime source of truth.
- Старый файловый `QuestionBank` временно сохранён только для legacy JSON-mode и
  изолированных тестов; финальный cutover должен удалить этот совместимый путь.

## Проверка

- Alembic `0009` создаёт обе таблицы; `alembic check` не находит расхождений.
- Importer включает 63 категории и 6706 вопросов в operational digest и сверяет
  число категорий после транзакции.
- Проверены CRUD, conflict, repair, bulk import, архивирование и история ревизий.
- Полный контейнерный gate: 428 тестов, dump/restore и JS syntax checks.
