## Единый запуск dev

```powershell
Set-Location -LiteralPath 'C:\Users\Lizard\Projects\morning-quiz-bot'
.\scripts\Start-LocalDevelopment.ps1
```

Команда собирает единый `Dockerfile.dev` и поднимает PostgreSQL, миграции,
dev-seed, админку на <http://127.0.0.1:4184> и Mini App на
<http://127.0.0.1:4185/app>. Для живого
тестового Telegram-адаптера используйте `-WithTelegram`; он читает только
явно выбранный локальный `.env` и ограничен тестовым ботом/личным чатом.
Compose выполняет импорт через отдельный одноразовый `seed` перед сервисами;
админка не повторяет этот импорт при каждом рестарте. При отдельном запуске
`scripts/run_admin_preview.py` bootstrap остаётся включён по умолчанию.

```powershell
.\scripts\Start-LocalDevelopment.ps1 -WithTelegram
.\scripts\Stop-LocalDevelopment.ps1
```

Остановка завершает управляемые приложения, но оставляет PostgreSQL запущенным.
`Stop-LocalDevelopment.ps1 -StopDatabase` останавливает и контейнер, сохраняя
volume. Dev и тесты используют один сервер `127.0.0.1:55433`, но разные базы:
`morning_quiz_dev` и `morning_quiz_test`.
Сервис `game-worker` независимо от Telegram polling исполняет дедлайны Classic,
Photo и Mafia; бот остаётся адаптером доставки сообщений из PostgreSQL outbox.

Логи всех контейнеров:

```powershell
.\scripts\Show-LocalDevelopmentLogs.ps1
.\scripts\Show-LocalDevelopmentLogs.ps1 -Service mini-app -Follow
```

Полная приёмка также выполняется внутри dev-образа:

```powershell
.\scripts\Test-LocalMilestone.ps1
```

Она пересоздаёт только `morning_quiz_test`. Образ не содержит `.env`, локальные
архивы, `.git` или production-конфигурацию. Admin backup вызывает PostgreSQL
client напрямую и не получает опасный доступ к Docker socket.

Перенесены Git-история и индекс, текущие незакоммиченные изменения,
операционные данные для разработки, банк вопросов, изображения и Mini App
prototype. Проверены SHA-256 всех 487 скопированных файлов вне `.git`:
расхождений на момент проверки не было. Проверка целостности Git также прошла.

Не переносились рабочие `.env*`, файлы ключей `*.pem`/`*.key`, PID,

## Безопасное окружение

Локальный `.env` исключён из Git и Docker image. Он подключается только к
опциональному Telegram profile; database URL и безопасные dev-параметры задаёт
Compose, а не `.env`.

Проверка 2026-08-30 на установленном Python 3.13: dry-run импортёра без ошибок
(11 чатов, 16 пользователей, 24 участия, 184 достижения, 18 расписаний,
198 фото-записей); unit-тесты импортёра — `2 passed`; компиляция storage,
основных runtime-модулей и `web/main.py` прошла. Полный набор и PostgreSQL
integration tests в рамках копирования повторно не запускались.

Не копируйте рабочий токен на этот компьютер для запуска второго бота.
Для ручной проверки Telegram нужен отдельный тестовый бот и тестовый чат.
Учтите, что уже заданные переменные процесса имеют приоритет над `.env`:
перед локальными проверками очистите их в текущем PowerShell.

```powershell
Set-Location -LiteralPath 'C:\Users\Lizard\Projects\morning-quiz-bot'
$env:BOT_TOKEN = ''
$env:OPENROUTER_API_KEY = ''
$env:SENTRY_DSN = ''
$env:DATABASE_URL = ''
$env:TEST_DATABASE_URL = ''
$env:STORAGE_BACKEND = 'json'
$env:MODE = 'testing'
python -m storage.json_importer --dry-run
python -m pytest tests/test_json_importer.py -q
```

Эти проверки не подключаются к PostgreSQL и не запускают Telegram-бота.
Для отдельного Python-окружения его нужно создать заново на Windows, а не
использовать скопированный с сервера `venv`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt pytest pytest-asyncio
```

После установки выполняйте Python-команды через
`.\.venv\Scripts\python.exe`. Изолированная тестовая БД поднимается отдельно
по [инструкции PostgreSQL](POSTGRESQL_MIGRATION.md); рабочая БД и её URL
для тестов не используются.

## Возврат изменений на сервер

1. Проверить код, миграции и совместимость в локальной копии.
2. Подготовить перенос кода отдельно от рабочих данных и секретов.
3. Перед финальным импортом остановить все writers на сервере, включая админку.
4. Снять свежий серверный snapshot и сохранить дополнительную копию здесь.
5. Выполнить миграции и импорт именно свежих серверных данных, сверить числа,
   очки, достижения, настройки и восстановление состояний.
6. Только после проверки переключить рабочий backend и возобновить запись.

Не копировать локальные `data/`, `.env`, `.git`, `venv`/`.venv` или тестовую
БД поверх серверных. Не применять зеркалирование рабочей папки через
`robocopy /MIR`: оно может удалить или заменить накопленные серверные данные.
После появления новых записей в PostgreSQL откат требует их сохранения и
согласованного переноса; старый JSON snapshot сам по себе их не содержит.

Начат перевод локальной админки на storage-слой: доступны чтение чатов,
пользователей, транзакционная правка баллов и базовых настроек квиза с проверкой
версии. Также реализовано [применение расписаний](POSTGRESQL_SCHEDULES.md)
ботом из PostgreSQL каждые 15 секунд, с отдельным статусом применения.
Рейтинги и статистика бота читают свежие данные PostgreSQL без перезапуска.
Фото-квиз использует каталог БД и сохраняет серии с защитой начислений при
рестарте; подробнее в [руководстве фото-квиза](POSTGRESQL_PHOTO_QUIZ.md).
Классический квиз сохраняет poll ID и дедлайны; очередь удаления переведена
на адресные команды с подтверждением. [Поведение при рестарте и границы](POSTGRESQL_RECOVERY.md).
Проверки и оставшиеся ограничения
описаны в [руководстве PostgreSQL-админки](POSTGRESQL_ADMIN.md), там же приведён
запуск тестов в отдельной логической базе общего локального PostgreSQL.
