- **Статус:** `proposed` (требования и дизайн; кода нет)
- **Создан:** 2026-10-15
- **Связано:** [NIGHT_CITY_WEEKLY_DESIGN](NIGHT_CITY_WEEKLY_DESIGN.md) (§6, §14–§16), [NIGHT_CITY_ART_DIRECTION](NIGHT_CITY_ART_DIRECTION.md), [MQB-010](MQB-010-night-city-weekly-stages.md) (этапы 5 и 8), [MINI_APP_DEEP_LINKS](../MINI_APP_DEEP_LINKS.md)

> **Требование Ильи (2026-10-15).** Карточки дела, карту игры и «ситуативные штуки»
> нужно уметь: **А)** легко отправить в чат Telegram; **Б)** удобно показать в
> мини-аппе внутри Telegram (с правильным вызовом API Telegram); **В)** показать
> в отдельной версии игры. Всё это — сквозное: один источник, разные показы.

## 1. Главная идея

**Карточка — это данные, а не картинка и не страница.** Сервер хранит карточку как
набор блоков (заголовок, арт, текст, значки, действия) вместе с аудиторией
(кому разрешено). Из одной карточки несколько «рендереров» делают:

| Показ | Как выглядит | Кто рисует |
| --- | --- | --- |
| **Сообщение в Telegram** | **заранее заготовленная** картинка-карточка + подпись + кнопки-ссылки | ассеты готовятся заранее (§5.2); сервер подставляет только подпись и ссылку |
| **Мини-апп в Telegram** | интерактивный компонент с темой Telegram | клиентская библиотека компонентов |
| **Отдельная версия** | тот же компонент в обычном браузере | та же библиотека |
| **Только текст** | читаемый текст (доступность, сбой картинок) | сервер/клиент |

Что считается карточкой: герой, роль, цель, предмет, улика, место, событие, призрак,
финал, **карта** (с отметками), **снимок доски улик**, **сводка окна**, уведомление об
обвинении/слушании, досье (дизайн §3.5).

## 2. Что известно о Telegram (проверено по документации)

Источники: [Telegram Mini Apps](https://core.telegram.org/bots/webapps),
[Bots FAQ](https://core.telegram.org/bots/faq). Страница Bot API целиком не читалась
(слишком объёмная): пункты ниже, помеченные **(не сверено)**, взяты из моей памяти.

**Запуск и ссылки**
- **Прямая ссылка** `t.me/<бот>/<приложение>?startapp=…` открывает мини-апп **в любом
  чате**, при этом приложению доступны `chat_type` и `chat_instance`. **Main Mini App**
  (`t.me/<бот>?startapp`) тоже работает в группах; режим `mode=compact` даёт половину
  высоты.
- Параметр запуска приходит в `start_param` / `tgWebAppStartParam`. Допустимые
  символы и длина на прочитанной части страницы не указаны **(не сверено; по памяти:
  `A–Z a–z 0–9 _ -`, до 512 знаков)**.
- Кнопки `web_app` (клавиатурная и inline) дают `initData`, но **в группах в проекте
  не используются** (решение в [MQB-004](MQB-004-night-city-mafia.md): «обычная
  `web_app`-кнопка в группе не используется»); для групп работает URL-кнопка с
  прямой ссылкой.
- `sendData` — до 4096 байт и только при запуске клавиатурной кнопкой: для нас не
  годится.

**Вызовы из мини-аппа**
- `Telegram.WebApp.openTelegramLink(url)` — открыть ссылку Telegram, мини-апп остаётся
  открытым (с версии 7.0).
- `switchInlineQuery(query, chat_types)` (6.7) — вставляет `@бот запрос` в выбранный чат;
  нужен включённый inline-режим бота **(не сверено, включён ли)**.
- `shareMessage(msg_id)` (Bot API 8.0): `msg_id` берётся из «подготовленного
  сообщения», которое **сервер** сохраняет методом `savePreparedInlineMessage`.
  Подготовленное сообщение имеет `id` и `expiration_date`; срок жизни **не найден**.
- `shareToStory(media_url, …)` (7.8): HTTPS-картинка; подпись до 200 знаков.
- `requestFullscreen` (8.0), `downloadFile` (8.0, нужны заголовки
  `Content-Disposition: attachment` и CORS для `https://web.telegram.org`).
- Тема: `themeParams`, `colorScheme`, событие `themeChanged`; поля безопасной
  области `safeAreaInset`, `contentSafeAreaInset`; `viewportStableHeight`;
  `BackButton`, `MainButton`/`SecondaryButton`, `HapticFeedback`; `CloudStorage`
  (до 1024 ключей, значение до 4096 знаков).
- Проверка: `initData` проверяется на сервере (HMAC от токена бота, проверка
  `auth_date`); `initDataUnsafe` не доверять.

**Лимиты бота** ([FAQ](https://core.telegram.org/bots/faq)): примерно **1 сообщение в
секунду в одном чате**, **20 сообщений в минуту в группе**, около 30 сообщений в
секунду на рассылку; загрузка файла ботом — до 50 МБ. Подпись к фото ≤ 1024 знаков,
группа медиа 2–10 элементов, сообщение ≤ 4096 знаков **(не сверено)**.

## 4. Где что можно показывать (секреты)

Правило главное: **в чат Telegram уходит только то, что публично по правилам
дела.** Личные карточки — только в мини-аппе владельца (или, по просьбе самого игрока, в
личном чате с ботом).

| Карточка | Группа Telegram | Личка Telegram | Мини-апп / отдельная версия |
| --- | --- | --- | --- |
| Сводка окна, событие, итоговое слушание, финал | да | да | да |
| Карта (публичные отметки) | да (снимок) | да | да, интерактивная |
| Улика, выложенная на доску | да | да | да |
| Герой другого игрока (публичная часть) | да | да | да |
| Своя роль, цель, тайна, досье | **нет** | только по запросу владельца | да |
| Личный блокнот (найденные, но не выложенные улики) | **нет** | **нет** | да (владельцу) |
| Реплики NPC, диалоги | **нет** | **нет** | да |

Как «поделиться» без утечки: кнопка «Поделиться» вызывает сервер, а сервер строит
**публичную проекцию** карточки (зритель = «никто»), записывает неизменяемый
снимок и выдаёт на него короткую ссылку. Клиент не собирает отправляемые данные
сам. Карточку, которой ещё нет на доске, делиться нельзя.

## 5. Как это устроено

### 5.1 Идентификаторы и ссылки

- Каждый показываемый объект имеет **непрозрачный id** (например, `nc_8f3k2…`),
  привязанный на сервере к `(игра, карточка, снимок)`.
- Ссылка в Telegram: `https://t.me/<бот>/<приложение>?startapp=<id>`; в отдельной
  версии — **тот же параметр на сайте**: `https://quizzywizzy.duckdns.org/app?startapp=<id>`
  (клиент уже понимает `?startapp=`, `?tgWebAppStartParam=` и `?invite=`:
  [`app.js:74-75`](../../web/mini_client/app.js), после использования параметр
  убирается из адреса [`app.js:106-107`](../../web/mini_client/app.js)). В ссылке
  нет ни данных игры, ни секретов; сервер проверяет членство и права при открытии.
- Параметр запуска: короткий, в допустимых символах Telegram. Белый список
  страниц в клиенте ([`app.js:6-16`](../../web/mini_client/app.js)) и
  `deep_link()` ([`mini_app_launch.py:53-69`](../../modules/mini_app_launch.py))
  расширяются новыми целями (`night_card`, `night_map`, `night_board`), но
  значения по-прежнему проходят строгую проверку; неизвестный id показывает
  понятное сообщение, а не подмену.

### 5.2 Показ в чате Telegram (А)

*(по ответу Ильи 2026-10-15: серверный рендер картинок не нужен — карточки и
прочее готовятся заранее как шаблоны)*

- **Картинки не рисуются на сервере.** Для каждой карточки дела и каждого типа
  ситуативной «штуки» заранее готовится ассет: арт в рамке-шаблоне нужного
  размера для чата. Статичный текст на ассете допустим (название типа карточки,
  название места, заголовок улики — это авторские данные дела); **динамика** —
  имена игроков, отметки, числа, «кто где» — **только в подписи** и в мини-аппе.
- Каталог ассетов — часть опубликованного дела: файл на карточку, хеш содержимого,
  версия; ассет не меняется вместе с версией дела (дизайн §8). Для
  каждой карточки два экспорта: **для чата** (фото) и **для мини-аппа** (арт без
  рамки, рамку рисует интерфейс).
- Карта: заготовленная базовая картинка места; интерактивная версия — только в
  мини-аппе (отметки поверх SVG). В чате — базовая картинка + текстовый список
  публичных «кто где».
- Первая отправка загружает файл, дальше можно хранить идентификатор файла в Telegram
  и не загружать заново **(не сверено: привязка file_id к боту и срок жизни)**.
- Под фото — **URL-кнопка** «Открыть карточку»: прямая ссылка на мини-апп (§5.1).
  Для группы `web_app`-кнопка не используется.
- Набор карточек — группой медиа, если число элементов в допустимых пределах.
- События окна собираются в **одну сводку** (лимиты 1 сообщение/сек в чате и 20/мин
  в группе), а не россыпь сообщений; доставка идёт через существующий outbox
  (в нём at-most-once, [ADR-011](../decisions/ADR-011-game-substrate.md): игра от
  доставки не зависит).
- Запасной вариант — текстовое представление.

### 5.3 Показ в мини-аппе Telegram (Б)

- Один набор компонентов: «карточка», «карта», «доска», «сводка»; тема берётся из
  `themeParams` и `colorScheme` Telegram, безопасные области — из
  `safeAreaInset`/`contentSafeAreaInset`, как уже делает
  [`telegram-ui.js`](../../web/mini_client/telegram-ui.js).
- Навигация: системная `BackButton`; основное действие — `MainButton`/нижняя кнопка
  (например, «Положить на доску»); тактильный отклик `HapticFeedback` на
  значимые действия.
- Карта: интерактивная (масштаб, места, отметки); полноэкранный режим
  `requestFullscreen` там, где версия клиента ≥ 8.0
  ([`telegram-ui.js:48`](../../web/mini_client/telegram-ui.js) уже проверяет версию).
- «Поделиться»: из мини-аппа — `shareMessage` с подготовленным сообщением
  (сервер вызывает `savePreparedInlineMessage`), запасной путь —
  `openTelegramLink` на ссылку или `switchInlineQuery`
  ([`telegram-ui.js:41`](../../web/mini_client/telegram-ui.js) уже использует
  `openTelegramLink`). Нужны проверки: версия клиента, включён ли inline-режим,
  срок жизни подготовленного сообщения.
- Открытие из группы: по ссылке с параметром; `chat_type` и `chat_instance`
  позволяют связать запуск с комнатой `telegram:<chat>`.

### 5.4 Отдельная версия (В)

- Тот же клиентский пакет компонентов без `Telegram.WebApp`: вход по аккаунту, тема
  по настройкам системы, `BackButton` → обычная навигация, `MainButton` → обычная
  кнопка.
- Сейчас отдельная версия — **сайт** `https://quizzywizzy.duckdns.org/app` (ответ
  Ильи 2026-10-15); позже переезд на постоянный хостинг и «нормальное приложение»,
  но не скоро. Ссылки — по схеме §5.1; «Поделиться» — копирование ссылки и системное
  меню «Поделиться»; для Telegram-чата — прямая ссылка на мини-апп.
- Все API — те же, что у мини-аппа (дизайн §14); различается только слой
  «оболочка» (Telegram или браузер).

### 5.5 Слои

```
игра (сервер) ──> карточка (данные + аудитория)
                      ├─> «сообщение Telegram»: заготовленный ассет + подпись + URL-кнопки → outbox
                      ├─> компоненты клиента          → мини-апп в Telegram / браузер
                      └─> текстовое представление     → запасной вариант
оболочка клиента: Telegram.WebApp  ИЛИ  обычный браузер (общий интерфейс «Shell»)
```

Интерфейс `Shell` (в клиенте): `theme`, `safeArea`, `back()`, `primaryAction()`,
`share(card)`, `openLink(url)`, `fullscreen()`, `haptic(kind)` — две реализации
(Telegram, браузер). Игровой код вызывает только `Shell`.

### 5.6 Слои и сборка карточек

*(по предложению Ильи 2026-10-15: предметы на прозрачном фоне, карточки собираются
из разных шаблонов в одно изображение)*

Карточка — это **рецепт из слоёв**, а не одна нарисованная картинка. Слои снизу вверх:

| № | Слой | Что это | Формат |
| --- | --- | --- | --- |
| 1 | **Подложка** | фон карточки: бумага, цвет по жанру и типу | PNG/WebP без прозрачности или цвет |
| 2 | **Рамка** | шаблон рамки по типу карточки (герой, улика, место…) и жанру, середина прозрачная | PNG с альфой или SVG |
| 3 | **Арт-вырезка** | один предмет/герой/призрак на прозрачном фоне: ключ, письмо, печать, свеча, портрет | PNG с альфой |
| 4 | **Значки** | тип карточки, фракция, надёжность, цели | SVG |
| 5 | **Текст** | заголовок и описание (статичный текст дела) в зонах шаблона | шрифт с поддержкой кириллицы и разрешённой лицензией |
| 6 | **Эффекты** | тень, свечение (у призрака), виньетка | по описанию |

Рецепт карточки (часть описания дела, дополняет схему; формат ещё не в
`case.schema.json`):

```
card_recipe: { template: "evidence_v1", style_pack: "noir_print_a",
               plate: "paper_warm", frame: "frame_evidence_noir",
               art: [ {asset: "key_old_a", slot: "main"}, {asset: "seal_cracked", slot: "accent"} ],
               icons: ["evidence", "solid"], text: {title: "...", body: "..."} }
```

Шаблон описывает **зоны в долях ширины и высоты** (слот арта, заголовок, описание,
значки), поэтому один и тот же шаблон исполняется двумя способами с одинаковым
видом:

- **при публикации дела** сборщик (позже: `scripts/build_card_assets.py`, пока не
  существует) накладывает слои и сохраняет готовые изображения для **чата**;
  результат кэшируется и привязан к `content_hash` дела (дизайн §8) — это
  «заготовка заранее», серверного рендера «на лету» нет, как решил Илья;
- **в мини-аппе и на сайте** те же слои складываются в клиенте (HTML/CSS/SVG), текст
  остаётся живым и доступным.

Правила для арта и шаблонов:
- каждая **отдельная вещь — отдельный PNG с альфой**, один предмет на файл
  (ключ, лупа, обрывок бумаги, печать, свеча…): так одна вещь переиспользуется в
  разных карточках и делах;
- цельными остаются только **места** и **сцены финалов** (они — подложка);
- стиль задаёт пакет `style_pack` дела (`рамка + подложка + палитра + детали`); единый
  стиль держится в пределах одного дела, другому делу — другой пакет;
- динамика (имена игроков, отметки на карте) в собранные картинки **не** попадает,
  только в подпись и в живой слой мини-аппа.

Что нужно проверить до реализации: подходящий шрифт и его лицензия;
воспроизводимость раскладки в двух исполнителях (снапшот-тест «сборщик» против
«клиент»); вес готовых изображений под лимиты Telegram **(не сверено)**.

### 5.7 Состояния времени суток

*(по предложению Ильи 2026-10-15)* Карточки мест и сцены существуют в четырёх
состояниях: **утро, день, вечер, ночь** — одна композиция, меняются небо, свет и
палитра. В рецепте карточки это набор подложек:

```
states: { morning: "plate_library_morning", day: "plate_library_day",
          evening: "plate_library_evening", night: "plate_library_night" }
```

- Предметы-вырезки (улики, герои, значки) в состояниях общие; согласование тона
  делает верхний слой (мягкая тонировка/тень), а не перерисовка.
- **Какое состояние показывать — предложение:** по местному времени стола в момент
  показа (утро 06–11, день 11–17, вечер 17–22, ночь 22–06); для сообщений в чат — по
  времени отправки. Окна игры «День» (09–19) и «Вечер/ночь» (19–09) этим не
  меняются. Можно добавить ось «погода/событие» (например, метель из события
  дела) позже.
- Состояния собираются при публикации дела (§5.6), поэтому набор изображений
  растёт в 4 раза для мест; число мест на дело 6–8, значит 24–32 подложки на дело.
- В чат уходит заготовленный вариант нужного состояния; в мини-аппе возможен плавный
  переход между состояниями.

### 5.8 Шрифты

*(по поручению Ильи 2026-10-15: взять свободно разрешённые под нуарный стиль либо
сгенерировать собственный полный шрифт RU+EN; свой шрифт сразу делать в SVG, чтобы

**Готовые кандидаты.** Лицензия и наличие кириллицы сверены по метаданным

Условия OFL: можно встраивать в графику и приложение, распространять вместе с
программой; нужно сохранять текст лицензии и не продавать сам шрифт отдельно;
для изменённых версий действует правило «зарезервированного имени» **(пересказ,
не юридическое заключение; проверить перед выпуском)**. Для мини-аппа шрифты
размещаем у себя (WOFF2), а не загружаем с чужого CDN: так нет обращений
игроков к сторонним серверам.

Проверка перед выбором: полный набор нужных знаков (русские и латинские буквы,
`Ёё`, цифры, `№`, `«»`, `—`, `…`), читаемость на мелком размере телефона,
вес файлов.

**Собственный шрифт (если решим делать).** Глифы сразу рисуются в **SVG** — по одному
файлу на знак — и затем собираются в шрифт сборщиком (FontForge или fontTools со
сборкой через `fontmake`; **инструмент не выбран и в этом окружении не
проверялся**).

- **Состав:** базовая латиница (`U+0020–007E`), кириллица (`А–я`, `Ёё` — `U+0401`,
  `U+0451`), цифры, знаки препинания, `№`, `«»`, `„“”`, `—`, `–`, `…`, знак
  рубля; позже — расширения.
- **Шаблон SVG (предложение):** единый размер em (1000 единиц), общая линейка:
  базовая линия, высота строчных, высота прописных, верхние и нижние выносные
  элементы; одна и та же толщина штриха и «зернистость» гравюры у всех знаков;
  имя файла по коду знака (`uni0410.svg`); одна замкнутая контурная геометрия на
  знак, без растровых вставок.
- **Проверки (автоматические):** все контуры замкнуты; число узлов на знак в
  пределах лимита (шум «гравюры» не должен раздувать знак); единые поля и ширины;
  непрерывность набора (нет пропущенных знаков из списка состава); сборка в TTF/WOFF2
  без ошибок; пробный образец «все знаки + строки текста».
- **Риски:** разная манера у разных знаков при генерации; потеря читаемости на
  малых кеглях при гравюрной фактуре; кернинг и метрики приходится настраивать
  вручную или правилами; права на сгенерированные формы — условия сервиса
  генерации не проверялись.
- **Рекомендация:** на первом выпуске взять готовые шрифты и сделать собственный
  только для заголовков и декора (вариант «в» вопроса 33), а текст оставить готовым.

### 5.9 Хранение и форматы

*(по ответу Ильи 2026-10-15: хранить на сервере и в git, если не много весит;
привести к WebP)*

- **Формат хранения — WebP** (поддерживает прозрачность, подходит для вырезок).
  Исходные PNG от генератора весят около 2,6–3,2 МБ каждый; в репозиторий они не
  идут, оригиналы хранятся отдельно на сервере.
- Проект уже умеет конвертировать изображения в WebP (пункт меню в `bot_control.sh`,
  по описанию в [CLAUDE.md](../../CLAUDE.md)); отдельный скрипт для ассетов карточек
  нужен, **не существует**.
- **Правило «в git или на сервер»:** манифест ассетов (имя, размеры, `sha256`,
  версия) всегда в git; сами файлы — в git, пока весь набор дела не превышает
  разумный предел (предложение: **до 25 МБ на дело**, до 250 КБ на отдельный
  ассет); сверх этого — только на сервере, с проверкой по хешу из манифеста.
- **Экспорт для чата** собирается готовой плоской картинкой (подложка + рамка +
  вырезки) — прозрачность там не нужна. Какие форматы принимает Telegram для
  фото и стикеров, не сверено: проверить до выбора формата экспорта для чата
  (запасной путь — JPEG или PNG).
- **Экспорт для мини-аппа** — слои в WebP (с прозрачностью) и SVG.

### 5.10 Карточки дел в меню (геймификация)

*(предложение Ильи 2026-10-15: немного геймифицированные «настольные» карточки дел
для меню игры)*

Каждое дело в каталоге — карточка как у настольной игры: лицо и оборот,
переворачивается по нажатию.

**Лицо:**
- обложка дела (арт-сцена дела, 2:3) в рамке пакета стиля дела;
- название; значок мира и номер дела в мире («Мир «Зимнее озеро» · 2/5»);
- полоса значков: **сложность** 1–5 (ключи), **игроки** 4–12, **длительность**
  (неделя / 3–4 дня), значки **модулей** дела (опровержение, шифр, рассудок…);
- метки: «Новое», «Набирается стол» (сколько столов ищут игроков), «Повтор с другой
  разгадкой доступен».

**Оборот:**
- завязка (`meta.logline`, без спойлеров) и жанр/эпоха;
- мой статус: не играл / идёт / **раскрыто** / не раскрыто / ушёл; лучшая точность
  (`final_questions`) и экономность (`efficiency`);
- прогресс мира: «пройдено 2 из 5», печать мира за все дела (косметика, без силовых
  бонусов — дизайн §9);
- кнопки: «Собрать стол», «Найти стол», «Поделиться» (в чат уходит публичная
  карточка-приглашение — правила §4).

**Данные** берутся из описания дела: в схему добавлены необязательные поля
`meta.world`, `meta.crime_type`, `meta.modules`, `meta.difficulty`, `meta.duration`,
`meta.logline` ([case.schema.json](night_city/case.schema.json)); статус и прогресс —
из истории игрока на сервере. Сложность предлагает автор, после игр её можно
уточнять по статистике (доля раскрытых дел) — **предложение**.

**Арт на дело:** обложка 2:3. **Арт на пакет:** рамка карточки дела (лицо и оборот,
с местами под значки), значки сложности/игроков/длительности, лист значков модулей
(уже в §10.2 документа об артах), печать мира.

**Где показывается:** каталог «Ночного города» в мини-аппе и на сайте (фильтры по
миру, модулям, сложности, длительности); в чат — только как приглашение «Собираем
стол» с публичной стороной карточки.

### Читаемость основного текста (решение Ильи, 2026-10-15)

«Для обычных текстов — классические шрифты, читаемые для всех: у некоторых игроков
плохое зрение.» Поэтому:

- Основной текст — **PT Serif** (описания, улики, диалоги) и **PT Sans** (кнопки,
  подписи, меню). Оба от ParaType, лицензия OFL, кириллица есть, начертания обычное,
  курсив, жирное, жирный курсив (сверено по метаданным Google Fonts 2026-10-15).
  Old Standard TT и EB Garamond для основного текста **не используем** (мелкие
  строчные, декоративность); узкий WeLizard Noir — **только заголовки**.
- Размер основного текста не меньше 16 px (на телефоне), межстрочный интервал около
  1,5, длина строки умеренная.
- Контраст текста и фона не ниже 4,5:1 (уровень WCAG AA); на фото и тёмных
  гравюрах текст — только на подложке.
- Учитывать системное увеличение шрифта и дать в настройках игры крупный размер
  текста; не передавать смысл только цветом.
- Текст не впекается в картинки (§5.6), поэтому размер и шрифт меняются без
  перерисовки арта.
