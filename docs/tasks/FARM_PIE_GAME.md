## 1. Решения владельца (2026-10-29)

| Вопрос | Решение |
|---|---|
| Первый запуск | «Посиделки», ярмарка 26–30.11.2026, **универсальный пирог**; блины, тыква и снежная баба — позже |
| Конец забега | Первый полный промах **или 60 секунд**; кран постепенно ускоряется |
| Общая башня | Сумма **лучших высот участников** за ярмарку; порог **40 слоёв** (стартово, уточним симулятором) |
| Награда | «Пирог-башня» — декор **1×1 на ферму** каждому участнику; без монет и опыта |
| Ярмарка фонда | При совпадении порог башни **−25 %** (`BOOST.tower_threshold_cut_pct`) |
| Попытки | 3 призовые в московские сутки, затем бесплатная тренировка; тренировка в общую башню не идёт |
| Зачёт | Лучшая высота игрока за ярмарку; общая башня пополняется только разницей нового лучшего результата |
| Уровень | С 1-го: ярмарочная игра без порога |

## 3. Пользовательский цикл

1. На ярмарке открывается карточка «Пирог до небес» с прогрессом общей башни.
2. Игрок входит, видит стол, башню и качающийся кран с коржом; нажимает «Начать».
3. Одно касание сцены (или Space/Enter, или кнопка «Бросить корж») сбрасывает корж.
4. Свисающие края срезаются, башня растёт вверх. Кран-податчик стоит на лесах: с каждым коржом леса надстраиваются на ярус, кран поднимается, камера плавно едет за ним вверх, а фон сменяется с высотой — облака, стратосфера, космос. Кран постепенно ускоряется.
5. Забег кончается промахом или на 60-й секунде; высота идёт в личный зачёт и в общую башню.
6. При пороге 40 вся деревня получает «Пирог-башню»; прогресс виден на ярмарке и в «Вестнике».

## 4. Правила

### 4.1. Мир и план

Сцена — 1000×600, стол внизу. Основание башни — центр 500, ширина 560: `[220, 780]`.
Кран ходит по `[140, 860]`. Корж всегда шириной 560; сужается только башня.

План сервера (version 1):

```text
base=560, x0=140, x1=860, t0=4200, step=100, tmin=1800, warmup_ms=700,
phase=0..t0-1, fall_ms=320, min_gap_ms=400, limit_ms=60000, max_taps=160
```

Положение крана на высоте `h` и времени `t` (целые числа, одинаково в Python и JS):

```text
T = max(tmin, t0 - step*h)
p = (t + phase) % T
u = p*2000 // T
q = u <= 1000 ? u : 2000-u
x = x0 + (x1-x0)*q // 1000
```

### 4.2. Бросок и срез

Корж падает в точку `x`; его отрезок `[x-280, x+280]`. Новый отрезок башни — пересечение с текущим:

```text
lo = max(tower_lo, x-280), hi = min(tower_hi, x+280)
если hi <= lo — промах, забег окончен
иначе башня = [lo, hi], высота += 1
```

Срезанные части — только анимация; сервер считает пересечение. Ширина башни не может вырасти.

### 4.3. Забег и журнал

- Журнал — возрастающие моменты касаний в мс от старта: `[t0, t1, …]`.
- Между касаниями не меньше `fall_ms + 80 = 400` мс; первое касание — с 0 мс (пауза 700 мс).
- Первые 700 мс кран стоит: игрок успевает сориентироваться. Касание позже 60 000 мс не учитывается; забег кончается на 60-й секунде.
- TTL попытки — 65 с, чтобы последний корж успел упасть; `vgame_finish` принимает журнал и после
  конца ярмарки, если попытка уже начата.
- Сервер проигрывает журнал до первого промаха или лимита; клиент показывает ту же картину.
- Пустой журнал — 0 слоёв, попытка расходуется. Максимум журнала — `max_taps=160` касаний (защита; при 400 мс между касаниями за 60 с их не больше 150).

### 4.4. Счёт и результат

Счёт — высота (число поставленных коржей). Башня растёт вверх от подставки на столе; леса под краном надстраиваются вместе с ней, камера следует за верхом башни (§7.5). Лучший результат игрока за ярмарку — максимум высоты
призовых попыток. Тренировка показывает высоту, но не меняет лучший результат и общую башню.
Результат: «Поставлено N коржей. Лучшая высота: M. Башня деревни: X из 40».

## 5. Общая башня

### 5.1. Формула

- Участвует ферма, у которой есть хотя бы один призовой забег с высотой > 0.
- Вклад фермы — её лучшая высота за ярмарку; при новом лучшем в SQL прибавляется только разница.
- Общая башня = сумма вкладов; число участников — фермы с вкладом > 0.
- Порог — `tower.goal` из `CONTENT` (стартово 40); если предыдущий сезон фонда закрыт
  (`farm_village.total >= goal`), порог при создании строки уменьшается на 25 %.
- Порог фиксируется в строке при первом вкладе и не меняется до конца ярмарки.

### 5.2. SQL-строка

Новая таблица `farm_festival_towers` по образцу `farm_village`:

```text
key TEXT PRIMARY KEY          -- 'posidelki-2026'
total INTEGER NOT NULL        -- сумма лучших высот
goal INTEGER NOT NULL         -- 40 или 30
players INTEGER NOT NULL      -- ферм с вкладом > 0
reached_at BIGINT NULL        -- когда total впервые достиг goal
updated_at BIGINT NOT NULL
```

`total = total + delta` и `players + (первый вклад ? 1 : 0)` — одним атомарным `UPDATE`; строка
создаётся `ON CONFLICT DO NOTHING`. Миграция — следующая после `20261028_0042_open_rooms`.
SQLite dev-тесты используют тот же код через диалект, как у фонда.

### 5.3. Награда

- В `CONTENT['posidelki']` добавляется `_g('fest_posid_tower', 'Пирог-башня', 'decor', 'farm1',
  1, 60, source='tower', limit=1)`; предмет не продаётся, в лавке не появляется.
- Коллекция праздника получает его как обычную награду; `source='tower'` разрешается в
  `validate_content` и в проверке состояния фермы.
- Выдача ленивая и идемпотентная: при чтении фермы сервис берёт строку текущей (и последней
  завершённой) ярмарки; если `reached_at` есть, а ферма участвовала, предмет добавляется один раз.
- Арт предмета (иконка и объект сцены) — отдельный шаг художника; до него предмет виден в
  коллекции с заглушкой, как остальные неотрисованные праздничные вещи.

### 5.4. «Вестник»

Пока ярмарка открыта: «Пирог до небес: башня деревни 24 из 40». После порога: «Башня деревни
достроена: „Пирог-башня“ у всех участников». Данные — из праздничной проекции (`fair.tower`),
новых запросов клиент не делает.

## 6. Сервер

### 6.1. Каркас

`domain/farm_village_games.py` получает два обработчика: `pukh_ballista` (без изменения поведения)
и `agata_pie`. Общий слой оставляет себе уровень, попытки, тренировку, TTL, квитанции, блокировку
фермы и хранение состояния. Обработчик игры описывает:

- `make_plan(seed)`, `replay(plan, log)` — чистая физика;
- `blank(now)`, `advance(state, now, fair_key)` — суточный сброс попыток и смена ярмарки;
- `public(state, spec, ...)` — проекция для клиента;
- `validate(state)` — проверка JSON фермы;
- `finish(state, farm, run, log, now)` — результат, лучший результат, разница для башни.

Баллиста переносится в этот интерфейс без изменения формул и фикстур; её тесты остаются зелёными.

### 6.2. Домен `domain/farm_pie.py`

Только целые числа: план из `sha256(seed)`, `crane_x`, `drop`, `replay`, `score`. Никаких
Telegram, HTTP, БД и UI. JS-зеркало — `qw_farm/static/pie-physics.js`, паритет на общих фикстурах,
как у баллисты.

### 6.3. Состояние фермы

```text
farm['village_games']['agata_pie'] = {
  version: 1,
  fair: 'posidelki-2026',   # ключ праздника
  day: <московские сутки>,
  attempts: 0..3,
  practice: int,
  best: int,                # лучшая высота за ярмарку
  contributed: int,         # сколько уже прибавлено в SQL
  run: {id, started_at, expires_at, practice, plan} | null,
  last_result: {run_id, height, best, practice, expired, reward?} | null
}
```

Смена суток сбрасывает `attempts`/`practice`, сохраняя `best` и `contributed`. Новая ярмарка
сбрасывает состояние целиком: прошлый вклад уже в SQL и в коллекции.

### 6.4. Команды и права

- `vgame_start {game:'agata_pie'}` — только при открытой ярмарке и наличии `tower` в контенте;
  проверяет уровень, попытки, создаёт план; при активном забеге возвращает его.
- `vgame_finish {game, run_id, log}` — проверяет владельца, квитанцию, журнал, темп и лимит;
  считает высоту, обновляет лучший результат и `contributed`, возвращает текст.
- Разницу в SQL и награду применяет сервис после чистой команды в той же транзакции; повтор
  команды не прибавляет второй раз.
- Гость чужой фермы играть не может: команды только владельцу, проекция — только владельцу.
- Показывать игру в карточке ярмарки — только когда `current.phase === 'fair'` и у праздника есть
  `tower`; на ярмарках без конфигурации карточки нет.

### 6.5. Контент первого среза

```text
CONTENT['posidelki']['tower'] = dict(goal=40, item='fest_posid_tower')
```

Плюс предмет `fest_posid_tower` в `goods`. Остальные праздники — после их контента; башня
добавляется в `CONTENT` тем же полем.

## 7. Клиент

### 7.1. Вход

Карточка «Пирог до небес» на ярмарке (`festivals.js`): название, одна строка описания,
прогресс «24 из 40», кнопка «Играть» / «Ещё раз» / «Тренировка». Одна главная кнопка на карточку.
В «Вестнике» — строка прогресса, без отдельной кнопки.

### 7.2. Экран

Как у «Баллисты»: `FARM_PIE` — заголовок, «‹ В деревню», сцена, карточка статуса, правила.
На телефоне управление под сценой, на ПК — справа. В статусе: попытка/тренировка, высота,
лучший результат, башня деревни. Главная кнопка: «Начать»; во время забега действие — сцена
и вторичная кнопка «Бросить корж» для клавиатуры и доступности. После забега — результат и
«Ещё раз» либо «Тренировка». Выход из игры — как у других мини-игр (⚙ → главное меню).

### 7.3. Состояния

- ярмарка закрыта — карточки нет;
- нет попыток — «Тренировка», в башню не идёт;
- идёт забег — кран, башня, счётчик коржей, таймер 60 с;
- результат — высота, лучший, общий прогресс, награда;
- порог достигнут — «Башня деревни достроена», предмет в коллекции;
- ошибка сети — понятный текст и «Повторить», без потери забега.

### 7.5. Сцена, камера и высота (уточнение владельца 2026-10-29)

Слова владельца: «с каждым новым коржом растёт основание, на котором стоит кран-податчик, и он должен
с камерой уезжать вверх — выше в небо, затем в космос, в зависимости от высоты».

- **Мир.** Подставка на ярмарочном столе, её верх — y=470; корж n (с 1) лежит верхом на `470 − 30·n`.
  Башня растёт вверх, ширину режет только срез (§4.2). Мир не сжимается и не масштабируется.
- **Кран.** Портальный кран: балка на двух деревянных лесах у краёв сцены (x 24 и 896, ярусы по 30 px от
  земли y=520), тележка ездит по балке по `crane_x`, корж висит на стропах. Балка всегда на 250 выше верха
  башни (`220 − 30·h`): каждый новый корж добавляет ярус лесов, и кран поднимается на слой (плавно, ~0,3 с).
- **Камера** едет вверх за верхом башни: пока башня ниже трёх слоёв, кадр стоит на ярмарке; дальше верх
  башни держится на y=380 экрана, кран — над ним. Камера догоняет кран с лёгким запаздыванием. Сдвигается
  весь мир (`#pie-world`), а не отдельная платформа.
- **Высота и фон.** Цвет неба, звёзды и Земля плавно интерполируются по высоте (ключи в SVG):
  ярмарка (0–9) → облака (10–19, облачный слой проходит мимо) → стратосфера (20–31, небо темнее, снизу
  поднимается изогнутый горизонт) → космос (32+, звёзды, Земля внизу). Значок в углу сцены и строка
  прогресса показывают зону и высоту; на лесах — таблички с высотой каждые 5 слоёв.
- **Броски.** Корж падает с ускорением за `fall_ms`, ложится, срезанные края отлетают и падают; следующий
  корж спускается с тележки. Промах пролетает мимо башни и уходит вниз из кадра.
- **Ночь** — та же геометрия: ночная ярмарка с фонарями, луна, тёмная Земля с огнями городов.
  **Контрастный режим** — обводка коржей 4 px тёмным, светлее ночь (фильтр сцены), сплошной значок
  высоты с рамкой. `prefers-reduced-motion`: камера и кран встают сразу, без срезанных кусков и пульса значка.
- Восстановленный забег (перезагрузка, повторное открытие) сразу показывает башню на своей высоте.
- Строка статуса (живой регион) объявляет высоту один раз на корж; секундомер — в строке прогресса без
  озвучивания.

### 7.4. Доступность и движение

Сцена — кнопка с `aria-label`; Space/Enter бросают корж; таймер не единственный способ узнать
состояние (высота и статус текстом). `prefers-reduced-motion` отключает качание фона и срезание
частей, оставляя понятный результат. Все касания ≥ 44 px, зазоры ≥ 8 px.

## 8. Арт

Сцена — ярмарочный стол на площади, леса с портальным краном, корж на стропах; небо по высоте
(облака, стратосфера, космос с Землёй); палитра и фигуры фермы, день и ночь. Генератор
`scripts/art/village_games/agata_pie.py` + `pie_scene.js` (по образцу `pukh_ballista.py`): чистый SVG
без растров и фильтров. Игра только расставляет нарисованное: `<use>` ярусов лесов и табличек высоты,
слои башни по рецепту `korzhMarkup` (тот же, которым генератор рисует висящий корж), трансформы
камеры и крана, цвета неба из ключей `data-sky`/`data-stars`/`data-earth`. Контракт координат —
`scripts/art/village_games/pie_scene.md`. Превью 375×812, 390×844, 1280×800 днём и ночью и крупный план — владельцу
до подключения. Облики Посидок и следующих праздников меняют только палитру и предметы, геометрия
общая. Награда «Пирог-башня» — иконка и объект сцены отдельным шагом.

## 9. Проверки

- **Домен:** детерминизм плана, крайние углы крана, промах, срез, 60 с, пустой журнал, слишком
  частые касания, лишние касания, журнал после конца.
- **JS↔Python:** общие фикстуры высот/отрезков/счёта, как `tests/fixtures/farm_ballista.json`.
- **Сервис:** 3 попытки, тренировка не в счёт, смена суток и ярмарки, повтор `command_id`,
  истечение TTL, повторная выдача награды, гость не играет, откат.
- **PostgreSQL:** атомарное прибавление из двух ферм, порог срабатывает один раз, `players`,
  ленивая выдача декора, откат миграции не удаляет историю.
- **Праздники:** `source='tower'` в контенте и состоянии, предмет в коллекции, не продаётся.
- **UI:** карточка только при ярмарке; экран на 375/390/1280, день/ночь; тап, Space, «Бросить»,
  reduced-motion; `node --test tests/js/ui_rules.test.cjs tests/js/ui_layout.test.cjs`;
  `python tests/ui/ui_check.py gaps --base <URL>` на живом приложении.
- **Арт:** XML, уникальные ID, детерминизм, отсутствие растров, превью, кадры реального экрана.
- **Баллиста:** старые тесты и фикстуры не меняются; общий рефакторинг каркаса не ломает её.

## 10. Порядок реализации

1. Дизайн-док и ответы владельца — этот шаг.
2. Домен `farm_pie`, JS-физика, фикстуры паритета.
3. Обобщение `village_games`, перенос баллисты без изменения поведения, тесты.
4. SQL-строка башни и миграция, сервис, контент и награда праздника.
5. Экран, вход с ярмарки, «Вестник», состояния.
6. Арт-генератор, превью, установка сцены.
7. Полный гейт, кадры, песочница — по `RELEASE_CRITERIA` и с разрешением владельца.

## 11. Открытые вопросы

- Порог 40 — стартовое число; проверить симулятором на реальном числе активных ферм.
- Условие ярмарки фонда для −25 %: использовать закрытый прошлый сезон фонда; если в сервисе
  ещё нет готовой проверки, вынести её в отдельный шаг и не блокировать первый запуск.
- Название и место награды («Пирог-башня» 1×1 на ферму) и её арт — подтвердить при превью.
- Кривая ускорения крана (`t0/step/tmin`) — проверить на плейтесте, числа в плане версионируются.
- Ход крана ±360 при ширине коржа 560: промах возможен, лишь когда башня сузится примерно до 160 px, а пока
  она широкая, забег кончается по 60 секундам. Решение владельца 2026-10-29: пока оставить, вернуться
  после плейтеста.
- Включать ли игру на ярмарках без `tower` в контенте — сейчас нет: карточка скрыта, пока
  праздник не получил конфигурацию.
