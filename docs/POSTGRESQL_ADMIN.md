# PostgreSQL: транзакционные баллы и локальная админка

Состояние на 2026-08-30. Это реализованный **локальный этап**, не готовый
production cutover. Задача [MQB-001](tasks/MQB-001-postgresql-and-mini-app-foundation.md)
остаётся `in_progress`. Серверный бот и исходные данные не переключались.

Админка теперь требует отдельный ключ и сессию, включая JSON-режим.
[Вход, CSRF, готовые PG-экраны и локальный preview](ADMIN_AUTH.md).

Первый локальный комплект теперь включает `/api/bank` и экран банка вопросов,
`/api/analytics/overview` и экран статистики. Настройки в UI включают разрешённые
и запрещённые категории, режим ежедневного выбора и мудрость дня.
Счётчики использования категорий и число завершённых классических игр
сохраняются внутри closing transaction с проверкой UUID/revision.
Bulk snapshot категорий больше не записывается. Перед новой игрой бот читает
актуальные счётчики и вопросы из PostgreSQL без записи служебных JSON.
[Воспроизводимая приёмка и запуск](LOCAL_MILESTONE.md).

## Как сохраняется ответ

`storage/members.py` содержит общий `MemberService` для бота и админки.
Он блокирует строку пользователя, затем участие в чате. Обработка ответа
читает свежий профиль из БД, рассчитывает результат на отдельной копии и одной
транзакцией сохраняет журнал ответа, баллы, счётчики, серию, достижения и
глобальные итоги. Память бота и результаты сессии обновляются после commit.

- Повторная пара `poll_id + user_id` не начисляет баллы и не повторяет сообщения.
- Учитываются и старые poll IDs, импортированные из JSON без записей в журнале.
- Фото-квиз использует ключ `photo:<session UUID>:<question index>`; сохраняются
  прежние правила начисления, без увеличения числа классических poll-ответов.
- Фото-вопрос не завершается дважды при одновременной обработке. При ошибке
  сохранения остаются возможность повтора и таймер окончания вопроса.
- Фото-метаданные и активные серии теперь работают через PostgreSQL. Баллы и
  переход вопроса сохраняются одной транзакцией; [восстановление фото-серии](POSTGRESQL_PHOTO_QUIZ.md)
  не отправляет подтверждённое фото заново и не сбрасывает дедлайн.
- В PG-режиме `save_user_data` и `update_global_statistics` не сохраняют
  устаревшие профили из памяти. Bulk snapshot-запись пользователей запрещена.
- `sync_member_state` оставлен только для начального заполнения отсутствующего
  участия; существующее участие таким вызовом перезаписать нельзя.

Изменение баллов в админке использует те же блокировки и в одной транзакции
обновляет чатовый и глобальный счёт. Параметр `expected_score` позволяет
отклонить устаревшую правку с HTTP 409. Если он не передан, явно заданный новый
счёт применяется к актуальному значению под блокировкой.

## Актуальное чтение и настройки

Рейтинги чата и глобальный рейтинг, `/mystats`, `/chatstats` и общие показатели
в итогах сессии читаются из PostgreSQL через `ScoreQueries`. Правка из админки
видна при следующем запросе без перезапуска и без нового ответа игрока.
Чтение не перезаписывает рабочий кэш, поэтому оно не может затереть результат
одновременно обработанного ответа. Профили участников в итогах игры читаются
одним запросом, без двух дополнительных запросов на каждого игрока.

При недоступной БД команды сообщают об ошибке, не возвращая старые значения
из JSON. В итогах игры сохраняется результат самой сессии, а вместо нулевых
общих баллов выводится предупреждение о недоступной статистике.

`SettingsService` обновляет только указанные пути настроек под блокировкой чата.
Миграция `20260830_0002` добавляет `chats.settings_revision`, не заменяя старые
настройки и баллы. Настройки и строки `daily_schedules` сохраняются одной
транзакцией; сбой откатывает и значения, и версию, и расписание.

Бот ожидает завершения записи перед продолжением обработки. `update_quiz_setting`
обновляет новый и совместимый старый ключ одной транзакцией. Устаревшая версия
даёт `SettingsConflict`; версии чтения разделены по callback-контекстам, поэтому
параллельное чтение другого callback не снимает защиту. Результаты чтения —
отдельные копии, их изменение не меняет кэш. Автосохранение настроек из снимка
в PG-режиме отключено. Сброс через настройки бота теперь сохраняется в БД.

Асинхронные методы чтения `ScoreManager` и изменения настроек `DataManager`
необходимо вызывать с `await`. Обработчики переведены; отдельный AST-тест
защищает их от случайно пропущенных ожиданий.

## Доступные административные API

При `STORAGE_BACKEND=postgres` перед старыми JSON handlers регистрируется
`web/postgres_admin.py`. Подключение БД открывается и закрывается через lifespan
FastAPI. Неизвестный backend или ошибка подключения не запускают JSON fallback.

| Метод и путь | Результат |
| --- | --- |
| `GET /api/storage/status` | Backend и предупреждение о незавершённой миграции |
| `GET /api/chats` | Список чатов из БД, без вызовов Telegram и записи JSON |
| `GET /api/chats/{chat_id}/settings` | Настройки; версия в `X-Settings-Revision` и `ETag` |
| `PUT /api/chats/{chat_id}/settings` | Параметры квиза и расписания, обязательный `expected_revision` |
| `GET /api/schedules/status` | Свежесть отчёта бота, применённые версии и ошибки расписаний |
| `GET /api/analytics/chats` | Аналитика чатов |
| `GET /api/analytics/chats/{chat_id}` | Профили и актуальные баллы участников |
| `GET /api/users` | Пользователи, глобальные баллы и участие в чатах |
| `PUT /api/users/{user_id}/score` | Правка баллов: `chat_id`, `new_score`, опционально `expected_score` |
| `GET /api/photo-quiz` | Каталог из БД, состояние enabled, наличие картинки и version |
| `PUT /api/photo-quiz/{name}` | Частичная правка ответа/подсказок/enabled с обязательной expected_version |
| `GET /api/images/{filename}` | Локальный WebP из ограниченной папки, после авторизации |

Балл — конечное число с не более чем тремя знаками после запятой. Некорректные
значения дают 422; отсутствующее участие — 404. Чатовые итоги баллов и ответов
вычисляются из `chat_members`, а не из старого JSON-снимка статистики.

Запись настроек разрешена для `default_num_questions` (1–100),
`default_open_period_seconds` (5–600), `enabled_categories`, `disabled_categories`.
Добавлен также `auto_delete_bot_messages` (boolean).
Также доступны частичные вложенные изменения `daily_quiz` и `daily_wisdom`.
Расписания применяются ботом каждые 15 секунд; протокол подтверждения и границы
гарантий описаны в [руководстве расписаний](POSTGRESQL_SCHEDULES.md).
Число вопросов и время ответа синхронизируются с соответствующими ключами `quiz`.
Отсутствующая версия даёт 428, устаревшая — 409, некорректный запрос — 422.
Передайте `expected_revision` из заголовка последнего GET, например:

```text
PUT /api/chats/-123/settings?expected_revision=4
Content-Type: application/json

{"default_num_questions": 15}
```

Это границы текущего API, а не утверждение о максимумах новейшего Telegram API.

Операции с банком вопросов выполняются транзакционно в PostgreSQL; media bytes
пока остаются файловыми, а их метаданные — в БД. Остальные неперенесённые
операционные `/api/` маршруты возвращают **501**, включая старые toggle-маршруты,
подписки, reset/delete/ban, системное управление, создание/удаление фото и upload
и ещё не переведённую аналитику. Это намеренная защита от записи в два хранилища.
Фронтенд PG-режима показывает обзор, чаты/настройки, участников/баллы и фото-метаданные.
Неперенесённые экраны временно скрыты. Формы настроек и фото используют версии,
а правка баллов — ожидаемое значение; конфликт не повторяется автоматически.
Сохранение настроек без версии по-прежнему даёт 428. Поля `daily_quiz` и `daily_wisdom`
поддерживаются через versioned PUT; невалидный смешанный запрос отклоняется целиком.
В JSON-режиме сохраняются прежние маршруты.

Админка остаётся локальной. Не публиковать этот сервис в интернете; эти
маршруты не являются пользовательским API Mini App и не получают Telegram
`initData`-авторизацию автоматически.

## Воспроизводимые проверки на Windows

Выполнять **в локальной копии**, не на серверной шаре. Docker Desktop должен
работать. Единственный Compose-проект `mqb-local-dev` запускает PostgreSQL 17
на loopback:55433. Dev и проверки разделены именами баз, а не контейнерами.

```powershell
Set-Location -LiteralPath 'C:\Users\Lizard\Projects\morning-quiz-bot'
.\scripts\Test-LocalMilestone.ps1
```

Проверено: **109 passed**. Сценарии включают параллельные ответы и бонус серии,
конкурентный дубль, правку администратора и устаревшее автосохранение, откат
после записи журнала/профиля/достижения, импортированные ответы, фото-начисления,
глобальный счёт двух чатов, API 404/409/422/501 и JSON-совместимость фото-квиза.
Smoke настоящего `web.main.app` также прошёл: status/chats/users — 200,
непереведённый reset — 501. Реальный Telegram при проверках не вызывался.

Дополнительно проверены свежие рейтинги и команды Telegram без реального
Telegram, конфликты настроек между callback-задачами, атомарность расписаний,
сброс настроек, API 428/409 и сохранение действующих jobs при ошибке чтения БД.
На заполненной тестовыми записями схеме `0001` выполнен upgrade до `0002`:
настройки, чатовые баллы и глобальные итоги сохранились. `alembic check` прошёл.

Добавлены проверки синхронизации расписаний, восстановления jobs, часовых поясов,
ошибок добавления/чтения БД, устаревших callbacks, отключения мудрости во время
генерации, статуса применения и ввода времени через меню бота.

Добавлены проверки классических checkpoints, рестарта с poll ID и дедлайнами,
конкурирующих таймеров и завершения, восстановления баллов из журнала,
устойчивой очистки, настроек автоудаления и паузы после RetryAfter.
Отдельно проверено, что pickle меню не подменяет PostgreSQL-сервисы.
[Границы восстановления и доставки](POSTGRESQL_RECOVERY.md).

Проверены также авторизация, CSRF/Origin/Host, сроки сессий, конфликт фото-метаданных,
безопасные пути картинок и настоящий web.main.app. Браузерный сценарий описан
в [руководстве входа](ADMIN_AUTH.md).

Актуальный полный набор через `Test-LocalMilestone.ps1`: **433 passed**,
35 предупреждений. Включены PostgreSQL-банк, миграция Mafia, сквозная приёмка, защита импорта и
сравнение всех полей после pg_dump/restore. Исправлены fixtures
`tests/test_simplified_category_stats.py`: файлы создаются до инициализации,
используются настоящие словари и актуальные поля глобальной/чатовой статистики.
Сохранены проверки количества, потоков и записи; добавлена проверка повторного
чтения. Исправлен дефект выбора категорий: если после cooldown осталось слишком
мало кандидатов, набор дополняется без дублей до запрошенного количества.
В старых тестах остаются предупреждения о возврате значений вместо `assert`;
зелёные старые проверки не заменяют ручную приёмку.

Приёмка сама пересоздаёт только `morning_quiz_test`. Для остановки приложений и,
при необходимости, общего контейнера:

```powershell
.\scripts\Stop-LocalDevelopment.ps1
.\scripts\Stop-LocalDevelopment.ps1 -StopDatabase
```

Volume не удаляется. Архивы реальных данных и серверная БД этими командами не
затрагиваются; `down -v` для локального dev использовать нельзя.

## Что ещё требуется до переключения

1. Перевести оставшиеся административные операции и расширить PG-интерфейс.
   Базовые экраны уже адаптированы к версиям и недоступным функциям. Авторизация
   одного локального администратора реализована, но панель ещё не завершена.
2. Проверить связку versioned API → работающий тестовый бот → Telegram-чат.
   Синхронизация jobs уже реализована и проверена без сети; реальные доставка,
   паузы процесса и поведение клиентов требуют отдельной приёмки.
3. Проверить фото-квиз в живом тестовом чате и перенести upload/создание медиа.
   Правка фото-метаданных, runtime-каталог и восстановление фото-серии реализованы,
   границы доставки и очереди очистки описаны в [руководстве](POSTGRESQL_PHOTO_QUIZ.md).
4. Провести живую приёмку восстановления игр, расписаний и очистки. Их локальные
   сценарии уже покрыты тестами. Для итогов/пояснений и фоновых служебных enqueue
   остаются окна сбоя: [точные границы](POSTGRESQL_RECOVERY.md). Транзакция БД
   не делает Telegram-отправку атомарной.
5. Провести дальнейшую проверку legacy handlers, обновить Telegram API и сделать
   реальный Mini App. Production сейчас не трогать; перенос требует нового
   прямого разрешения пользователя, приёмки и свежего snapshot.
