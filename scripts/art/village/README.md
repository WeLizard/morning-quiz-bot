# Генератор карты деревни

`qw_farm/static/village.svg` — мир 2400×1800 с одним встроенным WebP 3200×2400. Этот фон рисует
генератор из этой папки. Здания, деревья, фонари, тени, земля и дороги рисуются собственными функциями
фермы (`qw_farm/static/scene_buildings.js`, методы `FarmScene` из `scene.js`) на канвасе в headless Chromium.
Правки арта деревни делаются здесь, а не накладками поверх готовой картинки
(см. `.agents/skills/mqb-vector-art/SKILL.md`).

## Происхождение

Генератор восстановлен 2026-10-22 по журналу сессии, в которой 2026-10-14…15 нарисован нынешний фон: исходный
`village.js` и все последующие правки воспроизведены по порядку. Восстановленный рендер совпадает с WebP из
`village.svg` до уровня сжатия: средняя разница 1,3 из 255, различаются 0,05 % пикселей (сглаживание).
Из исходника изменены только обёртка (`render()` вместо скрипта страницы), сцена `s` (теперь это настоящий
`FarmScene`, а не копия его методов) и ворота (см. ниже).

## Команды

```bash
python scripts/art/village/build_village.py                  # -> .local/village-generator/out/
python scripts/art/village/preview.py                        # -> .local/village-generator-preview/
python scripts/art/village/test_reproducible.py
python scripts/art/village/build_village.py --install        # пишет qw_farm/static/village.svg — только после одобрения превью владельцем
```

Нужны Playwright и его Chromium. Используется закреплённый `chromium_headless_shell-*` из
`PLAYWRIGHT_BROWSERS_PATH` (по умолчанию `F:\Caches\ms-playwright`) либо путь из `VILLAGE_CHROMIUM`.
Эталон `reference.json` снят на `chromium_headless_shell-1194`, Pillow 11.3.0, libwebp 1.5.0. На других
версиях тест проверяет только равенство двух прогонов и сообщает о расхождении с эталоном.

## Неподвижный фон и живые слои

В фон запекается только неподвижное. Всё, что движется или нажимается, — отдельные слои игры (`app.js`, `style.css`),
которые ставятся по координатам из этого же рендера (`manifest.json`, единицы мира 2400×1800):

- дым труб — `smoke` (= `VILLAGE_SMOKE`); в фоне трубы без дыма: хук `smoke()` записывает точку и не рисует;
- окна и фонари ночью — `lights` (= `VILLAGE_LIGHTS`): хуки `winY`/`winX` записывают каждое окно;
- крылья ветряной мельницы — `sails` (элемент `.vfx-sails`); в фоне только башня;
- водяное колесо — `wheel_hub` (= ступица `VILLAGE_WHEEL_SVG`, 731/555); в фоне ось, жёлоб, слив и пена, лопасти — живой SVG-слой;
- табличка «Ферма» — кнопка `.village-gate`; в фоне арка (столбы, дуга, цепи, фонарь), доска — `gate_board.svg`.

Ворота — `gate.js`, в стиле таблички фермы (`FarmScene.welcomeSign`): тёмные столбы с острыми навершиями, трава у
подножия, фонарь на кронштейне. Арка запекается в фон. Доску рисует сама `FarmScene.signBoard` в плоскости арки, но
в записывающий контекст `svg_ctx.js`, поэтому она получается векторным SVG для кнопки: дневной и ночной варианты
(ночью, как на ферме, доска светлее тонировки), прозрачная зона нажатия `vg-hit` = контур доски с полями 4 единицы.
Положение и размер кнопки — `manifest.json → gate_board`. Превью ворот: `preview_gate.py` (375 и 1280, день, ночь, наведение).
Для подключения в игру нужно заменить `VILLAGE_GATE_SIGN`/`VILLAGE_GATE_BOARD` в `app.js` на `gate_board.svg` и его рамку
и добавить CSS из `preview_gate.GEN_CSS` (кнопка `pointer-events:none`, нажимается только `vg-hit`; день/ночь).

## Граф проходимости

`manifest.json → walk` и `app.js → VILLAGE_WALK` (те же данные, короткие ключи). Всё в единицах мира 2400×1800
(процент мира = `x / 24`, `y / 18`), целые числа, порядок детерминирован (узлы отсортированы по `y`, затем `x`).

```js
VILLAGE_WALK = {
  n: [x0, y0, x1, y1, …],   // узлы: пары координат; узел i = (n[2i], n[2i+1])
  e: [a0, b0, a1, b1, …],   // рёбра: пары индексов узлов, a < b; ребро — отрезок, по нему можно идти
  a: {'Филиныч': 12, 'place:board': 40, 'visitor:0': 7, gate: 98, hall: 51, start: 90, …},   // точки подхода
  z: [[x1, y1, x2, y2, x3, y3, x4, y4], …],   // проходимая земля: дороги, тропинки, площадь, мост (четырёхугольники)
}
```

- **Откуда.** Осевые линии дорог и тропинок плана, сетка 1,5 тайла по площади, мост над рекой; концы тропинок
  продлены до оси дороги. Каждое ребро проверено против препятствий сцены: следы зданий и реквизита,
  стволы деревьев, заборы, вода (настил моста — можно). Отрезки, задевающие препятствие, выброшены; куски сети,
  оторванные от неё, и точки подхода, до которых нет прямого чистого отрезка, присоединяются маршрутом по траве
  (поиск по сетке 0,25 тайла в обход построек, затем выпрямление). Маршруты по траве не заходят за высокие предметы:
  там фигурка, нарисованная поверх фона, выглядела бы идущей по крыше.
- **Точки подхода `a`.** Для каждой цели, куда клиент ведёт игрока (`villageGo`): жители `VILLAGE_SPOTS`
  (цель `[x, y + 1.6]`, ключ — имя), таблички `VILLAGE_PLACES` (`place:<id>`, `[x, y + 2.4]`), гости
  `VILLAGE_VISITOR_SPOTS` (`visitor:<i>`, `[x, y + 1.6]`), `gate` (`VILLAGE_GATE`, `y − 1.2`), `hall`
  (`VILLAGE_HALL`, `y + 3.6`), `start` (`VILLAGE_START`). Если цель нарисована на предмете (дверь, вывеска),
  узел ставится на ближайшую свободную землю. Добавили жителя или место в `app.js` — пересоберите генератор.
- **Ближайшая точка графа** (нажатие по траве, дому или в пустоту): для каждого ребра `(A, B)`
  `t = clamp(((P − A)·(B − A)) / |B − A|², 0, 1)`, `Q = A + t (B − A)`; ответ — ребро и `t` с наименьшим `|P − Q|`.
  Эталон — `nearest_point` в `test_walk.py`. Дальше: временный узел `Q` на ребре `(A, B)` (соседи `A` и `B`),
  такой же узел для текущего положения игрока, A* по длинам рёбер (эвристика — прямое расстояние), движение по
  ломаной из узлов пути. Нажатие внутри `z` можно вести в саму точку `Q`; вне `z` — тоже в `Q`, то есть к дорожке.
- **Связность и препятствия** проверяют `test_walk.py` (по выгрузке препятствий `out/walk_check.json`) и
  `tests/js/farm_village_walk.test.cjs` (данные `app.js`: один связный граф, у каждой цели есть узел).

## Фигурка игрока

`player.js` рисует фермера в соломенной шляпе функциями фермы (как помощников на ферме), без обводок, и пишет
SVG с тремя кадрами `vp-stand`, `vp-stepA`, `vp-stepB` (лицом вправо, ноги в точке 0,0, `viewBox -17 -48 34 52`).
В игре это `VILLAGE_PLAYER_SVG` внутри `.village-player`; CSS показывает `vp-stand`, а у `.is-walking` чередует
шаги (при `prefers-reduced-motion` — стоит); `data-face=left` зеркалит фигурку.

## Праздничные слои деревни

`fest_<id>.js` рисует слой праздника функциями фермы в записывающий контекст: только вектор, без растра, без `<style>`
и `style=` (CSP игры). Привязка — к якорям этого же рендера: трубы (`s.smk`), окна (`s.win`), заборы, перила моста,
скамейки, фонари площади, двери жителей, ратуша. Каждый предмет проверяется: стоит на свободной земле и не заслонён
постройкой, стоящей впереди (слой лежит поверх фона, иначе предмет оказался бы на крыше). Результат —
`qw_farm/static/village-fest-<id>.svg` (`--install`), хеш — `hashes.json → fest_sha256`.

Слой из трёх групп: `vf-decor` (предметы, дымок `vf-smoke vf-s1..3`), `vf-day` (тёплые окна днём), `vf-night`
(свет окон и самовара ночью). Игра (`app.js VILLAGE_FEST`, `syncVillageFest`) загружает файл только при
`html[data-festival=<id>][data-festival-decor=on]` и вставляет его дважды: под ночной тонировкой (`village-fest-base`:
decor + day) и над ней (`village-fest-glow`: night). Показ — `style.css`, файл — в `api.py ASSETS`.
Слои: `posidelki` («Посиделки»), `new_year` («Новый год»), `maslenitsa` («Масленица»), `spring_flowers`
(«Весенние цветы»). Превью с датой праздника — копия тестового сервера с подменой даты календаря (см. отчёт в
`.local/village-generator-preview/REPORT.md`).

Кроме окон и труб, генератор записывает крыши (`gableRoof`/`hipRoof` → `s.roofs`), трубы целиком (`chimney` →
`s.chim`) и двери (`doorY`/`doorX` → `s.doors`). Снег «Нового года» — те же крыши, перерисованные снегом поверх
фона; дом, стоящий впереди, вырезается из снега клипом, трубы рисуются заново поверх снега. Крупный декор
(ёлка, сцена, горка, чучело, клумбы, столы) ставит `fest_kit.place`: свободная земля (не дорога и не вода), предмет
целиком в виду, не закрывает больше 20 % дома позади, не накрывает фонарь, другой предмет слоя, кнопки деревни
(`opts.buttons`) и плашку праздника (`opts.badge`, по `style.css .village-stage-badge`). Если места нет — строка
в `manifest.json → problems`. Ёлка оставлена со свободными петлями под именные игрушки (`fest_ny_toy`).

## Сорока-коробейница

`merchant.js` рисует функциями фермы:
- **тележку-короб** с навесом в цветах сороки, колёсами, коробочками, свёртками, пакетами семян, баночками красок
  (индиго, марена, шафран), вымпелом и фонарём — слой мира `qw_farm/static/village-merchant.svg` (группы `vm-base`
  под ночной тонировкой и `vm-night` — фонарь над ней);
- **Сороку** — фигурку фиксированного размера, как у игрока: кадры `vm-stand` и `vm-call` (крыло поднято с блестяшкой,
  клюв открыт), лицом вправо, ноги в точке 0,0, `viewBox -20 -50 40 54` → `app.js VILLAGE_MERCHANT.figure`.

Место — на площади у торговых рядов: генератор занимает его в плане (граф ходьбы обходит тележку) и ставит точку
подхода `merchant` в `VILLAGE_WALK.a`. Координаты — `manifest.json → merchant` (`cart` — рамка тележки, `foot` —
где стоит Сорока, единицы мира) и `app.js VILLAGE_MERCHANT`. Иконки её товаров — в `icons.svg`: `dye_indigo`,
`dye_madder`, `dye_saffron`, `merchant_scroll`, `merchant_seeds`, `merchant_graft`, `merchant_voucher`, аватар
`avatar_magpie`.

**Как включить слой.** Во время визита поставить атрибут на `<html>` и вызвать загрузку:

```js
document.documentElement.dataset.merchant = 'on';   // убрать: delete document.documentElement.dataset.merchant
syncVillageMerchant();                             // при первом визите подгружает village-merchant.svg
```

CSS (`style.css`, «Сорока-коробейница») показывает тележку, фонарь ночью и фигурку только при `[data-merchant]`;
фигурка покачивается и время от времени зазывает (при `prefers-reduced-motion` стоит). Кнопку лавки (нажатие по
Сороке или тележке) делает механика: центр фигурки — `foot` с подъёмом на ~30 px, рамка тележки — `cart`.

## Как править арт

- Новое здание: `building('<тип фермы>', x, y, w, h)` в разделе плана `village.js`; координаты в тайлах фермы.
  Жителю — `spot('<имя>', x, y)` у двери. Проверка `problems` не даёт поставить объект на дорогу или в воду.
- Предмет, которого нет на ферме, рисуй примитивами `B.*` (`box`, `gableRoof`, `cyl`, `Q`, `L`, `E`) и цветами
  фермы, по образцу уже имеющихся (`well`, `stall`, `bench`, `pier`, `bearDen`).
- После правки: `build_village.py` → `preview.py` → показать владельцу. После одобрения: `--install`, перенести изменившиеся
  координаты из `manifest.json` в `app.js` (огни, дым, `VILLAGE_WALK`, `VILLAGE_PLAYER_SVG`, кнопка ворот), обновить
  `reference.json`, прогнать `test_reproducible.py` и `test_walk.py`.
- Новый предмет на земле занимает место через `claim(x0, y0, x1, y1, тег, высота)`: граф обходит его, а высокий
  (высота ≥ 20 px фермы) ещё и не пускает маршруты по траве за себя.

## Стройка и торговые ряды

Фон хранит только ровную утоптанную землю площадок (`site(id, …)` в `village.js`) и шесть пустых мест лавок на площади
(`stallSlot`: земля и четыре пенька). Всё, что меняется, — символы спрайта `qw_farm/static/village-build.svg` из `build.js`,
каждый со своим `viewBox` в единицах мира; `app.js` ставит их по `VILLAGE_BUILD.boxes` (`villageBuildPiece`, `<svg><use>`).
Стадию берёт `construction.js siteArt` (сделанная работа: «Скоро» до котлована, котлован, каркас, готово), лавки —
`stallStates` (Сорока в дни визита, Соня закрыта 23–7, лавка игрока — с лотами), бригада стоит на площадке, пока
жители работают (`crewAt`). Ночные окна готовых зданий и фонари лавок — символы `-night` над ночной тонировкой.
В `manifest.json`: `sites` (подпись площадки, % мира), `build.boxes`, `build.crew` (ноги бригады), `stalls` (хозяин и место).
