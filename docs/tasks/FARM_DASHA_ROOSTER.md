# Лиса Даша и петух Олег в деревне

## Пользовательский цикл

В деревне есть два новых жителя. Разговор открывает отдельное дневное задание:
взять просьбу, собрать товар, сдать его жителю. Даша просит две морковки,
Олег — четыре пшеницы. Сервер выдаёт каждому 12 монет и 4 опыта, списывает
товар и сохраняет фазу. Взятое задание переживает полночь и рестарт; выполненное
снова становится доступным на следующий московский день. Повтор с новым
`command_id` не повторяет выдачу в том же цикле, а тот же `command_id`
возвращает сохранённый ответ.

Это отдельные задания в JSON состояния фермы, не слоты `orders[0..2]`.
Состав `NPCS` и выбор прежних заказов через `rng % len(NPCS)` не изменяются.
Гость чужой фермы не видит задания и состояние кражи владельца.

Если игрок заходит в деревню и не заговаривает с Дашей, она может стащить
до двух имеющихся монет. Сервер отсчитывает 45 секунд по своему времени и
принимает подтверждения присутствия каждые 10 секунд. Пропуск более 25 секунд,
скрытие вкладки, выход и новая сессия обрывают прежнее окно. Нажатие на Дашу
отключает кражу до конца текущего посещения. После попытки действует cooldown
86400 секунд. Баланс и `starter_credit` уменьшаются согласованно через `pay`;
списание и событие попадают в экономический журнал один раз. Пустой карман не
уходит в минус. Клиент не передаёт время, сумму или результат кражи.

Присутствие записывается в одном ограниченном объекте состояния фермы без
экономического receipt на каждое подтверждение. Только состоявшаяся кража
создаёт запись в журнале. Вкладка открывает lease только для своей фермы.

## Проверки перед приёмкой

- Python domain: обе фазы заданий, новый ключ повтора, полуночный переход,
  непрерывное присутствие, обрыв lease, разговор, cooldown, нулевой баланс,
  приватная проекция.
- PostgreSQL HTTP: обе команды и сохранение после нового чтения, прежние три
  заказа, receipt idempotency, реальное списание по серверному clock и
  независимость другого аккаунта.
- JS: видимость двух жителей, карточки задания, движение Даши и уведомление;
  UI rules/layout/gaps для доступных экранов.
- Песочница: реальный цикл Ильи/Ирины после локальных проверок. Production
  и рабочий токен требуют отдельного разрешения.
