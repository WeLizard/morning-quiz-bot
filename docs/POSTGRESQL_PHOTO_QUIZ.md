# PostgreSQL: фото-квиз и восстановление серии

Локальный этап [MQB-001](tasks/MQB-001-postgresql-and-mini-app-foundation.md),
проверен 2026-08-30. Рабочий сервер не переключался.

## Метаданные

В PG-режиме `PhotoQuizManager` читает ответы, отображаемые названия, hints и
флаг enabled из `photo_quiz_items` через `PhotoCatalog` перед подготовкой серии.
Изображения остаются файлами `data/images/*.webp` либо в общем `PHOTO_IMAGES_DIR`.
Загрузка из админки и изоляция preview описаны в [фото-каталоге](PHOTO_CATALOG.md).

Отключённые записи не выбираются. Новые managed-файлы `mqb-upload-*` без записи
БД также не выбираются: это может быть ещё не завершённая загрузка.
Если для выбранной группы старых legacy-файлов нет записи,
создаётся минимальная запись с названием группы. `ON CONFLICT DO NOTHING`
не перезаписывает существующее описание или отключение, внесённое администратором.
При ошибке БД нет возврата к `photo_quiz_metadata.json`; файловая запись в
PG-режиме запрещена. В JSON-режиме прежний способ хранения остаётся доступен.

Серия сохраняет снимок выбранных вопросов. Изменения описаний применяются
при подготовке новой серии, а не меняют правильный ответ уже идущей игры.

## Состояние и начисления

`PhotoSessions` использует существующую таблицу `quiz_sessions`: запись
`photo:<chat_id>` с kind `photo`, UUID серии и возрастающей revision внутри state.
Новая миграция схемы не понадобилась. Классическое восстановление и сохранение
не читают и не удаляют эти записи.

Сохраняются вопросы, индекс, исходное время вопроса UTC, лимит, попытки,
подсказки, известные message IDs, очки серии и последний результат. Таймер как
Python Task не сериализуется. Сохраняется состояние до/после отправки вопроса,
при ошибочной попытке, выдаче подсказки и завершении вопроса/серии.

Для верного ответа под блокировкой строки серии одной транзакцией сохраняются:

- `poll_answers` с ключом `photo:<session UUID>:<question index>`;
- профиль участника и глобальные баллы;
- очки/правильные ответы серии и переход к следующему вопросу.

Сбой записи состояния откатывает также баллы. Повтор запроса после потерянного
подтверждения commit возвращает записанный результат, не начисляя повторно.
Даже если повтор пришёл как таймаут, уже подтверждённая победа не заменяется
проигрышем. Старый UUID или revision не могут перезаписать новую серию.

Обработчики одного чата сериализованы, другие чаты не блокируются. Второй старт
не отправляет второе фото. Запоздалый ответ не засчитывается после дедлайна;
ожидавшее обработку событие предыдущего вопроса не переносится на следующий.
Если БД недоступна при закрытии вопроса, он остаётся незавершённым, с повторной
попыткой закрытия после дедлайна и паузой не менее пяти секунд между повторами.

## Поведение при перезапуске

| Сохранённая фаза | Действие |
| --- | --- |
| `ready`, `between` | Отправить ещё не начатый следующий вопрос либо завершить серию |
| `active` | Восстановить оставшееся время, не отправлять фото снова; пропущенный дедлайн закрыть таймаутом |
| `sending` | Прервать серию: неизвестно, принял ли Telegram фото; автоматически не повторять отправку |
| `finalizing` | Прервать незавершённую выдачу итогов без повторного начисления/автоматического повтора итогов |
| completed/stopped/interrupted | Не восстанавливать игру |

Фазы `sending` и `finalizing` — консервативная политика для неопределённого
результата сетевой отправки. Записанные баллы не отменяются. Между commit и
доставкой сообщения нет общей транзакции; exactly-once доставки не обещается.
Бот восстанавливает фото-серии после инициализации Application, до polling;
при штатном завершении отменяет их таймеры.

## Проверки и оставшиеся границы

`tests/test_postgres_photos.py` проверяет каталог, параллельный старт,
атомарное начисление/откат, повтор commit, устаревший UUID, восстановление
таймера, таймаут, неизвестный результат отправки, остановку, сохранение попыток,
подсказок и совместимость с хранилищем классических сессий. Сетевые вызовы
Telegram заменены заглушками; тестовая PostgreSQL настоящая и отдельная.

- Поддерживается один процесс бота, не распределённое выполнение таймеров.
- Закрытие серии и постановка известных message IDs на удаление теперь
  выполняются одной транзакцией. Snapshot-запись очереди отключена; worker
  учитывает сроки, настройки чата и повторы. Сообщение, чей ID не сохранён,
  всё ещё нельзя гарантированно очистить. [Механизм и границы](POSTGRESQL_RECOVERY.md).
- В админке доступны чтение, versioned правка ответа/подсказок и отключение
  фото-вопроса без удаления картинки. [Вход и PG-интерфейс](ADMIN_AUTH.md).
  Создание/удаление медиа и upload ещё не перенесены.
- Правило начисления сохранено: фото-баллы получает `user_id` инициатора серии,
  не обязательно автор сообщения в группе. Изменение этого правила требует
  отдельного решения; оно не сделано скрыто при миграции.
- Изображения не переносятся в БД. Их наличие и совпадение путей проверяются
  при отправке; для переноса Windows → Linux нужен обычный перенос кода и медиа,
  а не копирование локальных активных сессий поверх серверных.

Полный запуск тестов описан в [руководстве админки](POSTGRESQL_ADMIN.md).
